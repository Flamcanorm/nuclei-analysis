# 현재 문서 상태와 주의점 #전지성

## 앞 문서와 이 문서의 차이

[[01_프로젝트와 폴더 지도]]부터 [[09_용어 사전]]까지는 Nuclei 코드와 실행 흐름을 설명했다. 이 문서는 실행에 참여하는 파일을 새로 설명하는 문서가 아니라, **분석 노트 저장소 자체의 중복·빈 파일·보완 상태를 관리하는 문서**다.

여기서 나오는 `기준 문서`는 프로그램이 선택하는 파일이라는 뜻이 아니다. 사람이 분석할 때 내용이 실제로 들어 있어 참고해야 하는 노트를 뜻한다.

## 이 문서에서 사용하는 관리 용어

| 이름 | 뜻 |
|---|---|
| 기준 문서 | 현재 내용이 있고 설명서가 링크하는 분석 노트 |
| 중복 폴더 | 같은 이름의 문서 구조가 다른 위치에 다시 생긴 폴더 |
| 빈 문서 | 파일은 있지만 분석 내용이 없는 0바이트 Markdown 파일 |
| 작성자 태그 | `#전지성`, `#박영현`처럼 작성 출처를 구분하는 태그 |
| 보완 지점 | 코드 근거·연결 설명·용어 정의를 더 추가해야 할 부분 |

## 기준 문서 위치

Main 관련 분석은 다음 폴더를 기준으로 읽는다.

```text
01_Main_Flow
├─ main.md
├─ main_Functions.md
├─ main_Varialbes.md
└─ main_Functions
```

루트에 별도로 존재하는 `main_Functions` 폴더의 Markdown 파일들은 현재 모두 내용이 없다. 따라서 기준 자료로 사용하지 않는다.

## 작성자 태그

현재 문서에는 `#전지성`, `#박영현` 등 작성자 태그가 섞여 있다. 사용자가 작성하거나 사용자의 분석에 새로 추가한 설명은 `#전지성`으로 표시하는 원칙을 사용한다.

이 설명서 폴더의 문서는 모두 제목에 `#전지성`을 넣었다.

## 파일명 철자

`main_Varialbes.md`는 영어 `Variables`의 철자가 잘못된 이름이다. 현재 다른 문서가 이 이름을 참조할 수 있으므로 즉시 바꾸기보다 링크를 확인한 뒤 일괄 변경해야 한다.

## execution_architecture 1.md

파일 이름의 공백과 `1`은 내용상 역할을 설명하지 못한다. 나중에 링크를 정리할 때 `execution_architecture.md`처럼 바꾸는 것을 고려할 수 있다. 현재 설명서에서는 기존 이름을 그대로 가리킨다.

## test.md와 테스트 폴더

- 루트 `test.md`: 내용이 거의 없어 기준 분석 문서가 아님
- `테스트` 폴더: 현재 비어 있음

향후에는 다음 내용을 넣는 용도로 사용할 수 있다.

- 코드에서 예상한 옵션 동작
- 실제 실행 명령
- 실제 출력
- 예상과 실제가 다른 이유
- Nuclei와 templates 버전

## 분석 노트의 상세도 차이

`readConfig` 문서는 비교적 상세하지만 일부 내부·외부 패키지 문서는 짧다. 특히 다음 문서는 이후 보강할 가치가 있다.

- `runner_options.md`: `ConfigureOptions`, `ParseOptions`, `ValidateOptions`, Logger 설정 연결
- `pdcp_writer.md`: ResultEvent가 Cloud 요청으로 바뀌는 흐름
- `types_scanstrategy.md`: 두 전략의 실제 반복 구조와 메모리 차이
- `uncover_uncover.md`: 지원 엔진과 대상 공급 연결
- `interactsh_client.md`: URL 등록, polling, correlation 흐름
- `gologger.md`: Logger 레벨과 Writer 결과의 차이

## 코드 줄 번호에 대한 주의

Nuclei가 업데이트되면 줄 번호는 쉽게 바뀐다. 보고서에는 줄 번호와 함께 반드시 다음 정보를 적는 것이 좋다.

- 파일 경로
- 함수 이름
- 옵션 또는 필드 이름
- 호출되는 다음 함수

예:

```text
cmd/nuclei/main.go의 main()
→ options.ListDslSignatures 확인
→ pkg/operators/common/dsl.GetPrintableDslFunctionSignatures 호출
→ 출력 후 return
```

## 출력 결과를 붙일 때의 주의

비슷해 보이는 명령의 결과를 섞으면 코드 분석 전체가 잘못될 수 있다.

- `-tl`: 템플릿 목록
- `-u ...`: 실제 대상 스캔
- `-o`: 스캔 결과를 텍스트 파일에 저장
- `-json-export`: 스캔 결과를 JSON으로 저장
- `-ldf`: DSL 함수 목록만 출력하고 종료

명령을 실행한 직후 명령과 결과를 같은 파일에 기록하면 혼동을 줄일 수 있다.

## 이 설명서의 한계

이 폴더는 현재 `nuclei-analysis`에 존재하는 문서를 연결한 안내서다. Nuclei 원본 저장소의 모든 하위 패키지와 모든 프로토콜을 전부 분석한 것은 아니다. 새로운 분석 폴더가 생기면 [[01_프로젝트와 폴더 지도]]와 이 상태 문서를 함께 갱신해야 한다.
