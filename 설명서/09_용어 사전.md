같은 용어가 문맥에 따라 달라질 수 있다. 예를 들어 `Options`라는 구조체는 여러 패키지에 존재하므로, 이 설명서에서 단독으로 `Options`라고 하면 기본적으로 `pkg/types/types.go`의 Nuclei 전체 실행 설정을 뜻한다. 다른 Options는 반드시 `loader.Config`, `reporting.Options`처럼 소속을 붙여 구분한다.

## CLI

터미널 명령으로 프로그램을 조작하는 방식이다.

## Flag 또는 Option

프로그램 동작을 바꾸기 위해 명령에 붙이는 값이다. 예: `-debug`, `-u`, `-o`.

## Parse

문자열로 들어온 입력을 프로그램이 사용할 수 있는 구조와 타입으로 해석하는 작업이다.

## Options

파싱된 실행 설정을 모아 둔 구조체다. 기능을 수행하는 객체라기보다 설정 보관함이다.

## Logger

프로그램 상태와 오류를 출력하는 구성요소다. INF, WRN, ERR, DBG 등을 담당한다.

## INF

Information. 정상 실행 상태나 안내 정보다.

## WRN

Warning. 실행은 계속할 수 있지만 확인해야 할 문제다.

## ERR

Error. 일부 작업이 실패했거나 입력·환경에 문제가 있다는 뜻이다.

## DBG

Debug. 개발자나 분석자가 내부 동작을 추적할 때 보는 상세정보다.

## Runner

스캔에 필요한 구성요소를 준비하고 실행 순서를 연결하는 상위 관리자다.

## Catalog

템플릿 파일의 위치를 찾고 열 수 있게 하는 파일 접근 계층이다.

## Loader

후보 템플릿에 필터를 적용하고 이번 실행에서 사용할 목록을 만든다.

## Parser

YAML·JSON 템플릿 원문을 Template 객체로 해석한다.

## Engine

대상과 템플릿을 조합하고 실행 작업을 관리한다.

## Protocol Executor

HTTP, DNS, SSL 등 특정 프로토콜 요청을 실제로 실행하는 구성요소다.

## InputProvider

URL, 목록 파일, 표준 입력 등에서 스캔 대상을 공급한다.

## Output Writer

탐지 결과를 터미널, 파일, JSON, Cloud 등으로 보낸다.

## ResultEvent

한 건의 탐지 결과를 구조화한 데이터다. Template ID, 대상, 프로토콜, 심각도, 추출값 등이 들어갈 수 있다.

## Template

무엇을 요청하고 어떤 조건을 탐지할지 정의한 YAML·JSON 검사 규칙이다.

## Workflow

여러 템플릿을 조건과 순서에 따라 연결해 실행하는 상위 실행 규칙이다. 단일 템플릿 하나의 검사와 구분된다.

## Matcher

응답이 탐지 조건에 맞는지 참·거짓으로 판단한다.

## Extractor

응답에서 필요한 문자열이나 값을 뽑는다.

## DSL

템플릿 조건과 변환을 표현하기 위한 Nuclei 전용 표현 언어다.

## 함수 서명

함수 이름, 받을 인자, 인자 타입, 반환 타입을 요약한 호출 설명이다.

## Cache

이미 읽거나 계산한 결과를 다시 사용할 수 있게 임시 보관하는 공간이다. 같은 템플릿을 반복 파싱하는 시간과 작업량을 줄인다.

## raw

가공하기 전 원문이다. 템플릿 Parser 문맥에서는 YAML·JSON 파일 전체 문자열을, 결과 문맥에서는 원본 요청·응답을 뜻할 수 있다. 문맥에 따라 대상이 다르므로 주의해야 한다.

```text
Parser Cache의 raw
└─ 템플릿 YAML·JSON 원문

JSON 출력의 raw
└─ 네트워크 요청·응답 원문
```

따라서 `StoreWithoutRaw`와 `-omit-raw`는 이름은 비슷하지만 서로 다른 파일과 데이터를 다룬다.

## Compile

해석된 템플릿과 DSL 표현식이 실제 실행 가능한지 검사하고 요청 실행기를 준비하는 단계다. 단순히 파일을 읽는 Parse보다 뒤 단계다.

## RateLimiter

일정 시간 동안 전송 가능한 요청 수를 제한한다.

## Concurrency

한 시점에 여러 작업을 함께 수행하는 정도다.

## WorkPool

동시에 실행할 작업과 작업용 자원을 관리하는 묶음이다.

## ScanStrategy

템플릿 중심 또는 호스트 중심처럼 대상과 템플릿을 반복하는 순서다.

## Clustering

동일하거나 비슷한 네트워크 요청을 하나로 묶어 중복 전송을 줄이는 최적화다.

## Interactsh / OAST

대상이 외부 서버로 DNS·HTTP 접속을 했는지 관찰해, 즉시 응답에 나타나지 않는 취약 동작을 찾는 방식이다.

## Headless

화면 없는 브라우저를 자동 조작해 JavaScript 기반 페이지를 검사하는 실행 방식이다. `-show-browser`를 사용하면 브라우저 화면을 보이게 할 수 있다.

## Fuzzing

요청의 일부 값을 여러 형태로 변형해 예상하지 못한 반응이나 취약점을 찾는 검사 방식이다.

## Resume

중단된 스캔의 진행 상태를 저장했다가 나중에 이어서 실행하는 기능이다.

## Config

반복해서 쓰는 실행 옵션을 파일에 저장한 설정이다.

## Template Profile

템플릿 선택, 필터, 실행 설정, 인증 정보 등을 하나의 재사용 가능한 프로필로 묶은 것이다.

## Callback

특정 사건이 일어났을 때 나중에 호출하도록 전달한 함수다. 옵션을 만났을 때 버전을 출력하거나 실행 결과를 Writer로 보낼 때 사용할 수 있다.

## Context

실행 취소 신호, 제한 시간, 요청 범위 같은 상태를 여러 함수에 전달하는 공통 실행 정보다.

## Serialization

구조체나 객체를 JSON 같은 저장·전송 가능한 문자열 형식으로 바꾸는 작업이다.

## Standard Input

파일 옵션 없이 다른 명령의 출력이나 키보드 입력을 프로그램이 받는 기본 입력 통로다.

## Environment Variable

운영체제나 셸에 저장해 프로그램이 읽을 수 있는 설정값이다. API Key, Config 경로 등에 사용될 수 있다.
