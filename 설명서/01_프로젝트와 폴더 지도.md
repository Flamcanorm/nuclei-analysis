# 프로젝트와 폴더 지도 #전지성

## 이 문서의 위치와 새로 나오는 이름

이 문서는 설명서의 첫 번째 문서이므로 선행 문서가 없다. 여기서는 실제 Nuclei 코드와 분석 노트를 먼저 구분한다.

| 이름 | 뜻 | 이후 연결 |
|---|---|---|
| Nuclei 원본 소스 | 실제로 컴파일되어 실행되는 Go 파일 모음 | 다음 문서부터 파일·함수를 직접 추적함 |
| `nuclei-analysis` | 원본 코드를 사람이 해석한 학습용 저장소 | 모든 설명서와 분석 노트가 들어 있음 |
| Obsidian | Markdown 노트를 폴더와 링크로 관리하는 프로그램 | `.obsidian`, `.base`, 문서 간 내부 링크를 사용함 |
| Markdown | 제목, 표, 코드 블록을 표현하는 문서 문법 | `.md` 파일의 내용 형식 |
| 패키지 | 관련된 Go 파일과 기능을 묶은 코드 단위 | Runner, Catalog, Engine 등의 소속을 구분함 |

이 문서에서 폴더를 설명한 뒤 [[02_Main과 프로그램 시작 흐름]]에서는 실제 시작 파일 `cmd/nuclei/main.go`로 들어간다.

## nuclei-analysis는 무엇인가?

`nuclei-analysis`는 Nuclei 원본 프로그램 자체가 아니라, Nuclei 코드를 분석한 내용을 정리하는 Obsidian 저장소다. 따라서 이 폴더 안의 Markdown 문서는 실행 코드가 아니라 **코드를 이해하기 위한 학습 기록**이다.

```text
nuclei 원본 소스
└─ 실제로 컴파일되고 실행되는 Go 코드

nuclei-analysis
└─ 원본 소스를 사람이 읽고 설명한 분석 노트
```

## 전체 폴더 구조

```text
nuclei-analysis
├─ 00_Dashboard
├─ 01_Main_Flow
│  ├─ main.md
│  ├─ main_Functions.md
│  ├─ main_Varialbes.md
│  └─ main_Functions
│     └─ readConfig
├─ 02_Internal_Packages
├─ 03_External_Packages
│  └─ 04_etc
├─ 설명서
├─ main_Functions
├─ 테스트
├─ .obsidian
└─ .git
```

## 00_Dashboard

`README.base`는 일반 Markdown 문서가 아니라 Obsidian의 **Base 보기 설정 파일**이다. 노트의 `유형`, `상세`, `상태`, 수정 시각 등을 표나 목록으로 모아 보여준다.

이 폴더의 목적은 코드 분석이 아니라 **작성한 문서를 한눈에 관리하는 화면**을 만드는 것이다.

## 01_Main_Flow

프로그램이 시작되는 `cmd/nuclei/main.go`를 중심으로 정리한 폴더다.

위의 `00_Dashboard`가 “분석 문서를 보여주는 화면”이었다면, `01_Main_Flow`는 처음으로 **실제 실행 코드의 순서**를 다룬다. 이 폴더에서 정리한 `options`와 `main()`은 다음 `02_Internal_Packages`의 Runner와 Engine으로 연결된다.

### main.md

`main()`이 위에서 아래로 어떤 순서로 실행되는지 정리한다. Logger 준비, CLI 모드 설정, 옵션 읽기, 조기 종료 명령 처리, Runner 생성, 스캔 실행, 종료 정리 등이 들어간다.

### main_Functions.md

`main.go`에 선언된 보조 함수들의 목차다. 실제 설명은 하위 `main_Functions` 폴더에 나누어 저장되어 있다.

### main_Varialbes.md

`options`, `inlineSecretsTempFiles`, `profileSecrets`처럼 `main.go`의 실행 중 값을 담는 변수와 구조체를 설명한다. 파일 이름의 `Varialbes`는 `Variables`의 철자 오류지만, 현재 링크 호환성을 위해 그대로 유지되어 있다.

### main_Functions 폴더

다음과 같은 보조 함수를 함수별 문서로 나눈다.

- `printVersion`: Nuclei 버전 출력
- `printTemplateVersion`: 템플릿 버전 출력
- `readFlagsConfig`: 설정 파일을 찾아 CLI 설정과 병합
- `cleanupOldResumeFiles`: 오래된 이어하기 파일 정리
- `findProfilePathById`: 프로필 ID로 파일 경로 찾기
- `processInlineSecretsFromProfile`: 프로필 안의 비밀값을 임시 파일로 처리
- `resetCallback`: 설정과 템플릿 초기화 처리
- `disableUpdatesCallback`: 자동 업데이트 확인 비활성화

`readConfig()`가 등록하는 CLI 옵션을 18개 그룹과 후처리 문서로 나눈 곳이다.

## 02_Internal_Packages

Nuclei 프로젝트 내부에서 직접 만든 핵심 구성요소를 정리한 폴더다.

앞의 `01_Main_Flow`에서 `main()`이 `runner.New(options)`을 호출했는데, 이 호출의 실제 구현과 그 안에서 만들어지는 Catalog·Parser·Writer가 이 폴더의 주제다.

- `runner_runner`: 전체 실행 준비와 지휘
- `runner_options`: 옵션 처리와 검증
- `pkg_types`: 프로그램 전체 설정인 `Options`
- `catalog_disk`: 템플릿 경로와 파일 접근
- `catalog_loader`: 템플릿 선택·파싱·로딩
- `core_engine`: 대상과 템플릿의 실제 실행 조합
- `types_scanstrategy`: 스캔 순서 전략
- `pdcp_writer`: Cloud 결과 전송용 Writer
- `uncover_uncover`: 외부 검색 서비스 지원 정보
- `execution_architecture 1`: 위 구성요소들의 관계도

여기서 `internal`은 Go의 문법 설명이 아니라 프로젝트 관점에서 **Nuclei 내부 구현**이라는 뜻으로 이해하면 된다. `pkg` 아래 코드도 이 분석 저장소에서는 내부 패키지로 묶어 설명한다.

## 03_External_Packages

Nuclei가 직접 모든 기능을 새로 만들지 않고 가져다 쓰는 외부 라이브러리를 정리한다.

앞의 내부 패키지들이 자체 실행 구조를 만들 때, CLI 파싱은 `goflags`, 로그는 `gologger`, OAST 통신은 `interactsh`에 맡긴다. 즉 외부 패키지는 별도 주제가 아니라 내부 구조체의 필드와 생성 함수 안으로 들어가 사용된다.

## 폴더 사이의 연결 흐름

```text
00_Dashboard
문서를 보여주고 관리
  ↓
01_Main_Flow
프로그램 시작과 Options 전달
  ↓
02_Internal_Packages
Runner가 내부 구성요소를 생성하고 Engine이 실행
  ↓
03_External_Packages
내부 구성요소가 빌려 쓰는 CLI·로그·OAST 기능 설명
  ↓
설명서
위 내용을 초보자 관점에서 다시 연결
```

- `goflags`: CLI 옵션 등록·도움말·파싱
- `gologger`: INF, WRN, ERR, DBG 등 로그 출력
- `interactsh`: 대상이 외부 서버로 접속했는지를 이용한 탐지
- `04_etc/sample`: 목록 옵션의 기본값 등 부가 예시

외부 패키지를 쓴다고 해서 해당 코드가 중요하지 않은 것은 아니다. Nuclei의 `main.go`는 외부 라이브러리가 제공한 기능을 조립해 CLI를 구성한다.

## 설명서

기존 분석 노트 사이의 관계, 기초 용어, 읽는 순서를 제공한다. 세부 코드 증거는 기존 분석 노트에서 보고, 전체 개념이 막힐 때는 설명서를 먼저 본다.

## .obsidian

Obsidian 화면 설정, 플러그인 설정, 그래프·작업공간 상태가 저장된다. Nuclei 코드 분석 내용은 아니므로 보통 학습 대상에서 제외한다.

## .git

문서의 변경 이력과 브랜치 정보를 관리한다. Nuclei 실행 로직과는 관계없다. 여러 사람이 작성한 내용을 합칠 때 어떤 파일이 언제 바뀌었는지 추적하는 용도다.

## 테스트

현재 비어 있는 폴더다. 앞으로 분석 내용의 검증 명령, 예상 출력, 실제 출력 비교 등을 넣을 수 있다. 비어 있으므로 현재 기준 문서는 아니다.

## 루트의 main_Functions

루트에 별도로 있는 `main_Functions`에는 내용이 없는 Markdown 파일들이 있다. 실제 내용이 들어 있는 기준 폴더는 다음이다.

```text
01_Main_Flow/main_Functions
```

따라서 루트의 빈 `main_Functions`를 읽으면 분석 내용이 누락된 것처럼 보일 수 있다. 삭제 여부는 작성자들과 확인한 뒤 결정해야 하며, 이 설명서에서는 `01_Main_Flow/main_Functions`만 기준으로 삼는다.
