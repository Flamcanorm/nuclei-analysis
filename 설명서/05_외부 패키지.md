# 외부 패키지 설명서 #전지성

## 외부 패키지를 쓰는 이유

Nuclei가 명령줄 파싱, 로그 형식, 외부 상호작용 서버 통신을 전부 처음부터 만들면 핵심 스캐너 개발과 유지보수가 어려워진다. 이미 검증된 라이브러리를 가져와 사용하면 Nuclei는 템플릿 실행과 보안 검사에 집중할 수 있다.

```text
Nuclei 코드
├─ 자체 구현: Runner, Loader, Engine, Writer
└─ 외부 기능 이용: goflags, gologger, interactsh, dsl 등
```

## 내부 코드와 외부 패키지가 연결되는 방식

Go의 `import`는 외부 패키지의 공개 함수와 타입을 현재 파일에서 사용할 수 있게 한다. 하지만 import만으로 기능이 자동 실행되지는 않는다. Nuclei 코드가 실제 함수를 호출하거나 타입을 필드로 선언해야 연결된다.

| 외부 패키지 | Nuclei의 연결 파일 | 실제 연결 예 |
|---|---|---|
| `goflags` | `cmd/nuclei/main.go` | `NewFlagSet`, `BoolVarP`, `Parse` |
| `gologger` | `main.go`, `types.Options`, Runner | `DefaultLogger`를 Options와 Runner에 공유 |
| `interactsh` | `internal/runner/runner.go` | `DefaultOptions` 구성 후 `interactsh.New` |
| `projectdiscovery/dsl` | `pkg/operators/common/dsl/dsl.go` | HelperFunctions 가져오기와 Nuclei 함수 추가 |

외부 패키지 사용을 분석할 때는 `import가 있는가?`에서 멈추지 않고, `어떤 함수가 호출되고 반환값이 어느 구조체 필드에 저장되는가?`까지 봐야 한다.

## goflags

관련 문서: `03_External_Packages/goflags.md`

ProjectDiscovery가 만든 CLI 옵션 라이브러리다.

### Nuclei가 사용하는 기능

- `NewFlagSet`: 옵션 관리자 생성
- `CreateGroup`: 도움말에서 옵션을 영역별로 묶기
- `BoolVar`, `StringVar`, `IntVar`: 옵션 종류 등록
- `StringSliceVar`: 여러 문자열을 받는 옵션 등록
- `CallbackVar`: 값을 저장하는 대신 함수를 실행하는 옵션 등록
- `Parse`: 실제 명령줄 입력 해석

### File...StringSliceOptions

문자열 목록 옵션은 `a,b,c`처럼 쉼표로 받을 수도 있고, 여러 줄이 든 파일 경로를 받을 수도 있다. 세 설정은 목록을 나누고 정리하는 방식이 다르다.

- `FileNormalizedStringSliceOptions`: 목록을 비교하기 좋은 표준 형태로 정리
- `FileStringSliceOptions`: 원래 문자열 형태를 더 많이 유지
- `FileCommaSeparatedStringSliceOptions`: 쉼표 목록과 파일의 여러 줄을 지원

각 설정의 `IsFromFile`은 “현재 문자열을 값 하나로 둘지, 파일을 열어 여러 줄 목록으로 펼칠지” 판단하는 함수다.

이것은 특정 사이트만 쓸 수 있게 제한하는 기능이 아니다. 예를 들어 `-u https://example.com`의 URL을 파일로 열지 않는다. 반면 어떤 목록 옵션에 `targets.txt`가 전달되고 일반 목록 파일로 판별되면 각 줄을 개별 값으로 읽을 수 있다. YAML·JSON Nuclei 템플릿은 목록 파일로 잘못 펼치지 않도록 `config.IsTemplate()` 결과를 이용한다.

## gologger

관련 문서: `03_External_Packages/gologger.md`

프로그램 상태 메시지를 일관된 형식으로 출력한다.

| 표시 | 영어 | 의미 |
|---|---|---|
| `INF` | Information | 정상적인 실행 상태와 안내 |
| `WRN` | Warning | 실행은 가능하지만 주의할 문제 |
| `ERR` | Error | 일부 작업이 실패했거나 잘못됨 |
| `DBG` | Debug | 문제 분석을 위한 상세 내부 정보 |
| `FTL` | Fatal | 계속 실행할 수 없어 프로그램 종료 |

### Debug, Verbose, Silent

- `Debug`: 요청·응답 또는 내부 디버그 메시지까지 자세히 표시
- `Verbose`: 기본 정보보다 더 많은 로딩·실행 정보를 표시
- `Silent`: 배너와 일반 상태 로그를 줄이고 탐지 결과 중심으로 표시

이 옵션은 Logger의 출력 범위를 바꾼다. 서로 동시에 켰을 때는 Nuclei의 옵션 후처리 규칙이 우선순위를 정한다.

## interactsh

관련 문서: `03_External_Packages/interactsh_client.md`

일부 취약점은 대상의 HTTP 응답에 바로 흔적이 나오지 않는다. 대신 대상 서버가 공격자가 준비한 외부 도메인으로 DNS 조회나 HTTP 요청을 보내게 된다.

```text
Nuclei가 특수 주소를 대상에 전달
  ↓
대상이 Interactsh 서버로 DNS/HTTP 접속
  ↓
Interactsh가 접속 기록을 Nuclei에 알림
  ↓
Nuclei가 취약 동작으로 판단
```

이 방식을 OAST(Out-of-Band Application Security Testing)라고 부른다. 출력의 `Using Interactsh Server: oast...`는 이런 상호작용 서버를 사용한다는 상태 메시지다.

## DSL 라이브러리

Nuclei는 `github.com/projectdiscovery/dsl` 라이브러리의 문자열, 인코딩, 해시, 정규식, 시간, 변환 함수를 템플릿 조건에서 사용한다. Nuclei 자체도 `resolve`, `getNetworkPort` 같은 함수를 추가한다.

Nuclei의 `pkg/operators/common/dsl`은 외부 DSL 함수를 그대로 가져오는 동시에 Nuclei 전용 함수를 등록하는 연결 계층이다.

## 표준 라이브러리와 외부 라이브러리

- 표준 라이브러리: Go 설치에 기본 포함된 `fmt`, `os`, `time` 등
- 외부 라이브러리: 별도로 받아 사용하는 `goflags`, `gologger`, `projectdiscovery/dsl` 등

분석 보고서에서는 필요할 때 두 종류만 구분하면 된다. Nuclei 프로젝트 내부 패키지는 외부 라이브러리가 아니라 **내부 코드**로 별도 설명하는 편이 정확하다.
