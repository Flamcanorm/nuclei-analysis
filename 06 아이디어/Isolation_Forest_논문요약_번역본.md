## 초록

역사적으로 이상 탐지는 제조 과정의 고장이나 결함을 탐지하는 것과 같은 산업 응용 분야에서 중요한 문제였다. 현재에도 침입 탐지, 사기 탐지, 생태계 변화 탐지 또는 센서 네트워크에서의 이벤트 탐지와 같은 다양한 분야에서 지속적으로 증가하는 요구를 충족시키기 위한 중요한 주제이다. 따라서 이상 탐지는 여러 연구 분야에서 여전히 큰 관심을 받고 있는 연구 주제이다.

본 논문에서는 잘 알려져 있고 효율적인 이상 탐지 알고리즘인 **Isolation Forest(IForest)**에 초점을 맞추었다. 우리는 IForest에 대한 심층적이고 종합적인 관점을 제공하였다. 또한 입력 파라미터인 **트리의 수, 샘플 크기, 결정 임계값**이 탐지 효율성과 실행 시간에 미치는 영향을 평가하였다.

우리는 학습 단계에 일부 이상 데이터를 포함하는 것의 이점에 대해서도 논의하였다. IForest의 한계를 다루기 위해 일반적으로 사용되는 실제 데이터셋뿐만 아니라 단순하지 않은 분포를 가진 합성 데이터셋을 이용하여 다양한 실험을 수행하였다.

여러 차원이 동시에 이상을 나타내는 다차원 데이터셋을 설계하였다. 또한 이상 데이터와 정상 데이터 사이의 유사도를 다양하게 만들기 위해 두 데이터 클래스 사이의 밀도와 거리를 변화시켰다.

우리는 IForest의 성능을 개선 버전인 **Extended IForest(EIF)**와 비교하였다.

마지막으로 전체 Forest의 하나의 전역적인 판단을 사용하는 대신, 각각의 개별 Tree가 내리는 판단을 기반으로 하는 새로운 IForest 확장 방법을 설계하고 검증하였다. 이를 **Majority Voting IForest(MVIForest)**라고 명명하였다.

실험 결과, MVIForest는 IForest와 거의 동일한 정확도를 가지면서 IForest보다 더 짧은 실행 시간을 보였다.

## I. 서론

이상은 일반적으로 정상 데이터와 비교했을 때 다른 행동을 보이는 요소로 정의된다. 이상 탐지는 통계학, 데이터 마이닝, 머신러닝, 그리고 최근에는 딥러닝을 포함한 여러 연구 분야에서 널리 연구되고 있는 흥미로운 문제이다.

실제로 이상 탐지는 침입 탐지, 천문학, 금융 또는 사이버보안과 같은 다양한 실제 응용 분야를 가진다. 빠르고 효율적인 이상 탐지는 막대한 경제적 손실과 자연재해를 방지하고 심지어 사람의 생명을 구할 수도 있다.

문헌에서는 서로 다른 접근법을 기반으로 하는 많은 이상 탐지 기법들이 제안되어 왔다. 기존 이상 탐지 기법에 대한 가장 잘 알려진 조사 연구는 [1], [4], [5], [19]이다.

이 연구들은 다음과 같은 주요 접근법을 확인하였다.

- 통계적 접근법
- 클러스터링
- 최근접 이웃

후자의 두 범주는 일반적으로 밀도 기반 또는 거리 기반으로 나뉜다.

밀도 기반 방법에는 **Local Outlier Factory(LOF)** [3]와 **Density-Based Spatial Clustering of Applications with Noise(DBSCAN)** [20] 등이 있으며, 거리 기반 방법에는 **K-means** [14]와 **k-Nearest Neighbors(k-NN)** [35] 등이 있다.

최근에는 복잡하거나 고차원 데이터에서 이상을 탐지하기 위해 딥러닝 접근법도 적용되고 있다([6], [11], [26], [28], [30]).

각 접근법은 각각 장점과 단점을 가지고 있다. 이러한 접근법을 비교하고 주어진 상황에 가장 적합한 방법을 선택하기 위해 여러 기준을 고려할 수 있다.

예를 들어 다음 사항에 초점을 맞출 수 있다.

- 방법의 확장성: 대규모 또는 다변량 데이터를 처리할 수 있는 능력
- 사람의 개입: 지도, 비지도 또는 준지도 방법
- 응답 시간: 탐지 속도
- 자원 소비량
- 응용 분야의 민감도에 따른 탐지 효율성: False Positive 또는 False Negative 허용 정도

Isolation Forest(IForest)는 앞에서 제시한 통계, 클러스터링, 최근접 이웃 등의 접근 방법과는 다른 개념을 기반으로 하는 이상 탐지 방법이다.

IForest는 거리나 밀도를 계산하지 않기 때문에 실행 시간과 메모리 요구량을 크게 줄인다.

IForest는 Liu 등 [22], [24]에 의해 2008년에 설계되었다. 이 방법은 이진 트리를 기반으로 데이터를 연속적으로 분할하고, 대부분의 데이터보다 트리에서 빠르게 격리되는 데이터를 이상 데이터로 식별한다.

Isolation Forest는 비지도 학습 방법으로, 선형적인 시간 복잡도와 낮고 일정한 메모리 요구량을 가지면서 정확도 측면에서도 우수한 결과를 제공한다.

[17]에서는 보다 정확한 탐지를 위해 데이터 분할 방식을 개선한 **Extended Isolation Forest(EIF)**라는 새로운 버전의 IForest를 제안하였다.

향후 스트리밍 환경에 적합한 IForest의 분산 버전을 설계하고 개발하기 위해, 본 논문에서는 먼저 IForest에 대한 완전하고 심층적인 연구를 수행한다. 이는 스트림 환경에 적합한 분산 버전으로 IForest를 적용하기 위해 필요한 단계이다.

본 논문의 목적은 Isolation Forest를 심층적으로 연구하고, 서로 다른 파라미터들이 성능과 탐지 효율성에 미치는 영향을 평가하는 것이다.

특히 Isolation Forest의 한계를 탐구하기 위해 다차원 데이터셋에서 단순하지 않은 이상 데이터에 초점을 맞춘다.

우리는 Isolation Forest와 그 확장 버전인 EIF를 비교하였다. EIF는 False Positive를 개선하지만 실행 시간이 더 길다.

또한 **Majority Voting Isolation Forest(MVIForest)**라고 명명한 새로운 버전을 제안하였다. MVIForest는 Isolation Forest와 동일한 수준의 정확도를 제공하면서 실행 시간이 더 짧다.

이 세 알고리즘을 비교하기 위해 이상 탐지 분야에서 일반적으로 사용되는 실제 데이터셋과 서로 다른 특성을 가진 합성 데이터셋을 이용하여 여러 실험을 수행하였다.

## II. Isolation Forest: 원리와 장점

이상은 정상 패턴에 대해 잘 정의된 모델을 따르지 않는 데이터의 패턴으로 간주된다.

**Isolation(격리)**은 이러한 비정상적인 패턴을 전체 데이터셋으로부터 분리하는 과정이다.

데이터셋은 일반적으로 불균형하며, 이상 데이터보다 정상 데이터가 훨씬 많이 존재하고 이상 데이터는 예외에 해당한다.

Isolation 기법은 이상 데이터의 다음 두 가지 특성을 기반으로 한다.

- 이상 데이터는 전체 데이터셋에서 매우 작은 비율을 차지한다.
- 이상 데이터는 서로 구별된다. 이상 데이터는 정상 데이터와 비교하여 서로 다른 행동이나 특성을 가진다. 또한 이상 데이터들이 서로 구별될 경우 쉽게 식별할 수 있으며, 이는 Masking Effect를 방지한다.

이 두 가지 특성의 직접적인 결과로 **이상 데이터는 정상 데이터보다 더 쉽게 격리된다.**

기존의 대부분의 이상 탐지 접근법은 기존 데이터로부터 모델을 구축한다.

비지도 학습 방법은 레이블이 없는 데이터에서 얻은 정보를 기반으로 모델을 만들며, 준지도 및 지도 학습 방법에서는 관리자가 제공한 레이블, 즉 사전에 식별된 클래스를 사용한다.

정상 데이터, 즉 다수를 차지하는 데이터의 행동을 모델링하면 표준적인 행동을 따르지 않는 요소를 비정상 데이터로 식별할 수 있다.

일부 접근법은 데이터셋의 각 요소 사이의 거리 또는 밀도를 계산하고, 일정한 임계값을 초과하는 거리를 가진 요소를 이상 데이터로 식별한다.

이러한 방법들은 좋은 탐지 결과를 제공하지만, 데이터셋의 차원이나 크기에 따라 확장성이 부족하다는 문제가 자주 발생한다.

대규모 데이터셋의 경우 이러한 방법의 실행 시간과 메모리 요구량은 빠르게 한계에 도달할 수 있다.

일반적으로 LOF [3], k-NN [35]과 같은 최근접 이웃 기반 이상 탐지 방법은 데이터의 각 쌍 사이의 거리를 계산하기 때문에 **O(n²)**의 이차 복잡도를 가진다 [15].

이러한 방법의 응답 시간 역시 오늘날 여러 시스템과 센서에서 지속적으로 증가하는 속도로 생성되는 데이터 스트림을 실시간으로 처리하는 데 적합하지 않다.

모델을 설계하고 이상을 탐지하기 위해 필요한 모든 거리를 계산하는 것은 이러한 환경에서 수행하기 어려울 수 있다.

Isolation Forest는 통계, 클러스터링, 최근접 이웃 등과는 다른 접근법을 기반으로 하는 이상 탐지 방법이다.

거리나 밀도를 계산하지 않기 때문에 실행 시간과 메모리 요구량을 크게 줄인다.

IForest는 낮은 메모리 요구량 [22]과 데이터셋 크기에 비례하는 선형 실행 시간을 가진다(Section VI-C).

따라서 우수한 확장성을 가지고 있어 대규모 데이터셋과 실시간 처리 모두에 적합하다.

이상 데이터는 드물며 정상 데이터와 비교하여 서로 다른 행동을 보인다.

**그림 1**은 이상 데이터 \(X_0\)와 정상 데이터 \(X_i\)의 예를 보여준다.

Isolation은 데이터셋을 연속적으로 분할함으로써 수행된다.

이상 데이터는 정상 데이터보다 더 쉽게 격리된다.

\(X_0\)는 3단계 만에 격리되는 반면, 정상 데이터 \(X_i\)를 격리하는 데에는 11단계가 필요하다.

**그림 1. 이상 데이터 \(X_0\)는 정상 데이터 \(X_i\)보다 더 빠르게 격리된다.**

IForest([22], [24])는 Isolation 기반 이상 탐지 범주에서 최초로 제안된 방법이다.

이 방법은 **Random Forest**라고 하는 무작위적이고 서로 독립적인 Tree(itree)들의 집합을 사용한다.

IForest는 Forest에 포함된 모든 Tree를 사용하여 각 데이터에 대한 점수를 생성한다.

IForest는 데이터의 점수를 계산하기 위해 두 개의 입력 파라미터를 사용한다.

- \(\psi\): 전체 데이터셋에서 무작위로 선택한 Sample의 크기
- \(t\): Forest에 포함되는 Tree의 개수

각 Tree는 데이터셋을 Sampling하여 독립적으로 구축되므로 Tree의 개수는 Sample의 개수에 대응한다.

IForest는 두 단계로 구성된다.

첫 번째 단계는 본질적으로 Forest를 구축하는 **Training Phase**이고, 두 번째 단계는 데이터셋의 각 항목에 대한 점수를 생성하는 **Scoring Phase**이다.

이상 데이터를 포함하는 데이터셋을 다음과 같이 정의한다.

\[
X(n,m) \subset R^m
\]

여기서 \(n\)은 X에 포함된 데이터의 개수이며, \(m\)은 데이터의 차원을 나타낸다.

### A. 학습 단계

Training Phase의 주요 목적은 무작위적이고 서로 독립적인 Tree(itree)로 구성된 Forest를 구축하는 것이다.

\(\psi\)와 \(t\)는 IForest의 핵심 파라미터이다.

IForest는 하나의 Tree를 구축할 때 사용할 Sample을 구성하기 위해 \(\psi\)개의 데이터를 무작위로 선택한다.

이 단계는 IForest의 성능과 효율성의 핵심적인 아이디어이기 때문에 매우 중요하다.

IForest는 X에서 복원 없이 \(\psi\)개의 데이터를 무작위로 선택한다.

각 Sample은 하나의 Tree에만 사용된다는 점에 유의해야 한다.

데이터가 무작위로 선택되고 이상 데이터는 정상 데이터와 비교하여 매우 적다고 가정되기 때문에, Sample에는 정상 데이터만 포함될 수도 있으며 대부분 정상 데이터이고 일부 이상 데이터가 포함될 수도 있다.

Isolation Tree(itree)는 이진 트리이다.

Tree의 구성은 다음과 같이 수행된다.

초기에 Root Node는 Sample의 모든 데이터를 포함한다.

Tree를 구축할 때 각 Internal Node는 데이터가 완전히 격리되거나 최대 Tree Depth에 도달할 때까지 왼쪽과 오른쪽 두 개의 Subnode로 분할된다.

\[
max\_depth = \lceil \log_2(\psi) \rceil
\]

데이터가 하나의 Node에 혼자 존재하면 격리되었다고 간주한다.

그림 1에서 \(X_0\)와 \(X_i\)는 각각 3번과 11번의 Split 이후 격리된다.

Node \(i\)를 Split하기 위해 IForest는 차원 \(d_i\), 즉 `splitDimension`을 무작위로 선택한다.

그다음 해당 차원 \(d_i\)에 대해 현재 Node에 포함된 데이터의 최소값 \(min(d_i)\)과 최대값 \(max(d_i)\) 사이에서 Split 값 \(v_i\), 즉 `splitValue`를 무작위로 선택한다.

Node \(i\)의 요소들은 각각의 값과 \(v_i\)를 비교하여 왼쪽과 오른쪽 두 그룹으로 분할된다.

Training Phase의 의사 코드는 Algorithm 1에 제시되어 있다.

**그림 2. itree 예시, \(\psi = 8\)**

Forest의 \(t\)개의 Tree를 만들기 위해 Sampling과 Tree 구축이라는 두 단계를 \(t\)번 반복한다.

따라서 각각의 Tree는 자신만의 Sample을 가진다.

각 itree의 Sample은 전체 X 데이터셋에서 선택된다.

Training Phase의 복잡도는 다음과 같다.

\[
O(t\psi\log\psi)
\]

이는 \(t\)개의 Tree 각각에서 \(\psi\)개의 데이터 항목이 해당 Tree에서 격리되거나 거의 격리되어야 하기 때문이다.

Tree의 개수 \(t\)는 IForest 성능의 핵심 파라미터이다.

#### 알고리즘 1. iTree(X, e, l) — 트리 구축

**Input**

- X - Node에 포함된 데이터 집합
- e - 현재 Tree Depth
- max_depth - Tree의 최대 Depth

**Output**

- iTree

```text
1  if |X| <= 1 || e >= max_depth then
2      return ExternalNode(size = |X|)
3  else
4      Q ← X의 Attribute 목록
5      q ← Q에서 하나의 Attribute를 무작위로 선택 (q ∈ Q)
6      p ← q에 대한 x 값의 최소값과 최대값 사이에서
           하나의 값을 무작위로 선택
7      l ← filter(X, q < p)
8      r ← filter(X, q >= p)
9      return InternalNode(
           left ← iTree(l, e+1, max_depth),
           right ← iTree(r, e+1, max_depth),
           splitDimension ← q,
           splitValue ← p
       )
```

### B. 점수화 단계

Scoring Phase에서는 X 데이터셋의 각 항목에 대한 점수를 계산한다.

이 점수는 해당 항목과 다른 항목들, 즉 대부분 정상 데이터로 이루어진 항목들 사이의 유사성 정도를 나타낸다.

이 점수를 계산하기 위해 데이터 항목 \(x\)는 Forest에 존재하는 각각의 Tree에서 처리되어야 한다.

Split 기준에 따라 최종적으로 데이터 항목 \(x\)는 각각의 Tree에서 하나의 External Node에 위치하게 된다.

Root Node부터 자신의 External Node에 도달할 때까지 \(x\)가 지나간 Node의 개수를 **Path Length**라고 하며, 이를 \(h(x)\)로 나타낸다.

하나의 Tree에서 \(x\)의 Path Length를 계산하는 의사 코드는 Algorithm 2에 제시되어 있다.

\(x\)가 Forest에 존재하는 모든 Tree에서 처리되고 나면, IForest는 \(x\)에 대한 \(t\)개의 Path Length 평균을 계산하며 이를 \(E(h(x))\)로 나타낸다.

Binary Search Tree(BST)에 관한 잘 알려진 결과를 사용하여 저자들은 \(x\)의 점수 \(s(x,n)\)를 다음과 같이 생성한다.

\[
s(x,n)=2^{-\frac{E(h(x))}{C(n)}}
\]

여기서

\[
C(n)=2H(n-1)-\frac{2(n-1)}{n}
\]

은 Binary Search Tree에서 실패한 탐색의 평균 Path Length이다.

\[
H(i)=\ln(i)+0.5772156649
\]

여기서 0.5772156649는 Euler Constant이며 \(H(i)\)는 Harmonic Value이다.

\(C(n)\)은 정규화된 점수 \(s(x,n)\)를 얻기 위해 사용된다.

이 점수 공식에 따라 데이터는 다음과 같이 분류된다.

- \(E(h(x))\rightarrow C(n)\), \(s\rightarrow0.5\)인 경우: 모든 인스턴스가 \(s\approx0.5\)의 점수를 가진다면 데이터셋에는 식별할 수 있는 이상 데이터가 존재하지 않는다.
- \(E(h(x))\rightarrow0\), \(s\rightarrow1\)인 경우: 데이터 \(x\)의 점수가 1에 매우 가깝다면 이상 데이터이다.
- \(E(h(x))\rightarrow n-1\), \(s\rightarrow0\)인 경우: 데이터 \(x\)의 점수 \(s\)가 0.5보다 훨씬 작다면 정상 데이터이다.

상대적으로 짧은 평균 Path Length \(E(h(x))\)는 \(t\)개의 Tree로 구성된 Forest 전체가 \(x\)를 이상 데이터로 분류한다는 것을 의미한다.

Scoring Phase의 복잡도는 다음과 같다.

\[
O(nt\log\psi)
\]

이는 크기가 \(n\)인 데이터셋의 각 항목이 Forest에 포함된 \(t\)개의 Tree에서 처리되어 Path Length를 평가하고, 평균 Depth와 점수를 생성해야 하기 때문이다.

따라서 \(t\)와 \(\psi\)는 입력으로 주어지는 상수 파라미터이므로 IForest는 데이터셋의 크기 \(n\)에 비례하는 선형 복잡도를 가진다.

#### 알고리즘 2. PathLength(x, Tᵢ, e)

**Input**

- x - 데이터 하나
- \(T_i\) - itree
- e - 현재 Path Length  
- 첫 호출에서 e는 0으로 초기화된다.

**Output**

- itree \(T_i\)에서 x의 Path Length

```text
1  if Ti가 External Node이면
2      return e + C(Ti.size)
       /* C(n)은 II-B에서 정의됨 */
3  q ← Ti.splitDimension
4  if xq < Ti.splitValue then
5      return PathLength(x, Ti.left, e + 1)
6  else
       /* xq >= Ti.splitValue */
7      return PathLength(x, Ti.right, e + 1)
```

Swamping과 Masking은 IForest에서 실제로 중요한 문제이며, IForest는 일정한 한도 내에서 이러한 문제를 처리한다.

**Swamping**은 두 종류의 데이터가 서로 유사하기 때문에 정상 데이터를 이상 데이터로 분류하는 현상을 의미한다.

정상 데이터가 이상 데이터와 매우 가까운 경우 이상 데이터를 분리하는 데 필요한 Partition 수가 증가하여 이상 데이터와 정상 데이터를 구별하기 어려워진다.

**Masking**은 서로 유사한 이상 데이터가 많이 존재하여 각각을 개별적으로 격리하기 어려워지는 현상을 의미한다.

이상 데이터 집단이 크고 밀집되어 있다면 각각의 이상 데이터를 격리하기 위해 필요한 Partition 수가 증가한다 [22].

따라서 이러한 비정상 데이터가 정상 데이터로 간주될 수 있다.

IForest가 Random Tree Forest를 구축할 때 전체 데이터셋이 아니라 Random Sample을 사용한다는 점은 Masking과 Swamping을 처리하는 데 도움이 된다.

Sampling을 사용하면 실제 데이터셋보다 낮은 밀도의 데이터를 고려할 수 있기 때문에 이상 데이터를 정상 데이터와 더 잘 분리할 수 있으며, 이상 데이터끼리도 더 잘 분리할 수 있다.

또한 Forest의 각각의 Tree는 자신만의 Sample을 이용하여 구축된다.

Tree들이 반드시 동일한 이상 데이터를 격리하는 것은 아니며 일부 Sample에는 이상 데이터가 하나도 존재하지 않을 수도 있다.

따라서 IForest는 Swamping과 Masking 효과에 대해 강건하다.

## III. IForest의 기존 개선 방법

이상 탐지를 위한 Isolation 기법은 여러 연구에서 다루어졌다.

2008년에 최초의 IForest 방법([22], [24])이 설계된 이후 많은 적용 방법과 개선 방법이 제안되었다.

여러 연구자들은 IForest의 몇 가지 한계를 확인하고 이러한 한계를 극복하기 위한 개선 방법을 제안하였다.

우리는 제안된 방법을 고려하는 데이터의 종류에 따라 두 가지 범주로 분류하였다.

### A. 배치 데이터

[23]에서 저자들은 거리 및 밀도 기반 방법과 마찬가지로 데이터 내부의 Cluster를 식별할 수 있는 **SCiForest** 방법을 제안하였다.

따라서 SCiForest는 Local Anomaly를 탐지하기 위한 Clustering 방식의 IForest 확장 방법이다.

SCiForest는 Node의 데이터를 분할하기 위해 Hyperplane을 무작위로 선택함으로써 여러 Attribute에 동시에 존재하는 이상 데이터를 고려한다.

서로 다른 Cluster를 분리하기 위해 SCiForest는 각 Node의 데이터 Standard Deviation을 고려하여 Split Criterion을 설정한다.

SCiForest의 처리는 복잡한 데이터에 적합하지만 높은 복잡도를 가지며, 이는 이 방법의 주요 단점이다.

Node 내부에서 데이터를 Split하는 방식이라는 동일한 맥락에서 [17]의 저자들은 **Extended IForest(EIF)** 알고리즘을 제안하였다.

EIF는 Node를 수직 또는 수평으로 Split함으로써 IForest의 점수에 발생하는 불일치를 수정한다.

이 방법은 Section IV에서 자세히 설명한다.

[31]에서는 최근 Functional Dataset에서 이상을 탐지하기 위한 **FIF(Functional IForest)** 방법을 제안하였다.

IForest가 모든 데이터셋 분포에서 효율적이지 않다는 관찰을 바탕으로 [25]에서는 **Hybrid IForest(HIF)**를 제안하였다.

저자들은 비교적 긴 Path를 가진 Leaf Node에 비정상 데이터가 존재할 가능성을 고려하기 위해 동일한 Leaf Node에 포함된 데이터의 유사성을 고려하는 새로운 Decision Criterion을 추가하였다.

이 추가 단계의 주요 목적은 False Negative를 줄이는 것이다.

실제로 IForest의 원래 버전에서는 이상 데이터 사이의 유사성 때문에 일부 이상 데이터를 놓칠 수 있다. 이것이 앞에서 설명한 Masking Effect이다.

지도 및 비지도 기법을 결합함으로써 HIF는 서로 다른 분포를 가진 다양한 데이터셋에서 이상 데이터를 탐지할 수 있다.

그러나 지도 기반 이상 탐지에 필요한 Label을 얻는 것이 항상 쉬운 것은 아니다.

[8]에서 저자들은 IForest를 사용하여 Tree에서 각 데이터의 Path Length를 계산하고 이 Metric을 두 Point 사이의 새로운 거리로 정의하였다.

Euclidean Distance나 Manhattan Distance와 같은 다른 거리 방법보다 더 강건하다.

또한 범주형 데이터 및 Missing Data에 IForest를 적용할 수 있도록 하였다.

**Simulated Annealing IForest(SA-IForest)** [34]는 Training Phase에서 보다 안정적이고 강한 Forest를 생성하기 위한 IForest의 개선 방법이다.

이를 위해 SA-IForest는 먼저 IForest를 이용하여 첫 번째 Forest를 구축한다.

그다음 Forest에 포함된 Tree들 사이의 유사성을 계산한다.

Tree의 Precision 역시 Cross Validation을 이용하여 계산한다.

과정이 끝나면 Precision이 높은 Tree만 유지한다.

이 검증 과정에서는 Training Data의 Labeling이 필요하며, 이러한 Labeling을 항상 쉽게 수행할 수 있는 것은 아니다. 이것이 이 Semi-supervised 방법의 한계이다.

데이터의 차원 수가 증가할 때 IForest의 효율성이 떨어지는 문제를 해결하기 위해 [21]에서는 **Entropy IForest(E-IForest)** 방법을 제안하였다.

이 방법은 Noisy Data가 존재할 경우 IForest의 강건성이 부족한 문제도 처리한다.

저자들에 따르면 문제는 Tree의 각 Node에서 데이터를 Split할 Attribute를 선택하는 방식에 있다.

따라서 저자들은 Entropy를 기반으로 하는 IForest의 확장 방법을 제안하였다.

Node를 Split할 때 E-IForest는 Random Sample에서 해당 Attribute의 Entropy를 기반으로 Attribute를 선택한다.

이 논문에서는 가장 적절한 Attribute를 선택하기 위한 여러 전략이 연구되었다.

[36]에서 저자들은 IForest가 거리나 밀도 개념을 기반으로 하지 않는다고 알려져 있지만 Random Dimension을 따라 연속적인 Split을 수행하기 때문에 암묵적으로 Manhattan Distance를 사용한다는 점을 발견하였다.

따라서 원래 버전의 IForest는 이 Distance Measure에 제한되며 다른 Distance Measure를 처리할 수 없다.

저자들은 이후 IForest를 다른 Distance Measure와 Data Space로 일반화한 **LSHIForest(Locality-Sensitive Hashing IForest)** [36]라는 Generic Framework를 제안하였다.

정상 데이터가 다수를 차지하는 불균형 데이터셋에서 Sampling하는 것은 간단하지 않다.

Sampling 전에 데이터셋의 균형을 맞추기 위한 여러 방법이 존재한다.

이러한 방법은 두 가지 범주로 분류할 수 있다.

- **Over-sampling:** 합성 데이터를 이용하여 Minority Class를 추가
- **Under-sampling:** 더 나은 균형을 위해 Majority Class에서 데이터를 제거

Over-sampling은 **SMOTE**라는 방법을 이용하여 수행할 수 있다.

[37]에서 저자들은 IForest를 이용하여 데이터의 Category를 식별하고 순위를 매겼다.

그다음 SMOTE를 이용하여 Neighborhood 정보를 기반으로 새로운 데이터를 생성하였다.

따라서 **IForest-SMOTE**는 IForest의 사전 선택과 SMOTE 방법을 이용하여 새로운 데이터를 생성함으로써 데이터셋의 균형을 맞출 수 있다.

두 번째 범주에서 **IOS(Isolation Forest Outlier Detection and Subset Selection)** [7]는 대표적인 Sample을 생성하기 위해 설계된 방법이다.

IOS는 IForest를 이용하여 이상 데이터를 탐지한다.

일부 정상 데이터를 제거하고 균형이 맞춰진 데이터셋을 기반으로 Sample을 구성한다.

### B. 데이터 스트림

앞에서 설명한 IForest 및 여러 개선 방법은 데이터가 지속적으로 도착하고 휘발성이 있는 Data Stream 환경에는 적합하지 않다.

다음 방법들은 Data Stream 환경에 적합하도록 IForest를 확장한 것이다.

- Isolation Forest Algorithm for Streaming Data(IForest ASD) [9]
- Half-Space Trees(HSTrees) [32]
- PCB-iforest [18]

IForest ASD는 Sliding Window 기법으로 데이터를 가져온다.

각 Window에서는 이전 Window의 데이터로 생성한 Model을 기반으로 IForest를 실행하여 이상을 탐지한다.

Drift가 발생하면 이 Model을 다시 초기화한다.

HSTrees는 Streaming 환경을 위해 설계된 IForest의 확장 방법이다.

HSTrees는 무작위로 선택한 Attribute에서 Node에 포함된 데이터의 평균값을 이용해 Node를 Split한다.

그 결과 IForest ASD와 달리 HSTrees는 Model을 재초기화하지 않고도 Concept Drift([12], [13])를 자동으로 관리한다.

실제로 HSTrees는 IForest ASD보다 빠르며, 고려하는 데이터셋과 독립적으로 Model을 구축한다.

그러나 IForest ASD는 데이터셋과 밀접하게 연결되어 있다.

Concept Drift를 관리하기 위해 IForest ASD는 Anomaly Rate를 나타내는 입력값 \(\mu\)를 유지한다.

주어진 Window에서 Anomaly Rate가 \(\mu\)를 초과하면 IForest ASD는 데이터의 정상 행동에 변화, 즉 Drift가 발생했다고 판단하고 현재 Window의 데이터로 Model을 갱신한다.

이 갱신은 기존 Model을 삭제하고 현재 Window의 데이터를 기반으로 새로운 Model을 다시 구축하는 방식이다.

이 접근법은 각 Concept Drift가 발생할 때마다 기존 정상 행동에 대한 전체 History가 사라지기 때문에 효율적이지 않다.

**Randomized Space Trees(RS-Forest)** [33]도 Isolation 개념을 기반으로 Data Stream에서 이상을 탐지하는 방법이다.

Concept Drift를 처리하기 위해 Model을 갱신할 필요가 있는지를 판단하는 Density Estimator를 사용한다.

RS-Forest는 이상 데이터가 낮은 밀도를 가진다는 가정을 기반으로 한다.

이는 앞에서 설명한 이상 데이터의 희소성과, 이상 데이터가 서로 다르고 정상 데이터와도 다르다는 가정과 일치한다.

[2]에서는 Tree 기반 이상 탐지 방법에 대한 최근의 종합적인 Review를 제공하였다.

본 논문에서는 그중 Isolation 기반 이상 탐지 방법에만 초점을 맞춘다.

앞에서 설명한 Isolation 기반 이상 탐지 방법의 요약은 그림 3에 제시되어 있다.

**그림 3. Isolation 기반 이상 탐지 방법의 분류**

Isolation 기반 이상 탐지 방법은 여러 Framework에서 구현되어 있다.

가장 잘 알려진 Framework는 정적 데이터에 초점을 맞춘 **scikit-learn**이며 IForest 알고리즘을 구현하고 있다.

또 다른 IForest 구현은 Machine Learning 분야에서 잘 알려진 **H2O Framework**에서 제공된다.

HSTrees [32], IForest ASD [9]와 같이 Data Stream에 적합한 일부 버전은 scikit-learn의 Streaming 버전인 Open Source Framework **scikit-learn multiflow** [27]에 구현되어 있다.

[16]에서는 Cloud 기반 이상 탐지 Framework를 제안하였다.

이 Framework는 Spark Cluster와 여러 User Interface를 사용하며 모두 Kubernetes에 의해 관리된다.

2008년 IForest가 개발된 이후 다양한 개선 방법들이 제안되어 왔다.

본 Section에서는 문헌에 존재하는 IForest의 모든 확장 및 적용 방법을 제시하였다.

본 논문에서는 동일한 탐지 효율성을 유지하면서 실행 시간을 줄이기 위한 IForest의 개선 방법을 제안한다.

다른 방법과 달리 우리가 제안하는 방법은 추가적인 계산을 필요로 하지 않는다.

또한 데이터의 분포에 의존하지 않는다.

다음 Section에서는 여러 실험을 통해 IForest와 비교할 EIF에 초점을 맞춘다.

또한 우리가 제안하는 새로운 IForest 확장 방법을 제시한다.

## IV. Extended Isolation Forest

### A. 다루는 IForest의 한계

IForest는 강력한 방법이지만 몇 가지 단점을 가진다.

문헌에서 다루어진 IForest의 한계 중 하나는 데이터 분류의 **일관성 부족**이다.

IForest는 각 데이터에 점수를 부여한다.

이상의 정의에 따르면 데이터가 다른 데이터와 더 많이 다를수록 더 높은 점수를 받을 것으로 예상된다.

그러나 IForest가 부여하는 점수에서는 항상 그렇지 않다.

따라서 IForest 점수의 설계에는 일정한 불일치가 존재한다.

이러한 약점을 설명하기 위해 그림 4에서는 Ring 위에 균등하게 분포한 2차원 데이터셋을 고려하였다.

이상 데이터는 Ring의 중심에 배치하였다.

이 분포는 회전해도 변하지 않는다.

IForest를 실행한 후 IForest가 부여한 점수에 대응하는 Heat Map을 나타냈다.

Point Density가 높은 영역은 점수가 낮으며 따라서 정상 데이터 영역으로 간주된다.

Heat Map 중심부의 균일한 밝은 색은 데이터가 원형 Disc 전체에 분포되어 있는 것처럼 보이게 하며, 중심이 거의 비어 있는 Ring 형태를 반영하지 못한다.

밀도가 높은 영역에서 멀어질수록 점수는 증가한다.

Border 영역의 Edge Effect와 데이터가 존재하지 않는 영역에 해당하는 어두운 부분을 명확하게 확인할 수 있다.

그러나 Heat Map은 실제 데이터와 동일한 대칭성을 가지지 않는다.

Heat Map은 회전에 대해 불변하지 않다.

보다 정확히 말하면 Ring이 Square 형태로 변하였으며, 매우 높은 점수를 가진 네 개의 어두운 Corner가 인위적으로 나타난 것을 확인할 수 있다.

이 영역들은 이상 데이터로 간주된다.

이러한 현상은 Training Phase에서 IForest가 Node를 Split하는 방식 때문에 발생한다.

IForest는 각 Node를 수직 또는 수평으로 Split한다.

이 때문에 실제로 다른 데이터가 존재하는 것처럼 인위적인 밀집 영역이 생성된다.

그림 4는 Forest Tree를 구축할 때 Node를 Split하는 예를 보여준다.

데이터셋을 여러 번 Split하면서 Ring 외부에 높은 밀도를 가진 인위적인 직사각형 영역이 생성되는 것을 확인할 수 있다.

**그림 4. IForest의 Node Split 예와 그에 따른 Score Heat Map: 인위적인 가상 영역의 존재. X와 Y는 데이터 항목의 좌표이다.**

이 문제를 해결하는 IForest의 확장 방법이 EIF이다.

EIF의 핵심 아이디어는 IForest처럼 반드시 수평이나 수직으로 분할하는 것이 아니라 무작위로 선택한 방향에 따라 Node의 데이터를 Split하는 것이다.

이를 통해 IForest가 생성하는 가상 영역을 제거하고 점수의 일관성을 개선한다.

### B. EIF 방법

Section II에서 설명한 것처럼 2차원 데이터의 경우 IForest는 각 Node를 수평 또는 수직으로 Split한다.

이러한 Split은 Score Heat Map에서 명확하게 확인되는 Bias를 발생시킨다.

이 불일치를 수정하기 위한 **Extended Isolation Forest(EIF)** 방법은 [17]에서 제안되었다.

EIF와 IForest의 가장 큰 차이는 Node의 데이터를 Split하는 방법이다.

EIF 역시 IForest처럼 다음 두 단계로 구성된다.

- Training Phase
- Scoring Phase

Scoring Phase는 두 방법에서 동일하지만 Training Phase는 크게 달라졌다.

IForest와 달리 EIF는 모든 Dimension을 조합하여 무작위로 선택한 Point와 Direction에 따라 Node를 Split한다.

EIF를 이용한 Data Split의 예는 그림 5에 제시되어 있으며, Node가 비스듬하고 무작위적인 방향으로 Split되는 것을 확인할 수 있다.

동일한 데이터셋에서 얻은 Score Heat Map 역시 그림 5에 제시되어 있다.

이 실험에서도 학습 단계의 트리 표본을 구성할 때 정상과 이상 데이터를 모두 사용하였다. 데이터 분포와 히트맵의 색이 정확히 대응한다. 점수 히트맵에도 원형이 유지되며, IForest에서 보였던 인위적인 밀집 영역이 사라졌다. 고리 중심의 비교적 어두운 색은 중앙 데이터가 있는 고리 형태를 뚜렷하게 나타내 IForest보다 정확하다. 따라서 이 히트맵은 원래 데이터셋의 실제 분포에 부합한다.

차원 수가 더 많아져도 EIF의 원리는 같다. 노드는 법선 벡터 `n⃗`과 절편점 `p⃗`으로 정의되는 무작위 초평면을 따라 분할된다. 임의의 데이터 `x⃗`에 대해 `(x⃗ − p⃗) · n⃗ ≤ 0`이면 왼쪽 자식 노드에, 그렇지 않으면 오른쪽 자식 노드에 배정한다.

EIF는 IForest의 점수 불일치를 해결하지만 고려해야 할 한계도 있다. IForest의 오경보율을 크게 줄이는 반면 이상 탐지 성능이 항상 더 높은 것은 아니다.

**그림 5.** EIF의 노드 분할 예와 해당 점수 히트맵. 인위적인 가상 영역이 사라졌다. X와 Y는 데이터 항목의 좌표이다.

다만 EIF가 이상 탐지 성능에서 항상 IForest보다 우수한 것은 아니다. 두 방법의 비교는 VIII절에서 수행한다.

## V. 실험: 데이터셋과 평가 지표

IForest의 성능을 평가하기 위해 여러 실제·합성 데이터셋에서 시험하였다. 모든 실험, 합성 데이터셋 생성, MVIForest의 소스 코드는 공개 저장소 <https://github.com/Elmecio/IForestStudyAndMVIForest>에서 이용할 수 있다.

### A. 공개 데이터셋

사용한 실제 데이터셋은 공개되어 있으며 이상 탐지 분야에서 자주 사용된다. 확인된 이상에 대한 레이블이 있지만, IForest는 비지도 방법이므로 실행 중에는 레이블을 사용하지 않는다. 레이블은 특이도와 ROC AUC 등 결과 평가에만 사용한다. 데이터셋은 캘리포니아대학교의 UCI Machine Learning Archive [10]에서 가져왔다. 이 저장소는 머신러닝 알고리즘의 시험, 검증, 비교에 유용하다. 표 1과 같이 크기, 차원 수, 이상 비율이 다른 네 데이터셋을 선택하였다.

HTTP와 SMTP는 네트워크 침입을 기술하는 대규모 KDD-CUP99 데이터셋에서 가져왔다. Shuttle은 NASA가 수집한 레이더 관련 9개 속성의 데이터셋으로, 이상 비율이 가장 높다. ForestCover는 콜로라도주 루스벨트 국유림의 네 지역에 있는 나무를 기술한다. 수종, 그림자 범위, 도로 등 인근 지형지물까지의 거리, 토양 종류, 지형을 나타내는 10개 속성이 있다. [9]와 같은 데이터셋을 사용하였다. HTTP와 SMTP는 원래의 41개 속성 가운데 서비스, 지속 시간, src-bytes, dst-bytes의 관련 속성만 남기도록 전처리되었다. 두 데이터셋에서 이상은 네트워크 공격이다. 전처리 방법은 [9]에 기술되어 있다. 원래 KDD-CUP99에는 4,898,431개 데이터 중 공격이 3,925,651개(80.1%) 포함되어 이상 탐지에 사용하기에는 지나치게 많다. 따라서 [9]의 저자들은 전체 데이터에서 `logged_in` 속성이 양수인 데이터를 선택해 하위 데이터셋을 만들었다. 이 가운데 `logged_in`이 양수인 공격을 침입으로 부른다. 자세한 내용은 [9]에 있다. ForestCover는 10차원이고 Shuttle은 9차원이다.

**표 1. 공개 데이터셋**

| 데이터셋 | 크기 (n) | 차원 수 | 이상 비율 |
|---|---:|---:|---:|
| HTTP | 567,498 | 3 | 0.39% |
| SMTP | 95,156 | 3 | 0.03% |
| Shuttle | 49,097 | 9 | 7.15% |
| Forest Cover | 286,048 | 10 | 0.96% |

### B. 합성 데이터셋

데이터 특성 변화에 대한 IForest의 작동과 민감도를 시험하기 위해 합성 데이터셋을 사용하였다. 실제 데이터셋의 이상은 대개 하나의 속성에서 나타나므로 특정 매개변수의 영향을 자세히 분석하기 어렵다. 이에 합성 데이터셋에서 차원 수, 정상·이상 데이터의 밀도, 두 부류 사이의 거리를 변화시켰다. 이를 통해 IForest의 한계를 평가하고 입력 매개변수를 조정할 수 있다. 다변량 데이터에서는 모든 차원에 동시에 나타나면서 정상 데이터로 둘러싸인 이상을 설계하였다.

2차원 합성 데이터셋에서 정상 데이터는 고리 모양으로 균일하게 분포하고, 이상 데이터는 그 중앙의 더 작은 원판에 균일하게 분포한다. 3차원에서는 정상 데이터가 구의 두꺼운 껍질에 있고, 이상 데이터는 중앙의 더 작은 구에 균일하게 분포한다. 따라서 이상은 언제나 정상 데이터에 둘러싸여 있으며, 단순하게 분리되지 않아 탐지 알고리즘의 한계를 시험할 수 있다. 사용한 데이터셋은 그림 6과 7에 제시하였다. 이상은 빨간색, 정상은 파란색이다. 모든 데이터셋은 정상 1,500개와 이상 15개(1%)로 구성되며 좌표는 설명한 분포 안에서 무작위로 선택된다. 표 2와 같이 고리의 두께와 중앙 구의 반지름을 바꾸어 밀도와 거리를 시험하였다. 생성 코드는 앞서 제시한 공개 저장소에 있다.

그림 6의 Synthetic_1은 정상 데이터의 밀도가 높고 정상과 이상의 거리가 짧다. 그림 7(a)의 Synthetic_2는 고리 두께만 늘려 정상 데이터의 밀도가 감소할 때의 영향을 평가하며, 두 부류의 거리는 여전히 짧다. 그림 7(b)의 Synthetic_3은 정상 데이터의 밀도가 높고 정상과 이상의 거리가 멀다. 그림 7(c)의 Synthetic_4는 큰 거리를 유지하면서 정상 데이터의 밀도를 낮춘다. 그림 7(d)의 Synthetic_5는 앞서 논의한 마스킹 효과를 시험한다. 이상이 분포하는 원판의 반지름을 크게 줄여 유사도가 높고, 이상은 고리 중앙에 더 밀집한다. 표 2에 특성을 요약하였다. 각 2차원 데이터셋에 대응하는 3차원 데이터셋도 그림 6의 Synthetic_1과 같은 방식으로 만들었다.

**그림 6.** Synthetic_1: 높은 정상 데이터 밀도(ND++), 낮은 이상 데이터 밀도(AD+), 작은 정상·이상 거리(dAN+). (a) 2차원, (b) 3차원.

**표 2. 합성 데이터셋의 특성.** +는 낮음, ++는 높음. ND는 정상 데이터 밀도, AD는 이상 데이터 밀도, dAN은 정상·이상 데이터 사이 거리.

|---|:---:|:---:|:---:|
| Synthetic_1 | ++ | + | + |
| Synthetic_2 | + | + | + |
| Synthetic_3 | ++ | + | ++ |
| Synthetic_4 | + | + | ++ |
| Synthetic_5 | + | ++ | + |

**그림 7.** 2차원 합성 데이터셋. 모든 합성 데이터셋은 정상 데이터 1,500개와 이상 데이터 15개로 구성된다.

### C. 평가 지표

머신러닝, 특히 이상 탐지에서는 여러 지표로 접근법을 평가·비교할 수 있다. 도착 속도가 계속 증가하는 데이터 스트림에서 방법의 확장성을 평가하려면 실행 시간과 메모리 요구량이 중요하다. 또한 재현율, 특이도, 정밀도, F1 점수, ROC 곡선 아래 면적도 고려한다.

#### 1) 실행 시간

머신러닝 알고리즘은 학습 단계와 그에 이은 시험 단계로 이루어진다. 실행 시간은 각 단계에 소요된 시간이다. IForest의 시간 복잡도는 학습에서 최악의 경우 `O(tψ²)`, 시험에서 `O(ntψ)`이다([24]). 학습 시간은 전체 데이터 크기에 관계없이 일정하다는 점에 주목한다.

#### 2) 메모리 요구량

IForest의 메모리 요구량은 `O(tψ)`로 낮다([24]). 따라서 데이터셋 크기와 관계없이 메모리 사용량이 일정하며, 이는 대용량 데이터 처리에 상당한 장점이다.

#### 3) ROC AUC, 재현율, 특이도, F1 점수, 오경보율

불균형 데이터셋의 이진 분류인 이상 탐지에서는 정상과 이상의 두 클래스만 있다. 본 논문에서는 scikit-learn [29]을 사용하였다. 다만 scikit-learn의 정의와 달리 이상 탐지 분야의 관례에 따라 정상을 음성(Negative), 이상을 양성(Positive)으로 두었다. 혼동 행렬에서 재현율, ROC AUC, F1 점수를 계산하는 데 scikit-learn API를 사용하였다.

정밀도는 참양성(TP)과 거짓양성(FP)에 달려 있다. 분류 능력을 평가할 때 유용하지만, 정상 데이터가 이상 데이터보다 훨씬 많은 불균형 데이터셋에서는 최선의 지표가 아닐 수 있다. 이때 거짓양성(오경보)의 수가 참양성보다 많을 수 있다.

```text
Precision = TP / (TP + FP)
```

특이도는 정상 데이터를 탐지하고 오경보를 피하는 성능을 평가하는 데 유용하다. 논문에 제시된 식은 다음과 같다.

```text
Specificity = TN / (TN + FN)
```

여기서 TN은 참음성의 수, FN은 거짓음성의 수이다. 오경보율(FAR)은 정상 데이터를 이상으로 분류한 수를 실제 정상 데이터 총수로 나눈 비율이다. 이상 탐지 방법은 오경보를 최소화하면서 모든 이상을 탐지하는 것을 목표로 한다. 문맥에 따라 허용되는 오경보에는 한계가 있으며, 실제 이상 탐지와 오경보 사이에는 절충 관계가 있다.

```text
FAR = FP / (FP + TN) = 1 − specificity
```

어떤 응용 분야에서는 이상, 특히 올바르게 분류한 이상의 비율에 초점을 맞춘다. 이때 적합한 지표는 재현율이다. FAR과 재현율 사이에는 절충 관계가 있으므로, 이상을 놓쳤을 때의 영향을 지표 선택에 고려해야 한다.

```text
Recall = TP / (TP + FN)
```

ROC AUC는 이상 탐지 효율을 수치화하는 데 자주 쓰인다. 탐지 효율이 높아질수록 ROC AUC는 증가하며 최대 1이다(그림 8). 대각선은 완전히 무작위인 방법의 그래프이다. 두 방법을 비교할 때는 F1 점수도 사용할 수 있다. 이상이 정상보다 훨씬 적은 불균형 데이터에서 유용한 지표이다.

```text
F1 score = 2 × (precision × recall) / (precision + recall)
```

## VI. Isolation Forest의 연구 및 평가

IForest는 여러 기준에서 최신의 효율적인 이상 탐지 방법 중 하나이며, 비교 연구에서도 그 성능이 강조되었다. 그러나 모든 방법과 마찬가지로 개선할 수 있는 한계가 있다. VI-A에서 기존 문헌에서 다루지 않은 한계를 제시하고, VI-C에서 매개변수의 영향, VI-D에서 표본 내 이상 데이터의 유무, VI-E에서 차원 수 증가의 영향, VI-F에서 결정 임계값 선택을 분석한다. 별도로 명시하지 않는 한 저자들이 권장한 기본값인 `t = 100`, `ψ = 256`을 사용하며 결정 임계값은 `0.6`이다.

### A. IForest의 한계

문헌에서는 IForest의 일부 한계를 파악하고 EIF, IForest ASD 등의 확장 방법으로 다루었다. 여기에서는 방법의 견고성을 높이고 이상 탐지 방법들 사이에서의 위치를 개선할 수 있는 다른 한계를 살펴본다.

#### 1) 결정 임계값

IForest는 데이터 `x`마다 여러 트리에서의 평균 경로 길이 `E(h(x))`를 바탕으로 점수 `s(x)`를 계산한다. 원 논문 [22]에서는 결정 임계값으로 0.5를 권장한다.

- `E(h(x)) → 0`이면 `s → 1`이고, 점수가 1에 매우 가까우면 `x`를 이상으로 볼 수 있다.
- `E(h(x)) → n − 1`이면 `s → 0`이고, 점수가 0.5보다 훨씬 작으면 `x`를 정상으로 볼 수 있다.

그러나 어떤 점수부터 이상으로 보아야 하는지 정확하지 않다. 이는 IForest의 첫 번째 한계이다.

#### 2) IForest 매개변수의 선택

IForest의 입력 매개변수는 표본 크기와 표본의 수이다. [22], [24]는 `ψ = 256`이 짧은 실행 시간과 낮은 메모리 요구량으로 좋은 결과를 낸다고 권장한다. 또한 안정적인 결과를 위해 트리 `t = 100`개를 권장한다. 100개를 넘기면 성능 이득은 없고 실행 시간과 메모리 사용량만 증가한다고 제시하였다.

실험 결과, 탐지 성능(특이도, 재현율, AUC)은 이러한 매개변수와 데이터셋의 특성에 달려 있었다. 특히 표본 크기의 영향이 크다. 표본이 너무 크거나 표본 추출 비율이 너무 높으면 트리들이 서로 매우 비슷해져 무작위 독립 트리로 이루어진 숲이라는 원칙과 어긋날 수 있다. 반대로 비율이 지나치게 낮으면 표본이 전체 데이터를 대표하지 못하고 트리가 너무 얕아 이상을 분리하지 못할 위험이 있다. 따라서 핵심 입력 매개변수인 표본 크기를 조정해야 한다. 이 한계는 VI-C에서 다룬다.

#### 3) 데이터 차원

[22]에서는 많은 차원이 중요하지 않을 경우 IForest가 고차원 데이터에서도 좋은 결과를 낸다고 하였다. 관련 차원만 선택해 차원을 줄이기 위해 첨도(Kurtosis) 같은 통계 검정도 제안하였다. 하지만 입력 매개변수 선택에는 차원 수 `m`이 반영되지 않는다. 여러 차원에 동시에 나타나는 이상은 더 탐지하기 어렵다. 그림 6은 이상이 각각 2차원과 3차원에 나타나는 경우를 보여준다.

두 경우 모두 기본 설정에서 약 15%의 높은 거짓양성률이 나왔다. 2차원에서는 이상이 정상에서 충분히 멀 때만 탐지되었고, 3차원에서는 어떤 이상도 탐지되지 않았다. 관련 차원 수가 늘수록 성능이 감소한다. 트리를 만들 때마다 `m`개 차원 중 하나를 무작위로 고르지만, 최대 깊이 `⌈log₂(ψ)⌉`는 `m`에 관계없다. `m`이 크면 일부 차원은 선택되지 않을 수 있다. VI-E에서 이를 다룬다.

#### 4) 결정 방법

항목 `x`는 숲의 트리들이 내린 집단 결정에 따라 이상으로 판정된다. `t`개 격리 트리는 평균 경로 길이 `E(h(x))` 계산에 모두 사용된다. 점수화 단계에서 각 항목이 모든 트리를 통과해야 하므로 실행 시간은 데이터 크기뿐 아니라 트리 수에도 좌우된다. 다른 결정 방법을 택하면 시간을 크게 줄일 수 있다. 연구진은 다수결을 적용하여 오경보율과 실행 시간을 줄였으며, 이 방법은 VII절에서 제시한다.

### B. IForest의 무작위성 효과

IForest에서는 숲의 각 트리를 위한 표본, 각 노드에서 다룰 차원과 분할값을 모두 무작위로 선택한다. 이 무작위성이 결과에 미치는 영향을 알아보기 위해 V-A의 Shuttle 데이터셋에서 결정 임계값 0.5로 IForest를 10회 실행하고 결과의 분산을 살펴보았다. 표 3에서 ROC AUC, 특이도, 재현율은 10회에 걸쳐 거의 일정했고 표준편차는 0에 가까웠다. 따라서 무작위성에도 결과가 안정적이며 한 번의 실행에 의존할 수 있다.

### C. IForest 매개변수의 영향

표본 크기 `ψ`와 트리 수 `t`는 IForest의 성능에 중요하다. 사용자는 결과를 최적화하도록 이를 선택해야 한다. 특히 개념 변동이 있는 데이터 스트림에 적용할 때는 스트림의 변하는 특성에 입력 매개변수가 자동으로 적응하는 것이 바람직하다. 여기에서는 두 매개변수가 IForest 효율에 미치는 영향을 살펴본다.

#### 1) 표본 크기의 영향

실행 시간은 표본 또는 트리 수 `t`와 각 표본의 크기 `ψ`에 관련된다. `ψ`의 영향을 살펴보기 위해 `t`는 기본값인 100으로 고정하였다. 그림 9의 Shuttle 실험에서는 표본 크기가 커질수록 실행 시간이 길어졌다. 트리의 최대 길이가 표본 크기에 좌우되고 각 트리가 표본 하나에서 만들어지기 때문이다. 그러나 트리가 커져도 반드시 성능이 좋아지는 것은 아니다. 일정 수준을 넘어서면 표본이 커질수록 재현율이 떨어져 이상을 덜 탐지한다. 반면 정상 데이터는 잘 분류되어 특이도가 빠르게 1에 도달한다. 표본이 매우 크면 모든 데이터를 정상으로 분류하는 경향이 있다. 가능한 이유는 표본이 커질수록 숲의 트리들이 서로 닮아 중복되고, 집단 결정의 질이 낮아지는 것이다. 좋은 표본은 원래 데이터를 충분히 대표하면서도 작아야 한다. 최적 크기는 데이터셋의 성질과 분산에 달려 있다.

그림 10에서는 V-A의 실제 데이터셋 네 개에서 각각 적합한 표본 크기를 찾았다. Shuttle과 SMTP에서는 `ψ = 1024`, ForestCover에서는 `ψ = 2048`, HTTP에서는 `ψ = 4096`일 때 ROC AUC가 가장 높았다. SMTP와 HTTP는 최적 크기 이후에도 ROC AUC가 유지되었지만, ForestCover와 Shuttle은 더 커지면 성능이 떨어졌다. 숲의 트리 최대 길이와 이상 탐지 능력은 표본 크기에 달려 있으므로 데이터셋에 맞는 입력값을 제공해야 한다.

#### 2) 트리 수의 영향

IForest는 무작위·독립 이진 트리로 이루어진 숲을 사용한다. 각 트리는 같은 크기의 독립적인 무작위 표본에서 만들어지고, 데이터의 정상·이상 분류 결정에 동등하게 참여한다. 트리 수는 입력 매개변수이며 메모리 요구량과 밀접하게 관련된다. 그 영향을 평가하기 위해 여러 `t` 값을 시험하되 표본 크기는 기본값 `ψ = 256`으로 고정하였다.

예상대로 트리가 늘면 학습에서 더 많은 트리를 만들고 시험에서도 각 항목이 모든 트리를 지나므로 실행 시간이 길어진다. 그림 11에서 ROC AUC, 특이도, 재현율에는 트리 수가 큰 영향을 미치지 않는다. 일정 수 이후 지표 값은 수렴하지만 실행 시간은 선형적으로 증가한다. 따라서 트리 수 100개라는 권장은 실행 시간과 결정 품질 사이의 좋은 절충안이다. ROC AUC가 최대값에 가까운 1로 빠르게 수렴한다는 점도 IForest의 효율성을 확인해 준다.

### D. 표본에 이상 데이터가 포함된 경우의 영향

표본은 무작위로 선택되므로 학습 표본에 이상이 없을 수도 있다. 학습 단계에서 이상의 포함 여부를 평가하기 위해 Synthetic_3(그림 7b)에서 두 실험을 하였다. 첫 번째 `AllDataset`은 정상과 이상 전체에서 무작위로 뽑고, 두 번째 `NormalOnly`는 정상 데이터에서만 뽑았다. 결과는 표 4에 있다.

정상과 이상이 섞인 표본으로 트리를 만들 때 IForest의 성능이 더 좋았다. 정상만 사용하면 ROC AUC가 0.95, 오경보율이 9%였다. 일부 정상 데이터가 다른 데이터와 약간 다르다는 이유로 트리에서 너무 일찍 분리된 것이다. 이상이 표본에 있으면 오경보율은 8%로 떨어지고 ROC AUC는 0.96으로 올라갔다. 이상이 포함되면 노드의 특정 차원에서 값의 범위가 일반적으로 넓어져 무작위 분할값이 이상값 근처에 놓일 가능성이 커지고, 이상을 더 빨리 분리할 수 있다.

이어서 그림 12와 같이 이상이 고리 밖에 있어 정상 데이터와 잘 분리된 다른 분포를 시험하였다. 이상 비율은 동일하게 전체의 1%로 유지하였다. 전체 데이터에서 표본을 뽑으면 때로 이상이 포함되어 점수 히트맵에 상당한 영향을 준다. 그림의 오른쪽에서 히트맵이 변형되고 색의 변화가 커진다. 이 불확실한 영역에서는 거짓양성과 거짓음성이 모두 생길 수 있다. 이런 분포에서는 표본에 이상을 포함하는 것이 유용해 보이지 않는다.

### E. 차원 수가 IForest에 미치는 영향

데이터는 시간에 따른 둘 이상의 관측값을 기술하는 다변량 데이터인 경우가 많다. 차원 수에 따른 성능을 평가하기 위해 V-B의 2차원·3차원 합성 데이터셋을 사용하였다. 이 데이터셋의 이상은 여러 차원에 동시에 나타나므로 탐지에도 여러 차원을 고려해야 한다. 그림 13과 같이 이 경우 IForest의 효율은 낮다. 정상과 이상 사이의 밀도·거리 차이가 매우 뚜렷할 때만 이상을 탐지한다. 특히 정상 데이터의 경계에서 오경보가 많이 발생하고, 실제 이상도 다수 놓쳤다.

학습 중 노드를 분할할 때 IForest는 속성 하나를 무작위로 선택하기 때문이다. 한 번에 한 차원만 보면 이상 데이터가 정상 데이터와 같은 값 범위에 있어 정상처럼 보인다. 차원 수가 많을 때 거짓양성률도 증가한다. 따라서 차원 수는 고차원 데이터에 IForest를 적용하고 확장성을 높일 때 중요한 매개변수이다. 가능한 개선 방법은 데이터 크기와 차원 수에 따라 `ψ`를 선택하는 것이다. `m`개 차원에 나타나는 이상을 탐지하려면 적어도 깊이 `m`인 트리가 필요한데 현재의 최대 깊이는 `⌈log₂(ψ)⌉`이다. 이 식에 `m`을 직접 포함하거나 `m`과 `ψ`를 연결하도록 바꿀 수 있다.

### F. 결정 임계값의 선택

이상 탐지 방법은 보통 각 항목의 점수를 계산해 임계값과 비교함으로써 정상과 이상을 분류한다. 원 IForest 논문에서는 `s(x,n) = 2^(−E(h(x))/c(n))`의 임계값을 0.5로 제안하였다. 점수가 1에 매우 가까우면 이상이고, 0.5보다 훨씬 작으면 정상이다. 실제로는 점수가 0.5보다 클 때 이상으로 판단하지만 최적 임계값이 항상 0.5는 아니므로 오경보나 탐지 누락이 발생할 수 있다.

이를 보이기 위해 Synthetic_2와 Synthetic_3에서 전체, 정상, 이상 데이터의 점수 분포를 그림 14에 나타냈다. 점수에서 경로 길이도 구해 그 분포를 나타냈다. 정상과 이상을 쉽게 나누는 점수 또는 깊이 임계값을 찾을 수 있는지를 평가하기 위한 것이다. 빨간 세로선이 임계값이다. 정상 데이터 가운데 점수가 0.5~0.6인 것이 많아 두 데이터셋에는 0.5보다 0.6이 적합했다.

그러나 정상 데이터의 밀도가 낮은 Synthetic_2에서는 임계값 0.6을 써도 이상의 일부만 탐지되었다. 실제 이상 가운데 임계 깊이보다 경로가 길고 점수가 0.6보다 낮은 것이 있다. 반면 Synthetic_3에서는 모든 이상의 점수가 결정 임계값을 넘었다. 두 데이터셋을 비교하면 정상과 이상이 멀수록 이상의 경로가 짧아진다. 정상과 크게 다른 이상은 빠르게 격리되는 것이다. 정상과 이상 사이의 밀도 차이는 IForest의 탐지 효율에 큰 영향을 미치며 탐지 임계값을 정할 때 고려할 수 있다.

**그림 14.** Synthetic_2와 Synthetic_3에서의 IForest 점수 및 경로 길이 분포.

이 절에서는 여러 각도에서 IForest를 연구하였다. 숲의 무작위 구성과 독립적인 격리 트리는 견고한 결정을 가능하게 하는 핵심이다. 트리를 많이 사용해도 이상 탐지 능력은 크게 좋아지지 않고 실행 시간만 증가하므로 약 100개가 적절한 절충안이다. 일정 크기를 넘으면 표본 크기는 실행 시간을 늘리고 탐지 성능을 낮추므로 데이터셋 특성에 맞는 최적 표본 크기를 정해 개선할 수 있다. 정상과 이상이 트리에서 얼마나 비슷하게 나타나는지에 따라 최적 결정 임계값도 달라져 고정하기 어렵다. 다음 절에서는 실행 시간을 개선하는 확장 방법인 MVIForest를 제안한다.

## VII. Majority Voting Isolation Forest

### A. Majority Voting IForest(MVIForest) 방법

IForest는 학습 단계에서 만든 모든 트리의 집단 결정으로 이상을 식별한다. 트리 `i`는 항목 `x`의 경로 `hᵢ(x)`를 제공하며, 그 평균 경로가 점수 계산에 사용된다.

```text
s(x, n) = 2^[−((Σᵢ₌₁ᵗ hᵢ(x))/t)/c(n)]
```

따라서 점수를 얻으려면 숲의 모든 트리에서 `x`의 경로를 계산해야 한다. 이 방식을 다수결로 개선하면 효율을 유지하면서 실행 시간과 메모리 요구량을 크게 줄일 수 있다. 연구진이 제안한 MVIForest는 평균 점수를 만들지 않고 트리들의 과반수 결정이 정해지는 즉시 실행을 멈춘다. IForest와 마찬가지로 두 단계로 구성된다. 숲 구축은 II-A의 IForest와 동일하고, 점수화 단계가 다르다.

MVIForest는 전체 트리에서 경로 길이를 구해 최종 점수를 계산하는 대신 각 트리 `i`에서 `x`의 점수 `sᵢ(x,n) = 2^[−hᵢ(x)/c(n)]`를 계산한다. 이 점수를 모든 트리에 공통인 임계값과 비교해 해당 트리의 국소 결정을 내린다. 그런 다음 숲의 트리들을 순서대로 처리하여 과반수 결정이 나올 때까지 반복한다. 과반수는 `t/2 + 1`개의 트리이다. 이때 `x`의 점수화가 끝나고 최종 결정을 내린다.

표 7과 그림 15, 16은 V-B의 합성 데이터셋에서 세 방법을 실행한 결과이다. 실제 데이터셋과 달리 MVIForest의 ROC AUC는 IForest와 같거나 더 높았다. 거의 모든 경우에 EIF보다도 높았다.

IForest에서는 일부 정상 데이터의 깊이가 임계값보다 짧아 이상으로 분류되지만 EIF에서는 그렇지 않다.

그림 7(d)의 Synthetic_5는 스왐핑과 마스킹 효과를 다룰 때 IForest의 한계를 보여준다. 한 차원씩 보면 이상이 정상처럼 보여 두 부류를 나눌 수 없다. EIF는 숲 구축 방식 덕분에 스왐핑을 피하지만, IForest와 MVIForest는 한 번에 한 차원만 보므로 여러 정상 데이터를 잘못 분류한다. 또한 이상의 높은 밀도 때문에 숲에서 충분히 일찍 격리되지 않아 세 방법 모두에서 임계값보다 긴 깊이를 얻었다(그림 17).

V-B의 3차원 데이터셋에서도 같은 실험을 하였다. 어느 방법도 이상을 탐지하지 못했고 IForest와 MVIForest는 오경보만 냈다. 이는 유의미한 차원 수가 늘면 IForest와 MVIForest의 탐지 성능이 크게 떨어진다는 직관을 확인한다. 가능한 해결책은 모든 차원을 차례로 다룰 수 있도록 더 깊은 트리를 탐색하는 것이다.

## IX. 결론 및 향후 연구

IForest는 이상 탐지에 가장 적합한 방법 중 하나다. 빠르고 정확하며 군집화나 최근접 이웃 같은 기법에 비해 자원을 많이 요구하지 않는다. 본 논문에서는 격리 기반 이상 탐지 방법의 연구 현황을 살펴보았다. 대부분은 IForest의 개선 방법이며, 각각 특정 한계를 다루거나 새로운 문맥에 맞게 조정한다. 연구진은 기존 개선 방법이 다루지 않은 IForest의 약점, 특히 입력 매개변수의 선택과 데이터셋의 특성(유의미한 차원 수, 정상·이상 데이터의 밀도 등)이 미치는 영향을 강조하였다. 여러 실제·합성 데이터셋에서 IForest와 EIF를 시험해 이 약점을 보였다.

이어 결정 방식을 바꾼 개선 방법인 MVIForest(Majority Voting IForest)를 제안하였다. MVIForest는 모든 트리를 요청하지 않고 과반수 결정이 가능해지는 즉시 실행을 중단하므로 IForest보다 빠르다.

향후 연구에서는 MVIForest를 다른 이상 탐지 방법과 비교할 예정이다. 살펴본 격리 기반 방법들은 성능이 좋지만 스트리밍 문맥에는 맞지 않는다. 데이터 스트림의 격리 기반 이상 탐지는 문헌에서 충분히 연구되지 않았다. 연구진은 스트림에 맞게 조정된 IForestASD에 초점을 맞추고, 성능과 확장성을 높일 분산 버전을 제안할 예정이다.
