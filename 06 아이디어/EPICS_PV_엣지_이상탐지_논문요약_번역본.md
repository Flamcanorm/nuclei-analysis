## 전체 한국어 번역

### 초록

EPICS(Experimental Physics and Industrial Control System) 기반 분산 제어 시스템은 안전하고 신뢰할 수 있는 운영을 위해 지연이 적고 견고하게 감시해야 하는 고속 프로세스 변수(PV) 스트림을 생성한다[1, 2]. 기존의 중앙 집중형 감시 구조에는 대역폭 제한, 지연, 단일 장애점의 문제가 있을 수 있다. 본 논문은 저비용 Raspberry Pi 하드웨어에서 작동하는 EPICS PV 스트림용 엣지 배치 머신러닝 이상 탐지 시스템의 설계, 구현, 평가를 제시한다. 제안한 구조는 EPICS IOC와 경량 오토인코더 및 Isolation Forest 모델을 통합한다. 오토인코더는 TensorFlow Lite용으로 양자화되며[3], PV 윈도에 대한 지속적인 추론과 로컬 이상 PV 생성을 지원한다. EPICS 통합, 데이터 전처리, 모델 학습, 양자화, 배포의 공학적 세부사항을 설명하고, 합성 및 기록된 PV 궤적을 사용하는 실험실 테스트베드에서 평가한다. 추론 지연은 20ms 미만이고 CPU 부담은 크지 않았으며, 엣지에서 이상을 선별해 중앙 네트워크 트래픽이 크게 줄었다. 분산 IOC를 위한 운영 고려사항, 장애 형태, 적응형 연합 학습의 방향도 논의한다[12].

**주요어:** EPICS, 이상 탐지, Raspberry Pi, 엣지 컴퓨팅, 프로세스 변수, TinyML, 오토인코더, Isolation Forest, 제어 시스템.

## 1. 서론

대형 과학 시설과 산업 연구소는 실험과 장비 관리를 위해 분산 제어 시스템을 점차 더 많이 사용한다[1]. EPICS는 계측 값들을 PV로 노출하는 널리 사용되는 오픈소스 미들웨어이며, 클라이언트와 운영자 콘솔은 이를 이용한다[2]. 최신 배치에는 수천 개의 PV가 있고, 갱신 속도는 1Hz 미만에서 수 kHz까지 다양하다. 센서 드리프트, 순간 잡음, 신호 중단, 구동기 고장 등의 이상 상태를 제때 탐지해야 운영 안전성과 과학적 무결성을 지킬 수 있다.

기존에는 EPICS 레코드에 설정한 고정 임계값 경보 또는 저장된 PV 로그의 사후 분석을 사용했다[10]. 고정 임계값은 쉽게 흔들려 성가신 경보를 자주 만들고, 사후 분석은 손상이나 중단을 막기에는 너무 늦다. 중앙 실시간 탐지도 가능하지만 네트워크 부하와 시스템 복잡도를 늘리고 단일 장애점을 만든다. 엣지 컴퓨팅과 TinyML은 모델을 데이터 원천 가까이에서 실행하여 낮은 지연으로 이상을 탐지하고 중앙에는 경보나 요약만 전달할 수 있다[6, 8].

본 논문의 시스템은 경량 머신러닝 이상 탐지기를 Raspberry Pi 기반 EPICS IOC에 통합한다. 기여는 다음과 같다.

1. 표준 EPICS 인터페이스를 유지하면서 Raspberry Pi IOC에 이상 탐지를 내장하는 실제 구조.
2. 자원 제약 하드웨어에서의 모델 선택·학습·양자화 전략과 대표 PV 스트림에 대한 오토인코더와 Isolation Forest 비교[4, 5].
3. 이상 점수와 플래그를 표준 PV로 노출해 기존 운영 도구에 연결하는 `mlAnomalyRecord` 인터페이스[7].
4. 실험실 테스트베드에서 합성 장애의 탐지 정확도, 지연, CPU·메모리 부하, 네트워크 대역폭 감소를 수치로 평가한 결과.

II절은 EPICS와 관련 연구, III절은 구조, IV절은 전처리·모델·EPICS 통합, V절은 Raspberry Pi 구현, VI절은 실험 결과, VII절은 논의와 한계, VIII절은 결론과 향후 연구를 다룬다.

## 2. 배경 및 관련 연구

### 2.1. EPICS와 프로세스 변수

EPICS는 센서 측정값, 설정값, 상태 정보를 나타내는 PV를 중심으로 제어 시스템을 구성한다[2]. 입출력 제어기(IOC)는 하드웨어를 읽거나 값을 계산하는 레코드를 호스팅한다. 클라이언트는 Channel Access(CA) 또는 pvAccess를 통해 PV 갱신을 구독한다. EPICS Base는 레코드 유형, 장치 지원, 통신 스택을 제공한다. CSS나 Phoebus 같은 운영자 인터페이스는 PV와 경보를 시각화한다[1].

### 2.2. 이상 탐지 접근법

시계열 이상 탐지에는 통계, 거리 기반, 트리 앙상블(Isolation Forest 등)[4, 9], 신경망(오토인코더, LSTM 예측기 등)[5] 접근법이 있다. 오토인코더는 정상 데이터의 압축 표현을 학습하고 재구성 오차로 이상을 판별한다. Isolation Forest는 무작위 분할 트리 앙상블에서 가장 쉽게 격리되는 표본을 이상으로 본다. 엣지 배치에서는 모델 복잡도, 추론 시간, 메모리 사용량이 중요하다.

### 2.3. 엣지 머신러닝과 TinyML

엣지 머신러닝은 저전력 장치로 추론을 옮긴다. TensorFlow Lite 같은 프레임워크는 양자화된 모델을 배치하도록 지원한다[3]. 산업 IoT 연구는 엣지 분석이 네트워크 사용량을 줄이고 응답성을 높일 수 있음을 보였다[8]. 그러나 EPICS 제어 스택과 TinyML 이상 탐지의 결합은 충분히 연구되지 않았으며, EPICS 시설 대부분은 여전히 중앙 집중형 또는 레코드 기반 경보를 사용한다[6].

### 2.4. 관련 구현

일부 시설은 IOC에서 로컬 전처리나 임계값 기반 필터링을 도입했고, 컨테이너화된 EPICS 배치도 증가하고 있다[11]. 제어 시스템용 머신러닝 감시의 개념 증명은 ICALEPCS 등의 워크숍에서 보고되었으나 Raspberry Pi IOC를 대상으로 공개되고 재현 가능한 구현은 드물다. 본 연구는 처음부터 끝까지 연결한 공학적 연구와 재현 가능한 자료로 이 간극을 메우고자 한다.

## 3. 시스템 구조

그림 1의 구조는 세 계층으로 나뉜다.

1. **장치 및 EPICS 계층:** 센서와 구동기가 EPICS 지원 IOC에 연결되고, IOC의 표준 레코드가 PV를 게시한다.
2. **엣지 머신러닝 계층:** Raspberry Pi에서 IOC와 함께 실행된다. pyepics 또는 네이티브 C 클라이언트로 CA를 통해 PV를 구독하고, 데이터 윈도를 버퍼에 모아 전처리한 다음 로컬 모델로 추론한다.
3. **경보 및 원격 측정 계층:** 이상 점수가 설정 임계값을 넘으면 전용 이상 PV(예: `DEVICE:ANOMALY:FLAG`)를 갱신하고 필요하면 작은 이벤트를 중앙 제어실에 보내 시각화, 기록, 운영자 조치에 사용한다.

이상 출력도 PV로 노출되어 기존 운영 도구, 경보 데몬, 로그 서비스가 소비할 수 있다. 이는 운영 중인 제어망의 변경을 최소화하고 도입을 쉽게 한다.

## 4. 방법

이 절은 데이터 준비, 모델 선택·학습, 추론, EPICS 통합을 설명한다.

### 4.1. 데이터 수집 및 전처리

합성 및 기록된 PV 스트림을 사용했다. 통제된 실험에서는 소형 빔라인 설정의 센서인 온도계(0.1°C 해상도), 모터 엔코더 위치, 광다이오드 전류, 진공 게이지를 모사했다. PV는 10–1000Hz로 표본화했으며 Raspberry Pi 실험에서는 실제적인 IOC 갱신 간격에 맞춰 10–100Hz에 초점을 맞췄다.

- 시간을 맞추고 고정 속도의 윈도로 재표본화한다.
- 최근의 짧은 기준 기간(예: 직전 10초)에서 이동 평균과 표준편차를 추정하여 이동 윈도를 정규화한다.
- 선택적으로 저역통과 필터를 적용해 고주파 측정 잡음을 제거한다.
- 길이 `L`의 윈도(예: 50개 표본)를 모델 입력 특징 텐서로 쌓는다. 윈도 사이에 예를 들어 50% 겹침을 주면 짧은 이상에 대한 민감도가 높아진다.

### 4.2. 모델 선택 및 학습

세 가지 경량 접근법을 평가했다.

- **Isolation Forest(IF):** 빠르고 비모수적이며 메모리 요구량이 낮다. 윈도에서 추출한 평균·표준편차·최댓값·왜도 등의 특징 벡터로 학습하며 Raspberry Pi에서 최적화된 C 라이브러리를 사용하는 scikit-learn으로 실행된다[4].
- **One-Class SVM(OCSVM):** 일부 환경에서는 효과적이지만 Python 추론의 계산 부담이 더 크다.
- **오토인코더(AE):** 정상 윈도를 재구성하도록 학습한 작은 완전연결 또는 합성곱 모델이다. 이상에서는 재구성 오차가 크다[5]. TensorFlow에서 구현하고 엣지 추론을 위해 TensorFlow Lite로 양자화했다[3].

실험에서는 오토인코더가 채널 사이의 시간적 상관관계를 포착하면서 가지치기와 양자화 후에도 작게 유지되어 가장 좋은 절충안을 보였다. 단순한 신경망은 강한 압축 후 모델 크기가 200KB 미만이었다.

### 4.3. 임계값 및 경보 논리

이상 판단은 절대 재구성 오차와 기준 분포에서 동적으로 조정한 임계값을 함께 사용한다. 시스템은 점수의 평균과 분산을 지수 가중 방식으로 계속 추정하여 느린 변화에 적응한다. 오경보를 줄이기 위해 점수가 `M`개의 연속 윈도(예: 3개)에서 임계값을 넘거나 최고 오차가 더 높은 비상 임계값을 넘어야 경보를 낸다.

### 4.4. EPICS 통합

Python 기반 `mlAnomalyRecord` 인터페이스는 수치형 이상 점수, 불리언 이상 플래그, 최근 재구성 오차 이력(배열 PV), 모델 상태·버전 메타데이터(문자열 PV)를 노출한다. 엣지 머신러닝 프로세스는 pyepics로 이 레코드들을 만들고 갱신한다[7]. 운영자는 기존 EPICS 경보 처리기와 시각화 도구를 이용해 경보를 구성할 수 있다.

## 5. Raspberry Pi 구현

### 5.1. 하드웨어 및 운영체제

기준 플랫폼은 RAM 4GB의 Raspberry Pi 4 Model B이다. 소프트웨어는 Raspberry Pi OS 64비트에서 네이티브로 컴파일한 EPICS Base 7.0, Python 3.9, pyepics, TensorFlow Lite 런타임, numpy, scikit-learn으로 구성했다.

### 5.2. 모델 내보내기 및 최적화

오토인코더는 워크스테이션에서 TensorFlow 2.x로 학습했다. 배포 전에 (1) 학습 중 가지치기와 은닉층 크기 축소로 매개변수를 제한하고, (2) TensorFlow Lite 변환기로 학습 후 8비트 정수 양자화를 적용했으며, (3) 대표 PV 윈도로 정적 범위를 보정해 양자화 오차를 줄였다. 결과 모델은 Raspberry Pi CPU에서 50개 표본 윈도를 15ms 미만에 추론했다. 필요할 때 Raspberry Pi의 NEON 벡터 확장으로 속도를 더 높였다.

### 5.3. 프로세스 설계 및 견고성

엣지 프로세스는 실패 시 자동 재시작되는 관리형 `systemd` 서비스로 실행된다. 설정된 PV에 CA 구독을 열고 PV마다 내부 순환 버퍼를 유지한다. IOC에 부정적인 영향을 주지 않도록 CPU 친화성과 `nice` 수준을 설정해 과부하 시 우선순위를 낮춘다.

### 5.4. 보안 및 접근 제어

머신러닝 서비스를 제한된 사용자 계정으로 실행하고 네트워크 정책으로 EPICS 제어망 접근을 제한할 것을 권장한다[14]. PV의 인증과 권한 부여에는 시설의 기존 관행을 이용한다. 머신러닝 모듈은 제어 루프에 간섭하지 않도록 전용 이상 PV에만 기록한다.

**그림 1.** EPICS IOC가 PV를 노출하고 Raspberry Pi 엣지 노드가 이를 구독해 머신러닝 이상 탐지를 수행하며, 경보를 중앙 제어실로 보내는 시스템 구조.

## 6. 실험 평가

### 6.1. 테스트베드와 데이터셋

1. **합성 정상:** 실제적인 잡음과 운영 변동이 있는 합성 센서 데이터 100,000윈도.
2. **주입한 장애:** 단계적 드리프트, 덧붙인 스파이크, 간헐적 신호 중단, 진동을 정상 스트림에 주입한 5,000개 장애 윈도.
3. **기록 궤적:** 실험실 빔라인 PV 로그 10시간을 내보내고 EPICS IOC를 통해 50Hz로 재생.

### 6.2. 지표

이상 종류별 정밀도·재현율·F1 점수, PV 도착부터 이상 PV 갱신까지의 지연, Raspberry Pi CPU·메모리 사용률, 모든 PV를 중앙 분석기로 보내는 방식과 비교해 절약한 초당 바이트 수를 평가하였다.

### 6.3. 결과

표 1은 여러 실행의 평균값으로, 오토인코더와 Isolation Forest를 비교한다. 오토인코더는 시간 구조를 학습할 수 있어 진동과 드리프트 같은 상관된 이상에서 더 정확했다. Isolation Forest는 약간 더 빠르고 CPU 사용량이 적어 지연에 특히 민감하며 덜 복잡한 상황에 적합했다. 원시 PV 대신 이상 이벤트와 압축 요약만 상위로 보내면 두 방법 모두 중앙 네트워크 트래픽을 약 35–45% 줄였다[6].

### 6.4. 사례 연구: 모터 엔코더 드리프트

모터 엔코더 PV에 느린 드리프트를 주입했다. 오토인코더는 재구성 오차가 이동 임계값을 넘으면서 6초 안에 드리프트를 탐지했다. 반면 정상값보다 3% 높은 고정 임계값은 점진적인 편차를 훨씬 나중에 탐지했을 것이다[5]. 이는 즉각적이지 않은 미세한 이상에 학습 기반 접근법이 유리함을 보여준다.

## 7. 논의

### 7.1. 실제 운영 고려사항

- **수명주기와 모델 갱신:** 모델에 버전을 붙이고 안전한 배포 방식으로 갱신해야 한다. 카나리 시험을 동반한 점진적 갱신으로 위험을 줄일 수 있다[12].
- **거짓양성·거짓음성:** 운영자 피드백과 지도 재학습으로 시간이 지남에 따라 오류율을 줄일 수 있다. 피드백 PV로 사람이 붙인 레이블을 수집할 수 있다.
- **계산량과 탐지의 절충:** 가벼운 모델은 지연과 에너지를 줄이지만 복잡한 이상을 놓칠 수 있다. 시설은 이상 종류별 중요도와 안전 여유를 바탕으로 모델을 선택해야 한다.
- **결정성·설명 가능성:** 안전에 중요한 시스템에서는 단순한 모델이나 규칙과 머신러닝을 결합한 시스템의 해석 가능성이 더 높다[15].

### 7.2. 한계

실험은 중간 속도의 PV 스트림(10–100Hz)에 집중했다. kHz~MHz의 매우 빠른 탐지는 FPGA나 GPU 같은 전용 하드웨어가 필요하며 이 연구 범위를 벗어난다. 테스트베드에는 주입한 장애와 보관된 궤적을 사용했다. 장기간 실제 배치에서는 개념 변동, 하드웨어 노화 등 지속적인 관리가 필요한 문제가 더 나타날 수 있다.

### 7.3. 보안과 안전

머신러닝 모듈이 이상 PV에 값을 쓰므로 시설은 접근을 통제하고 머신러닝 프로세스가 뜻하지 않게 구동기를 제어하지 못하도록 해야 한다. 네트워크 격리와 서비스 권한 제한을 권장한다[14].

## 8. 결론 및 향후 연구

Raspberry Pi IOC를 사용해 EPICS PV 스트림에서 엣지 배치 머신러닝 이상 탐지를 수행하는 전체 처리 과정을 제시했다. 이 접근법은 낮은 지연으로 이상을 탐지하고 EPICS 호환성을 유지하면서 네트워크 부하를 줄이고 여러 머신러닝 모델을 지원한다. 실험은 제한된 자원에서 양자화 오토인코더와 Isolation Forest 모두 실시간 탐지에 사용할 수 있음을 보였다.

향후 연구에는 더 높은 주파수의 PV와 여러 노드의 분산 추론, 여러 IOC에서 지속적으로 적응하기 위한 연합 학습[12], 엣지 콘솔의 경량 이상 시각화 및 운영자 피드백 자동화, 안전성과 설명 가능성을 높일 규칙·머신러닝 결합 시스템[15]이 포함된다.
