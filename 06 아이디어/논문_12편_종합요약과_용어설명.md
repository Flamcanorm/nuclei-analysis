## 먼저 읽는 핵심

이 자료는 앞서 정리한 이상 탐지 논문 7편과 보안 취약점 점검·자동화 논문 5편을 함께 다룬다. 열두 편이 모두 같은 문제를 푸는 것은 아니다. 앞부분은 멀티뷰 학습, Isolation Forest 변형, 웹 로그·제어 시스템 이상 탐지를 다룬다. 새로 추가한 다섯 편은 서버 설정 진단, 코드 생성 AI를 이용한 웹 점검, 대규모 탐지 규칙 생성, 침투 테스트 절차 자동화, Nuclei YAML 템플릿 제작을 다룬다.

이상 탐지의 기본 질문은 **“대부분과 다른 데이터를 어떻게 찾을까?”**다. 데이터에 정상·이상 정답이 충분하지 않은 경우가 많아서, 정상 패턴에서 벗어남을 수치로 표현하는 *이상 점수*가 중요하다. Isolation Forest(IForest)는 데이터를 무작위로 분할하는 트리에서 **빨리 분리되는 데이터가 이상일 가능성이 높다**는 생각을 쓴다. 그러나 *빨리 분리된다*는 기준은 전역적으로 희소한 데이터에 강하며, 정상 집단 안에 숨어 있는 국소 이상이나 특정 데이터 분포에는 약할 수 있다. 또한 사용하는 트리·표본·임계값에 따라 결과가 바뀐다.

## 각 논문의 해결 과정을 차례로 이해하기

### 1. 멀티뷰 리뷰: “하나의 대상을 여러 관점으로 보기”

한 사람의 행동을 영상만으로 보면 자세는 알 수 있지만 소리나 시간적 움직임의 정보가 부족할 수 있다. **뷰(view)**는 같은 대상을 설명하는 서로 다른 특징 집합 또는 데이터 원천이다. 영상·음성, 문서 본문·저자, 웹 로그의 요청 경로·사용자 에이전트처럼 나눌 수 있다. 논문은 여러 뷰를 원자료에서 결합하는 방식, 뷰별 분류 결과를 결합하는 방식, 뷰별 표현을 배운 뒤 합치는 방식을 구분한다. 딥러닝에서는 CNN이 국소 공간 패턴, RNN이 시간 순서, RBM·오토인코더·GAN이 잠재 표현 또는 생성 관계를 학습하는 예를 보여준다. **이 리뷰만으로 특정 이상 탐지 알고리즘의 정확도가 검증된 것은 아니다.**

### 2. IForest와 MVIForest: “얼마나 빨리 떨어져 나오는가”

IForest는 여러 격리 트리(isolation tree)를 만든다. 트리의 각 노드에서 임의의 특징과 분할값을 골라 데이터를 나눈다. 남들과 동떨어진 점은 보통 적은 분할만으로 혼자 남는다. 여러 트리에서 얻은 **경로 길이**가 짧을수록 이상 점수를 높게 준다. 여기서 표본 크기 `ψ`는 트리 하나를 만들 때 뽑는 데이터 수, `t`는 트리 수, **결정 임계값**은 점수부터 이상으로 부를지의 기준이다. 논문은 세 값에 단일한 최적 답이 없음을 보인다. MVIForest는 트리를 차례로 판단해 과반수가 정해지면 남은 트리를 보지 않는다. 따라서 주로 **추론 절차의 시간**을 줄인다. EIF는 분할 방향을 바꿔 축 평행 분할의 인공적인 영역을 줄이는 별도의 방법이다.

### 3. EPICS 엣지 논문: “이상 판단을 센서 가까이에서”

**PV(Process Variable)**는 온도, 모터 위치처럼 제어 시스템에서 이름을 붙여 공개하는 값이다. **IOC(Input/Output Controller)**는 장치값을 읽고 PV를 제공하는 제어기다. 이 논문은 PV 여러 개의 최근 측정치를 **슬라이딩 윈도**로 모아 엣지에서 판단한다. 오토인코더는 정상 윈도를 재구성해 복원 오차가 큰 경우 경보를 낸다. IF는 윈도에서 평균·표준편차·최댓값·왜도 같은 특징을 뽑아 격리 용이성을 본다. **양자화**는 신경망의 수치를 작은 정수 표현으로 바꿔 저장 공간과 계산 부담을 낮춘다. 결과를 새로운 경보 PV로 내보내므로 기존 EPICS 화면과 경보 도구가 그대로 받을 수 있다. 이 연구의 대상은 10–100Hz의 중간 속도 스트림과 실험실 테스트베드이며, 초고속 장기 운영 성능까지 검증한 것은 아니다.

### 4. 웹 트래픽 논문: “로그를 모델이 읽을 수 있는 수치로”

웹 로그에는 요청 방식, URI, 상태 코드, 전송 바이트, 사용자 에이전트 같은 문자열과 숫자가 섞여 있다. 이 연구는 결측 행을 제거하고 범주형 값을 **원핫 인코딩**하며 수치값을 **표준화**했다. URI 발생 횟수, 침해 지표(IOC) 발생 횟수, 사용자 에이전트 발생 횟수, URI 길이 같은 파생 특징을 추가했다. IForest 학습은 비지도이지만 시험 결과는 사람이 붙인 정상·이상 레이블과 비교했다. 따라서 **비지도 학습**과 **레이블을 사용한 평가**를 구분해야 한다. 보고된 수치는 그 웹 로그와 처리 절차에서 얻은 것으로 다른 네트워크에 그대로 보장되지 않는다.

### 5. ABIForest: “트리마다 다른 신뢰도 부여”

일반 IForest는 트리 경로를 평균낸다. ABIForest는 각 항목을 판별할 때 더 유용한 트리 경로에 큰 **어텐션 가중치**를 준다. **Nadaraya–Watson 회귀**는 유사한 관측치에 높은 가중치를 주어 값을 추정하는 커널 방법이다. 이 논문은 이를 어텐션 형태로 이용한다. **Huber 오염 모형**은 데이터의 일부가 정상 분포와 다른 오염 성분이라고 가정한다. 가중치의 학습은 신경망의 역전파가 아니라 선형 또는 이차 최적화로 풀 수 있다. 다만 최적화 기준을 만들 정상·이상 레이블이 필요하고, 오염 비율 등 추가 매개변수도 조정해야 한다. 그러므로 레이블 없는 IF를 그대로 대체하는 방식으로 생각하면 안 된다.

### 6. X-iForest: “첫 후보를 다시 걸러 내기”

네트워크에서 실제 이상 비율을 모르는데 IF의 `contamination` 비율을 잘못 지정하면 성능이 흔들릴 수 있다. X-iForest는 IF의 탐지 결과에서 정상 군집 중심과 의심 지점 사이의 표준 유클리드 거리를 보고 **X-means** 군집화로 다시 선별한다. X-means는 k-means의 군집 수를 미리 고정하기 어려울 때 군집 수를 탐색하는 확장이다. 여기서 **2차 선별**은 IF가 표시한 후보를 그대로 확정하지 않고 군집 구조를 이용해 점검하는 단계다. 이 논문의 높은 ADR은 평가에 사용한 8개 데이터셋과 비교 방법의 조건에서 얻은 결과다.

### 7. ISER: “초구의 크기로 국소 밀도를 표현하기”

**초구(hypersphere)**는 2차원에서는 원, 3차원에서는 구, 그 이상의 차원에서는 같은 거리 조건으로 정의되는 영역이다. 무작위로 고른 중심에서 가장 가까운 이웃까지의 거리를 반지름으로 삼으면, 빽빽한 곳에서는 반지름이 작고 성긴 곳에서는 크다. ISER는 이 반지름을 **국소 밀도의 단조 변환**으로 해석한다. 여러 번 만든 초구 앙상블에서 데이터가 어떻게 덮이는지를 표현하고, 평균 기반 또는 이론적 이상 참조 패턴과의 **유사도 기반 점수**로 이상을 찾는다. 국소 이상은 전체에서는 흔해 보여도 자신의 주변 집단과 비교하면 다를 수 있다. ISER는 이런 차이를 포착하려 한다. 논문은 데이터 크기 `n`에 대해 선형 시간과 일정한 공간 요구량을 주장하며, ISER 표현을 IForest에 결합한 ISER-IF도 평가한다.

### 8. 보안 취약점 진단 자동화: “반복 점검을 같은 절차로 실행하기”

이 연구는 서버의 보안 설정을 사람이 항목마다 확인하는 작업을 자동화한다. 사용자가 `Settings.ini`에서 환경을 정하면 Java 프로그램이 운영체제에 맞는 셸 스크립트를 실행하고, 결과를 모아 판정과 CSV 보고서를 만든다. 한국어 본문은 서버 한 대 점검이 약 20분에서 3분으로 줄었다고 설명하지만 영어 초록에는 10초와 120배라는 다른 수치가 있어 그대로 합쳐 해석하면 안 된다. 또한 CentOS 6·7 중심의 제한된 환경이며, 모든 진단 규칙의 정확도나 오탐을 충분히 검증한 연구는 아니다.

### 9. 코드 생성 AI 웹 점검: “검사 코드를 초안으로 만들기”

Cursor와 Continue 같은 코드 생성 도구에 점검 목적을 설명하고 Selenium 코드를 생성하게 한다. Selenium은 실제 브라우저를 자동으로 조작해 입력·클릭·응답 확인을 반복하는 도구다. 생성된 코드는 바로 정답으로 쓰지 않고 보안 전문가가 오류와 검사 논리를 확인한 뒤 실행해야 한다. 논문은 약 40%의 시간 단축을 보고하지만 제한된 실험 사례의 결과이며, 코드가 실행된다는 사실만으로 취약점을 정확히 판정한다는 뜻은 아니다.

### 10. RuleForge: “Nuclei 지식을 탐지 규칙으로 바꾸고 여러 단계로 검증하기”

RuleForge는 공개된 Nuclei YAML 템플릿을 취약점 지식의 입력으로 사용한다. LLM이 CVE별 JSON 탐지 규칙 후보 다섯 개를 만들고, 후보마다 합성 악성·정상 HTTP 요청으로 시험하며 최대 다섯 번 수정한다. 그 뒤 LLM 평가, 실제 트래픽 일치 결과, IP 평판, 보안 엔지니어 검토를 거친다. 100개 생성 예에 대한 LLM 평가에서는 AUROC 0.75와 ECE 0.17을 보고했다. 같은 Claude 계열이 생성과 평가에 쓰였고 전문가 설명 비교가 9건뿐이라는 한계가 있다.

### 11. EzPentest: “여러 점검 도구를 하나의 순서도로 묶기”

EzPentest의 YAML은 공격 방법 자체보다 **어떤 도구를 어떤 순서와 조건으로 실행할지**를 적는 워크플로다. Nmap, Nikto, Nuclei, SQLmap 등의 출력을 JSON으로 통일하고 SQLite에 저장해 화면에서 결과와 흐름을 보여준다. 조건 분기, 반복, 병렬 실행을 지원하며 기본 동시 작업 수는 네 개다. 세 시험용 취약 웹 앱에서 평균 F1 85.97%를 보고했지만, AIPenTool보다 실행 시간이 길었던 비교도 있으므로 자동화가 항상 더 빠르다는 결론은 아니다.

### 12. Nuclei 사용자 정의 템플릿: “찾으려는 노출 조건을 규칙으로 적기”

Nuclei 템플릿에는 요청할 주소와 방식, 응답에서 찾을 문자열·상태·패턴, 심각도 같은 정보를 YAML로 적는다. 연구는 Subversion의 `wc.db`, `WS_FTP.LOG`, 외부에 보이는 관리자 로그인 화면을 찾는 템플릿을 만들었다. 67개 대상에서 각각 4개, 2개, 2개의 일치를 보고했다. 논문은 오탐이 없다는 취지와 제로데이 대응 가능성을 주장하지만, 독립적인 정답 자료와 오탐률 계산 또는 실제 제로데이 발견 실험은 제시하지 않는다.

## 처음 읽는 사람을 위한 용어 설명

이 절은 앞의 열두 편에 나온 말을 **데이터 → 학습 방법 → 알고리즘 → 결과 평가 → 실제 장비** 순서로 설명한다. 영어는 가능한 한 풀어 쓰고, 같은 말이 논문마다 조금 다르게 쓰이면 그 차이도 적었다. 수식이 어렵다면 먼저 각 항목의 **예시**만 읽어도 된다.

### 1. 인공지능과 데이터의 가장 기본적인 말

| 용어 | 쉬운 뜻과 예시 |
|---|---|
| 인공지능(AI, Artificial Intelligence) | 사람이 하던 판단·예측 같은 작업을 컴퓨터가 하도록 만드는 넓은 분야다. 이 자료의 이상 탐지는 그중 하나다. |
| 기계학습(ML, Machine Learning) | 사람이 모든 판단 규칙을 하나씩 적는 대신, 데이터에서 규칙을 배우게 하는 방법이다. “온도가 80도 넘으면 고장”이라는 고정 규칙과 달리, 여러 정상·이상 사례의 패턴을 학습한다. |
| 딥러닝(Deep Learning) | 여러 층으로 된 신경망을 사용한 기계학습의 한 갈래다. CNN·RNN·오토인코더·GAN이 여기에 속한다. 모든 기계학습이 딥러닝은 아니다. Isolation Forest는 딥러닝이 아니다. |
| 데이터, 데이터셋(dataset) | 분석할 기록과 그 모음이다. 웹 접속 기록 1건은 데이터 한 건이고, 수십만 건을 모은 파일이 데이터셋이다. |
| 관측값·표본(sample) | 데이터셋의 한 행 또는 한 대상이다. 환자 한 명, 웹 요청 한 건, 센서의 최근 10초 구간 하나가 표본이 될 수 있다. 논문에서 `n`은 흔히 전체 표본 수다. |
| 특징(feature), 변수 | 표본을 설명하는 한 가지 값이다. 웹 요청의 길이·전송량, 환자의 나이, 센서 온도가 특징이다. 특징이 6개면 “6차원 데이터”라고도 한다. |
| 차원(dimension) | 한 표본을 나타내는 숫자의 개수다. 특징이 50개이면 50차원이다. 차원이 높으면 단순한 거리 비교가 어려워질 수 있다. |
| 레이블(label), 정답 | “정상”, “이상”처럼 표본에 붙인 정답 표시다. 사람의 판정이나 이미 확인된 사고 기록에서 얻기도 한다. 레이블이 틀리거나 기준이 모호할 수도 있다. |
| 모델(model), 모형 | 데이터에서 배운 판단 방식이다. 입력 특징을 받아 이상 점수나 정상·이상 판단을 출력한다. 신경망만 모델인 것은 아니다. |
| 학습(training) | 데이터로 모델의 규칙이나 구조를 만드는 단계다. Isolation Forest는 이때 여러 트리를 만들고, 신경망은 내부 숫자인 가중치를 조정한다. |
| 추론(inference), 예측 | 이미 만들어진 모델에 새로운 표본을 넣어 결과를 얻는 단계다. “학습 시간이 짧다”와 “새 데이터 판단이 빠르다”는 다른 주장이다. |
| 훈련·시험 자료 | 훈련 자료는 모델을 만드는 데, 시험 자료는 그 모델이 새 자료에서도 잘 작동하는지 확인하는 데 쓴다. 같은 자료로 배우고 평가하면 실력보다 결과가 좋아 보일 수 있다. |
| 지도 학습(supervised learning) | 정답 레이블을 보면서 배운다. ABIForest의 가중치 학습이 해당한다. |
| 비지도 학습(unsupervised learning) | 학습할 때 정상·이상 정답을 사용하지 않는다. 기본 Isolation Forest, X-iForest, ISER가 이 방향이다. 성능을 **평가할 때** 정답을 비교하는 것은 가능하다. |
| 과적합(overfitting) | 훈련 자료의 세세한 우연까지 외워 새 자료에서는 성능이 떨어지는 현상이다. |

**한 줄 예시:** 웹 요청 한 건을 `[요청 길이=40, 전송량=500, 응답코드=404]`처럼 숫자로 나타내면 그 한 줄이 **표본**, 각 값이 **특징**, “공격/정상” 표시가 **레이블**이다. 이 줄들을 보고 규칙을 만드는 것이 **학습**, 새 요청을 판단하는 것이 **추론**이다.

### 2. CNN·RNN·RBM·오토인코더·GAN은 무엇인가

멀티뷰 리뷰에 여러 신경망 이름이 나온다. **신경망**은 입력값을 여러 계산층에 통과시키면서 층 사이의 연결 강도인 **가중치(weight)**를 조정하는 모델이다. 사람의 뇌를 그대로 복사했다는 뜻은 아니다. **층(layer)**은 계산의 한 단계, **출력(output)**은 최종 결과다.

| 이름과 영어 원문                                              | 무엇을 하는가                                                                      | 쉬운 예시와 이 자료에서의 역할                                                                               |
| ------------------------------------------------------ | ---------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------- |
| **CNN** — *Convolutional Neural Network*, 합성곱 신경망      | 작은 구역을 훑으며 반복되는 모양을 찾는다. 이 작은 탐색 규칙을 **필터(filter)** 또는 **커널(kernel)**이라 부른다. | 사진에서 가장자리·눈·얼굴처럼 공간적으로 가까운 부분의 패턴을 차례로 찾는다. 멀티뷰 연구에서는 영상이나 이미지 뷰를 이해하는 도구로 등장한다.                |
| **RNN** — *Recurrent Neural Network*, 순환 신경망           | 입력을 시간 순서대로 읽고 앞에서 읽은 내용을 **상태(state)**에 담아 다음 계산에 사용한다.                     | “1초 전 온도 → 지금 온도”의 흐름, 음성이나 문장의 순서를 다룬다. 시간에 따른 센서 변화처럼 순서가 중요한 뷰에 쓰인다.                         |
| **LSTM/GRU**                                           | 긴 순서에서 이전 정보를 더 잘 유지하도록 만든 RNN의 변형이다.                                        | 오래전의 센서 변화가 현재 판단에 영향을 줄 때 쓰일 수 있다. 이름을 외우기보다 **순서 자료를 처리하는 RNN 계열**로 이해하면 된다.                  |
| **RBM** — *Restricted Boltzmann Machine*, 제한 볼츠만 기계    | 입력의 조합 패턴을 확률적으로 배우는 초기 신경망 모델이다.                                            | 여러 특징이 함께 나타나는 양상을 배워 새 표현을 만들 때 사용됐다. 오늘날 모든 딥러닝의 필수 단계라는 뜻은 아니다.                              |
| **오토인코더(AE)** — *Autoencoder*, 자기부호화기                  | 입력을 작은 내부 표현으로 **압축(encoder)**했다가 다시 **복원(decoder)**하도록 배운다.                 | 정상 센서값만 잘 복원하도록 배우면, 처음 보는 이상한 값은 원래와 다르게 복원될 수 있다. 이 차이가 **복원 오차**이고 EPICS 논문은 이를 이상 판단에 사용한다. |
| **GAN** — *Generative Adversarial Network*, 생성적 적대 신경망 | 가짜 데이터를 만드는 **생성기**와 진짜·가짜를 가리는 **판별기**를 경쟁시키며 학습한다.                         | 실제 사진과 비슷한 이미지를 만들거나 자료 분포를 배우는 데 쓰인다. 멀티뷰 리뷰에서 다루는 모델 계열이며, 여기의 모든 이상 탐지 논문이 GAN을 쓴다는 뜻은 아니다.  |

**CNN과 RNN의 차이:** 사진처럼 “어디에 무엇이 있나”가 중요하면 CNN이 자주 쓰이고, 말·영상·센서의 시간 흐름처럼 “어떤 순서로 나타났나”가 중요하면 RNN 계열이 자주 쓰인다. 둘을 결합해 영상의 각 장면을 CNN으로 읽고 장면의 순서를 RNN으로 읽는 방법도 있다.

**잠재 표현(latent representation)**은 원래 데이터를 모델이 다루기 쉬운 숫자 묶음으로 바꾼 것이다. 오토인코더의 압축 결과가 예다. **표현 학습**은 이런 숫자 묶음을 데이터에서 배우는 일이다. **멀티뷰 융합(fusion)**은 영상·소리처럼 서로 다른 뷰의 정보를 합치는 일이다. 원자료를 먼저 합칠 수도 있고, 각 뷰의 모델 결과를 마지막에 합칠 수도 있다. 멀티뷰 리뷰는 이런 방법을 정리한 논문이다.

### 3. Isolation Forest 계열을 읽는 데 필요한 말

| 용어 | 쉬운 설명 |
|---|---|
| **Isolation Forest, IForest, IF** — 격리 숲 | 표본을 무작위로 계속 나누는 **트리(tree, 나무 모양의 분기 규칙)**를 여러 개 만든다. 다른 점에서 빨리 떨어져 혼자 남는 표본을 이상하게 본다. “숲”은 트리를 여러 개 모았다는 뜻이다. |
| 노드(node), 가지(branch), 잎(leaf) | 노드는 트리의 질문 지점, 가지는 질문의 답에 따라 내려가는 길, 잎은 더 나누지 않은 끝이다. 예: “온도<30?”이라는 질문이 노드다. |
| 분할(split), 축 평행 분할 | 한 특징의 값을 기준으로 자료를 둘로 나눈다. 온도 30을 기준으로 나누면 온도축에 평행한 기준선을 쓴 셈이다. 이런 분할만 반복하면 실제로는 둥글거나 굽은 분포에서 네모난 인공 패턴이 생길 수 있다. |
| 경로 길이(path length) | 트리 맨 위에서 표본이 들어간 잎까지 거친 분할 횟수다. IF에서는 대체로 짧을수록 더 이상하다고 본다. |
| 이상 점수(anomaly score) | “얼마나 이상해 보이는가”를 나타내는 숫자다. 모델에 따라 값의 범위와 큰 값의 뜻이 다르므로 해당 논문의 정의를 확인해야 한다. |
| 앙상블(ensemble) | 여러 모델 또는 여러 번의 무작위 분할 결과를 합치는 방식이다. 트리 하나의 우연한 결과를 줄이려고 IF는 여러 트리를 사용한다. |
| 다수결(majority vote) | 여러 트리의 정상·이상 표 가운데 많은 쪽으로 결정한다. MVIForest는 남은 표가 결과를 뒤집을 수 없게 되면 평가를 일찍 끝낸다. |
| 표본 크기 `ψ`, 트리 수 `t` | `ψ`는 한 트리를 만들 때 뽑는 표본 수, `t`는 트리 개수다. ISER에서는 `ψ`가 한 초구 분할의 중심 개수, `t`가 분할을 반복한 횟수로 쓰인다. 글자를 같게 썼다고 두 방법의 세부 절차가 같지는 않다. |
| **EIF** — *Extended Isolation Forest* | 축에 평행한 선만 쓰는 한계를 줄이려고 다양한 방향의 분할을 사용하는 격리 숲 변형이다. |
| **MVIForest** — *Majority Voting Isolation Forest* | 여러 트리의 표를 세다가 다수결이 확정되면 남은 트리를 생략하는 방법이다. 앞의 “MV”는 여기서 **Majority Voting(다수결)**이지, 멀티뷰의 “multi-view”가 아니다. |
| **ABIForest** — *Attention-Based Isolation Forest* | 트리마다 똑같이 취급하는 대신 해당 표본에 유용한 트리의 영향력을 다르게 주는 방식이다. **어텐션(attention)**은 이 영향력·중요도를 계산한다는 뜻이며 사람의 주의와 완전히 같은 개념은 아니다. |
| **X-iForest** | IF가 표시한 이상 후보를 X-means 군집화로 한 번 더 검사하는 방법이다. |
| **ISER** — *Isolation-based Spherical Ensemble Representations* | 초구로 공간을 여러 번 나누고 각 표본이 덮이는 방식과 초구 크기를 숫자 묶음으로 나타내는 방법이다. |
| **ISER-IF** | 원래 특징 대신 ISER가 만든 표현을 IF에 넣는 결합 방식이다. 이 표현 공간에서는 긴 경로가 이상을 뜻할 수 있어 점수 계산을 조정한다. |

**국소 이상과 전역 이상:** 전체에서 아주 멀리 떨어진 점은 **전역 이상**이다. 예를 들어 대부분의 센서가 20∼30도인데 하나가 300도라면 눈에 띈다. **국소 이상**은 전체 범위에서는 평범해 보여도 자신의 비슷한 집단과 비교하면 다르다. 예를 들어 낮에는 30도가 흔하지만 밤에는 15도만 나오는 장치가 밤에 30도를 기록했다면, 전체 온도 범위만 보고는 놓칠 수 있다.

### 4. 군집·거리·확률을 읽는 데 필요한 말

| 용어 | 쉬운 설명 |
|---|---|
| 군집(cluster), 군집화(clustering) | 서로 비슷한 표본을 한 무리로 묶는 일이다. 정답 레이블 없이 묶을 수 있으며, 무리가 곧 정상·이상이라는 뜻은 아니다. |
| 중심(centroid) | 군집의 대표 위치다. 각 특징값의 평균으로 구할 수 있다. |
| **k-means** | 몇 개의 군집으로 나눌지 `k`를 먼저 정하고, 중심을 옮기며 가까운 표본끼리 묶는 방법이다. |
| **X-means** | k-means를 확장해 군집 수 후보를 비교하며 적절한 개수를 찾는다. X-iForest는 의심 지점의 거리들을 나눌 때 사용한다. |
| 거리(distance), 유클리드 거리 | 두 숫자 묶음이 얼마나 떨어졌는지 잰 값이다. 지도에서 두 점 사이의 직선거리를 떠올리면 된다. 여러 특징의 차이를 함께 계산한다. |
| 표준화(standardization), 표준 유클리드 거리 | 온도는 수십, 전송량은 수백만처럼 단위가 다르면 큰 숫자 쪽이 거리를 지배한다. 각 특징의 퍼짐 정도로 나누어 비교 가능하게 만드는 방식이다. |
| 최근접 이웃(nearest neighbor) | 특정 점에서 거리가 가장 가까운 다른 점이다. ISER는 이웃까지의 거리를 초구 반지름으로 쓴다. |
| 밀도(density), 성긴 곳·조밀한 곳 | 일정한 공간 안에 점이 얼마나 많은지다. 점이 빽빽하면 조밀하고 적으면 성기다. 성긴 곳의 점이 모두 이상인 것은 아니다. |
| 초구(hypersphere), 반지름(radius) | 2차원에서는 원 안, 3차원에서는 구 안과 같은 거리 기준 영역이다. 차원이 높아도 같은 규칙으로 정의한다. ISER는 작은 반지름을 조밀한 영역의 단서로 본다. |
| 분포(distribution) | 값들이 어디에 얼마나 자주 나타나는지를 나타낸다. “대부분 20∼30도, 일부 50도” 같은 모습이다. |
| 평균(mean), 분산(variance), 표준편차(standard deviation) | 평균은 대표값, 분산과 표준편차는 값이 평균에서 얼마나 퍼졌는지를 나타낸다. 표준편차는 원래 값과 같은 단위로 표현된다. |
| 왜도(skewness) | 분포가 한쪽으로 얼마나 치우쳤는지다. 평소 작은 웹 전송량이 많고 드물게 큰 전송량이 있는 경우를 생각하면 된다. |
| 공분산(covariance) | 두 특징이 함께 커지거나 작아지는 경향을 재는 값이다. 두 센서가 함께 오르는지 등을 살핀다. |
| 정규분포(Gaussian distribution) | 가운데 값이 흔하고 양끝으로 갈수록 드문 종 모양의 확률 분포다. 모든 실제 데이터가 정규분포를 따른다는 뜻은 아니다. X-iForest 논문은 실험용 가상 데이터를 만들 때 사용했다. |
| 단조 변환(monotonic transformation) | 원래 값의 크고 작은 순서를 뒤집지 않는 변환이다. ISER에서는 조밀한 곳일수록 초구 반지름이 작다는 순서 관계가 핵심이다. |
| **PCA** — *Principal Component Analysis*, 주성분 분석 | 여러 특징을 정보 손실을 가능한 한 줄이며 적은 수의 새 축으로 요약한다. X-iForest 논문은 높은 차원의 군집 결과를 2차원 그림으로 볼 때도 쓴다. |
| **LOF** — *Local Outlier Factor* | 주변 이웃과 비교해 자기 주변이 얼마나 성긴지를 보는 국소 이상 탐지 방법이다. |
| **k-NN/KNN** — *k-Nearest Neighbors* | 가장 가까운 `k`개 이웃을 찾는 방법 또는 그 거리를 이용한 이상 탐지 방법이다. `k`는 이웃의 수다. |
| **HBOS** — *Histogram-Based Outlier Score* | 특징값별로 구간의 빈도를 세어 드문 구간의 값을 이상하게 보는 방법이다. |
| **CBLOF** — *Cluster-Based Local Outlier Factor* | 군집의 크기와 군집에서의 떨어짐을 이용해 이상을 점수화한다. |
| **ECOD/COPOD** | 각 특징의 확률 분포에서 드문 값을 이용하는 이상 탐지 기준 방법들이다. 이 자료에서는 ISER를 비교할 상대 방법으로 등장한다. |

**어텐션 가중치, 커널 회귀, 최적화:** **가중치**는 “이 정보에 얼마나 힘을 실을까”를 나타내는 숫자다. ABIForest의 **Nadaraya–Watson 회귀**는 가까운 사례일수록 더 큰 가중치를 주어 결과를 추정하는 **커널(kernel) 회귀** 방식이다. 여기서 커널은 “얼마나 비슷한가”를 숫자로 계산하는 규칙이며, CNN의 이미지 필터를 뜻하는 커널과 용법이 다르다. **최적화(optimization)**는 정해 놓은 오류나 비용이 가장 작아지는 가중치를 찾는 일이다. **선형·이차 최적화**는 그 비용식을 일차식 또는 이차식 형태로 풀 수 있다는 뜻이다. **Huber 오염 모형**은 자료의 대부분은 기준 분포에서, 일부는 다른 분포에서 왔다고 가정한다. “오염”은 데이터가 물리적으로 더럽다는 뜻이 아니라 기본 패턴을 벗어난 일부를 가리킨다.

### 5. 웹 로그와 제어 장비에 나오는 말

| 용어 | 쉬운 설명 |
|---|---|
| 웹 로그(log), 트래픽(traffic) | 로그는 컴퓨터가 남긴 사건 기록, 트래픽은 네트워크를 오가는 요청과 데이터의 흐름이다. |
| **URI** — *Uniform Resource Identifier* | 웹에서 자원을 가리키는 식별 문자열이다. 요청한 경로의 길이나 빈도를 특징으로 쓸 수 있다. |
| HTTP 상태 코드 | 웹 요청 처리 결과를 나타내는 숫자다. 예를 들어 200은 보통 성공, 404는 찾지 못함을 뜻한다. |
| 사용자 에이전트(user agent) | 요청을 보낸 브라우저나 프로그램이 자신을 소개하는 문자열이다. 거짓으로 꾸밀 수도 있으므로 그 자체가 신원 증명은 아니다. |
| 결측값(missing value) | 기록되지 않아 비어 있는 값이다. 없애거나 알맞은 값으로 채우는 처리가 필요할 수 있다. |
| 범주형 값·원핫 인코딩(one-hot encoding) | “Chrome/Firefox”처럼 이름으로 된 값을 숫자로 바꾸는 방법이다. 각 이름마다 0/1 칸을 만들어 해당하는 칸만 1로 표시한다. |
| 파생 특징(derived feature) | 원래 기록을 계산해 새로 만든 특징이다. URI 문자열 길이, 최근 1분간 같은 주소의 요청 수 등이 예다. |
| 침해 지표(**IOC**, *Indicator of Compromise*) | 보안에서 공격 흔적을 가리키는 말이다. 수상한 주소·파일 해시·도메인 등이 예다. 아래 EPICS의 IOC와 약어가 같지만 뜻은 전혀 다르다. |
| **EPICS** — *Experimental Physics and Industrial Control System* | 실험·산업 장치를 연결하고 제어할 때 쓰는 소프트웨어 체계다. |
| 공정 변수(**PV**, *Process Variable*) | EPICS에서 이름을 붙여 읽거나 쓰는 값이다. 센서 온도, 모터 위치, 경보 상태 등이 될 수 있다. |
| 입출력 제어기(**IOC**, *Input/Output Controller*) | EPICS에서 장치와 통신하고 PV를 제공하는 제어기다. **보안 IOC(침해 지표)**와 구별해야 한다. |
| **엣지(edge)**, 엣지 컴퓨팅 | 모든 원자료를 중앙 서버에 보내기 전에 센서·기계 가까운 컴퓨터에서 처리하는 방식이다. 전송량과 판단 지연을 줄일 수 있다. |
| Raspberry Pi | 센서 옆에서 간단한 프로그램을 실행할 수 있는 작은 컴퓨터다. EPICS 논문의 엣지 장치로 쓰였다. |
| 슬라이딩 윈도(sliding window) | 이어지는 자료에서 최근 일정 구간을 계속 잘라 보는 방법이다. 예: 최근 10초를 분석하고 1초 뒤 다시 최근 10초를 분석한다. |
| Hz(헤르츠), ms(밀리초) | Hz는 1초당 횟수다. 10Hz면 1초에 10번 측정한다. `1 ms`는 1초의 1,000분의 1이다. |
| 지연(latency), 처리량(throughput) | 지연은 한 건이 결과를 얻기까지 걸린 시간, 처리량은 일정 시간 동안 처리한 건수다. 둘은 같은 수치가 아니다. |
| 스트림(stream), 실시간 처리 | 자료가 한 번에 파일로 오기보다 계속 흘러들어오는 상황과 그때의 처리다. |
| 양자화(quantization) | 신경망 내부의 숫자를 더 작은 정밀도로 표현해 메모리와 계산량을 줄이는 기술이다. 그 과정에서 결과가 조금 달라질 수 있다. |


### 6. 보안 점검과 자동화에 나오는 말

| 용어 | 쉬운 설명 |
|---|---|
| 취약점(vulnerability) | 공격자가 보안에 나쁜 영향을 주는 데 이용할 수 있는 설계·구현·설정상의 약점이다. 단순히 화면이나 파일이 보인다는 사실과 실제 악용 가능한 취약점은 구분해야 한다. |
| 취약점 진단·스캐닝 | 시스템에 정해진 검사 항목을 적용해 약점 후보를 찾는 과정이다. 결과에는 사람이 확인해야 할 후보가 포함될 수 있다. |
| 침투 테스트(penetration testing) | 허가된 범위에서 실제 공격자의 절차를 모방해 취약점과 영향을 확인하는 보안 시험이다. 자동 스캔은 그중 일부 단계다. |
| Nuclei | YAML 템플릿에 적힌 요청과 일치 조건을 여러 대상에 적용하는 오픈 소스 보안 검사 도구다. |
| YAML | 들여쓰기와 `이름: 값` 형태로 설정을 읽기 쉽게 적는 문서 형식이다. Nuclei에서는 검사 규칙, EzPentest에서는 도구 실행 흐름을 표현한다. |
| 템플릿(template) | 반복할 검사 규칙의 틀이다. 요청 대상, 일치 조건, 심각도 등이 들어갈 수 있다. 템플릿 일치는 최종 취약점 확정과 같지 않다. |
| 셸 스크립트(shell script) | 운영체제 명령을 순서대로 실행하도록 적은 파일이다. 서버 설정과 권한을 반복 점검할 때 사용한다. |
| CSV | 값을 쉼표로 나눈 표 형식의 텍스트 파일이다. 엑셀 같은 프로그램에서 열어 결과표로 사용할 수 있다. |
| Selenium | Chrome 같은 웹 브라우저의 입력·클릭·화면 이동을 코드로 자동화하는 도구다. |
| 코드 생성 AI | 사람이 자연어로 요구를 설명하면 프로그램 코드 초안을 만드는 AI 도구다. 생성 코드는 틀리거나 안전하지 않을 수 있어 검토와 시험이 필요하다. |
| LLM | *Large Language Model*, 대규모 언어 모델. 많은 텍스트와 코드를 학습해 문장이나 코드를 생성하는 모델이다. RuleForge는 탐지 규칙 후보 생성과 평가에 사용한다. |
| 프롬프트(prompt) | LLM에 주는 질문, 지시, 입력 자료다. 표현과 제공한 맥락에 따라 결과가 달라질 수 있다. |
| CVE | 공개된 보안 취약점에 붙이는 공통 식별 번호다. 같은 취약점을 서로 다른 도구와 기관에서 같은 번호로 가리킬 수 있다. |
| 탐지 규칙(detection rule) | 로그나 요청이 특정 공격 패턴에 해당하는지 판단하는 조건이다. 취약한 서버를 직접 고치는 규칙은 아니다. |
| HTTP 요청 | 웹 클라이언트가 서버에 보내는 요청이다. 주소, 방식, 머리글, 본문 등이 포함될 수 있다. |
| JSON | 이름과 값을 구조적으로 적는 데이터 형식이다. EzPentest는 여러 도구의 서로 다른 결과를 JSON 형태로 통일한다. |
| IP 주소·IP 평판 | IP 주소는 네트워크 장치를 식별하는 번호이고, 평판은 과거 악성 활동 기록 등을 바탕으로 위험 가능성을 평가한 정보다. 평판만으로 공격자를 확정할 수는 없다. |
| 워크플로(workflow) | 여러 작업의 실행 순서, 조건, 반복, 병렬 처리를 정한 흐름이다. |
| 병렬 실행 | 서로 독립적인 작업을 같은 시간대에 함께 처리하는 방식이다. 빠를 수 있지만 장비와 네트워크 부하도 커질 수 있다. |
| Nmap·Nikto·SQLmap | 각각 네트워크 서비스 확인, 웹 서버 점검, SQL 주입 점검에 주로 쓰이는 도구다. 허가된 대상에서 사용해야 한다. |
| 공격 표면(attack surface) | 외부 사용자가 접근하거나 공격에 이용할 가능성이 있는 시스템의 모든 지점이다. 열린 서비스, 공개 파일, 관리 화면 등이 포함된다. |
| 제로데이(zero-day) | 제작자가 고칠 시간이 거의 없었거나 패치가 준비되기 전에 알려지거나 악용되는 취약점을 가리킨다. 사용자 정의 템플릿을 만들 수 있다는 사실만으로 제로데이 탐지가 검증되는 것은 아니다. |
| AUROC | 점수가 양성과 음성의 순서를 얼마나 잘 구분하는지 여러 임계값에서 요약한 값이다. 1에 가까울수록 구분이 좋고 0.5 부근은 무작위 수준이다. |
| ECE | 모델이 말한 확신도와 실제 정답 비율의 차이를 요약한 보정 오차다. 일반적으로 낮을수록 확신도가 실제 정확도와 잘 맞는다. |

### 6. 성능 숫자 읽는 법

평가에서는 실제 정답과 모델 판단을 비교한다. **양성(positive)**은 여기서는 “이상”, **음성(negative)**은 “정상”으로 정한다. 아래 네 칸의 약어를 알면 정밀도·재현율을 읽을 수 있다.

| 실제 / 모델 판단 | 이상이라고 판단 | 정상이라고 판단 |
|---|---|---|
| 실제 이상 | **TP** (*True Positive*, 맞게 탐지) | **FN** (*False Negative*, 이상을 놓침) |
| 실제 정상 | **FP** (*False Positive*, 잘못 울린 경보) | **TN** (*True Negative*, 맞게 정상 판단) |

| 지표 | 계산과 뜻 | 예시 |
|---|---|---|
| 정확도(accuracy) | `(TP+TN)/(TP+FP+FN+TN)`, 전체 중 맞힌 비율 | 이상이 매우 적으면 모두 정상이라고 해도 높을 수 있으므로 이것만 보면 위험하다. |
| 정밀도(precision) | `TP/(TP+FP)`, 이상이라고 말한 것 중 실제 이상인 비율 | 경보 10건 중 진짜 8건이면 0.8이다. |
| 재현율(recall), 탐지율 | `TP/(TP+FN)`, 실제 이상 중 찾아낸 비율 | 실제 사고 10건 중 8건을 찾으면 0.8이다. |
| 거짓양성률(FPR, False Positive Rate) | `FP/(FP+TN)`, 실제 정상 중 오경보 비율 | 정상이 100건이고 5건을 잘못 경보하면 0.05다. |
| **F1 점수** | `2×정밀도×재현율/(정밀도+재현율)` | 두 수치를 함께 보며, 한쪽이 낮으면 점수도 낮아진다. |
| **ADR** — *Anomaly Detection Rate* | X-iForest 논문에서는 올바르게 찾은 이상 수/실제 이상 수 | 그 논문 정의에서는 재현율과 같은 계산이지만, 다른 논문에서는 정의를 확인해야 한다. |
| **ROC 곡선** — *Receiver Operating Characteristic* | 이상 판정의 **임계값**을 바꿀 때 거짓양성률과 재현율이 어떻게 바뀌는지 그린 선 | 경보 기준을 낮추면 더 많이 찾지만 오경보도 늘 수 있다. |
| **AUC-ROC** — *Area Under the ROC Curve* | ROC 곡선 아래 면적이다. 1에 가까울수록 대체로 정상·이상 점수의 순위가 잘 나뉜다. | 0.9와 0.8의 차이가 모든 현장 조건에서 똑같은 이익이라는 뜻은 아니다. |

**숫자 예시:** 실제 이상 10건, 정상 90건에서 모델이 이상 8건을 찾고 정상 9건에 잘못 경보했다면 `TP=8`, `FN=2`, `FP=9`, `TN=81`이다. 정밀도는 `8/17≈0.47`, 재현율은 `8/10=0.8`, 정확도는 `89/100=0.89`다. 정확도 89%라는 숫자만 보면 오경보 9건을 놓치기 쉽다.

**contamination(예상 이상 비율)**은 학습 자료에 이상이 어느 정도 섞였는지 모델에 알려주거나 이상 판정 경계를 정할 때 쓰는 설정값이다. 실제 비율과 다르면 같은 이상 점수라도 정상·이상 판정 결과가 달라질 수 있다. **임계값(threshold)**은 “이 점수 이상이면 경보”처럼 최종 판단을 나누는 기준이다.


### 8. 논문을 읽을 때 자주 만나는 나머지 표현

| 표현 | 뜻 |
|---|---|
| 표형 데이터(tabular data) | 엑셀 표처럼 행은 표본, 열은 특징인 자료다. ISER 논문 제목의 “tabular”가 이것을 뜻한다. |
| 리뷰(review), 문헌 연구 | 앞선 연구를 모아 방법·흐름을 정리한 글이다. 멀티뷰 리뷰가 여기에 속하며 새 알고리즘의 실험 논문과 목적이 다르다. |
| 기준 방법(baseline), 비교 방법 | 새 방법이 얼마나 나은지 알아보려고 같은 자료에서 함께 평가하는 기존 방법이다. |
| 벤치마크(benchmark) | 여러 방법을 같은 자료와 규칙으로 비교하는 평가다. 자료·설정이 달라지면 순위도 달라질 수 있다. |
| 하이퍼파라미터(hyperparameter), 매개변수 | 학습 전에 정하는 설정이다. 트리 수, 표본 크기, 군집 수 후보 등이 예다. 모델이 학습 중 조정하는 내부 가중치와 구별한다. |
| 학습된 가중치, 역전파(backpropagation) | 신경망의 가중치는 데이터에 맞춰 바뀌는 내부 숫자다. 역전파는 출력 오류를 거꾸로 전달해 그 숫자를 조정하는 일반적인 방법이다. ABIForest 논문은 다른 최적화 절차를 사용한다. |
| 복원 오차(reconstruction error) | 오토인코더가 다시 만든 값과 실제 입력값의 차이다. 예: 실제 30도인데 21도로 복원하면 오차가 크다. |
| 단일 장애점(single point of failure) | 한 장치가 고장 나면 전체 기능이 멈추는 취약한 지점이다. 중앙에서만 센서를 감시할 때 문제가 될 수 있다. |
| 테스트베드(testbed) | 실제 운영 환경을 흉내 내어 실험할 수 있게 만든 장비·소프트웨어 묶음이다. 테스트베드 성능이 모든 현장에 그대로 적용되는 것은 아니다. |
| 개념 변동(concept drift) | 시간이 지나면서 정상 데이터의 모습이 바뀌는 일이다. 밤낮·계절·새 장비 도입 때문에 모델을 다시 점검해야 할 수 있다. |
| 스왐핑(swamping), 마스킹(masking) | 스왐핑은 정상이 이상처럼 보이는 것, 마스킹은 이상끼리 모여 이상이 덜 눈에 띄는 것이다. |
| 논문 식별자 DOI, arXiv | **DOI**는 논문 등 문헌을 찾는 고유 번호다. **arXiv**는 연구자가 논문 원고를 공개하는 저장소다. arXiv 원고와 정식 학술지 게재본의 상태는 다를 수 있다. |


## 빠르게 다시 찾는 용어

| 용어 | 뜻 | 이 자료에서 기억할 점 |
|---|---|---|
| 이상(anomaly), 이상치(outlier) | 다른 데이터의 일반적인 패턴과 다른 관측값 | “이상”이 곧 공격이나 고장이라는 뜻은 아니다. |
| 비지도 학습 | 학습에 정답 레이블을 쓰지 않음 | 성능 평가에는 레이블을 쓸 수 있다. |
| 지도 학습 | 정답 레이블을 이용해 모형 또는 가중치를 학습함 | 이 논문의 ABIForest는 지도 방식이다. |
| 특징(feature) | 모형에 제공하는 측정값 또는 파생값 | 웹 로그의 URI 길이, PV 윈도의 평균 등이 예다. |
| 뷰(view) | 같은 대상을 보는 하나의 데이터 관점 | 특징 한 개와 항상 같은 뜻은 아니다. |
| 앙상블 | 여러 모델이나 여러 분할의 결과를 결합함 | IF의 여러 트리, ISER의 여러 초구 분할이 해당한다. |
| 이상 점수 | 이상일 정도를 나타내는 연속적인 수치 | 점수가 높을수록 이상이라는 정의는 모델마다 확인해야 한다. |
| 임계값(threshold) | 점수를 정상·이상 판단으로 바꾸는 기준 | 바꾸면 재현율과 오경보율이 함께 변한다. |
| 오경보(FP) | 정상을 이상으로 잘못 판단함 | 운영자가 불필요하게 대응해야 한다. |
| 미탐지(FN) | 이상을 정상으로 놓침 | 보안·안전 환경에서는 피해가 클 수 있다. |
| 정밀도 | 이상이라고 한 것 중 실제 이상인 비율, `TP/(TP+FP)` | 오경보가 많으면 낮아진다. |
| 재현율/탐지율 | 실제 이상 중 찾아낸 비율, `TP/(TP+FN)` | 미탐지가 많으면 낮아진다. |
| 특이도 | 실제 정상 중 정상으로 분류한 비율, `TN/(TN+FP)` | 오경보율은 일반적으로 `1−특이도`다. |
| F1 점수 | 정밀도와 재현율의 조화평균 | 둘 중 하나가 낮으면 크게 낮아진다. |
| ROC AUC | 임계값을 바꾸며 얻는 ROC 곡선 아래 면적 | 1에 가까울수록 대체로 분리 능력이 좋다. |
| ADR | 이상 탐지율(Anomaly Detection Rate) | 문헌마다 계산 정의를 확인해야 한다. |
| 개념 변동(concept drift) | 시간이 지나 정상 데이터의 패턴이 달라짐 | 센서와 네트워크의 장기 운영에서 중요하다. |
| 스왐핑(swamping) | 정상 데이터가 이상처럼 보이는 현상 | 오경보와 관련된다. |
| 마스킹(masking) | 이상들이 서로 뭉쳐 정상처럼 보이는 현상 | 실제 이상을 놓칠 수 있다. |

## 숫자를 비교할 때 주의할 점

논문 사이의 정확도·AUC·F1 숫자를 한 줄로 나열해 순위를 매길 수는 없다. **데이터셋, 이상 비율, 레이블 기준, 특징 설계, 임계값, 하드웨어**가 다르다. 예를 들어 웹 로그 논문의 정확도 93%와 EPICS 논문의 F1 0.905는 서로 다른 문제·지표다. 또한 멀티뷰 리뷰는 성능 경쟁 실험이 아니라 방법을 정리한 문헌 연구다. ABIForest는 레이블을 요구하는 반면 기본 IF·ISER는 비지도 이상 탐지에 초점을 둔다.

EPICS 논문 PDF의 첫쪽에는 저자가 **Ravi Dayani**로 적혀 있지만 이후 쪽의 머리말에는 **Selvakumar Kalyanasundaram**이라는 다른 이름이 나온다. 이 서지 정보 불일치는 PDF 원문에 있는 그대로이며, 저자 표기는 첫쪽의 논문 제목 아래에 있는 이름을 따랐다.
