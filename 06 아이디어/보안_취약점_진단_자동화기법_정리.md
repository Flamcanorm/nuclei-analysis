## 핵심 요약

| 질문 | 논문의 내용 |
|---|---|
| 문제 | 서버와 운영체제의 취약점 진단에 시간과 인력이 많이 들고, 여러 대상의 결과를 수작업으로 정리해야 한다. |
| 방법 | Java로 운영체제별 진단 기준을 담은 `Settings.ini`를 만들고, 셸 스크립트로 점검한 결과를 CSV로 변환한다. |
| 결과 | 논문 국문 초록과 결론은 서버 1대당 진단 시간이 기존 약 20분에서 약 3분으로 줄었다고 보고한다. 저자는 약 7배의 시간 차이와 작업일 기준 비용 약 63% 감소를 제시한다. |
| 범위 | 실험 대상 운영체제는 CentOS 6·7이다. 오탐 및 실제 운영 환경의 다양한 변수는 충분히 검증하지 못했다. |

## 무엇을 자동화했나

1. 운영체제별로 다른 진단 항목의 기준값을 `Settings.ini`에 정의한다.
2. 셸 스크립트가 서버 설정 상태를 점검한다.
3. 점검 결과를 CSV 형태로 출력하여 여러 서버의 결과를 모으고 보고서를 만들기 쉽게 한다.

이 논문이 다루는 대상은 **서버·운영체제 설정 진단**이다. 웹 페이지를 탐색하거나 HTTP 요청으로 웹 애플리케이션 취약점을 찾는 연구로 분류하면 범위가 달라진다.

## 평가와 읽을 때 주의할 점

- 국문 초록·본문 결론: 서버 1대당 약 **20분 → 3분**.
- 영문 초록: 자동화 진단 시간이 **10초**, 약 **120배**라고 적혀 있다. 같은 PDF 안의 수치가 충돌하므로 이 정리는 국문 초록·결론에서 반복되는 `3분`을 주된 결과로 적고, 차이를 명시한다.
- 본문은 자동화 스크립트에 모든 진단 항목을 넣지 못했다고 밝힌다. 따라서 시간 비교를 “동일한 범위의 모든 항목을 검사한 비교”로 단정하기 어렵다.
- CentOS 6·7 외 운영체제, 실제 운영 서버의 오탐, 환경 차이에 대한 추가 검증이 필요하다고 저자가 결론에서 적었다.

## 용어

| 용어 | 뜻 |
|---|---|
| `Settings.ini` | 항목별 점검 기준을 적어 두는 설정 파일 |
| 셸 스크립트 | 운영체제 명령을 순서대로 실행하는 파일 |
| CSV | 결과를 쉼표로 구분해 저장하는 표 형식 파일 |
| 오탐 | 실제 취약하지 않은 상태를 취약하다고 판단하는 오류 |
