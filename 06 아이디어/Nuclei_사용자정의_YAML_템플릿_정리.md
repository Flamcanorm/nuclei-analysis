# Nuclei 사용자 정의 YAML 템플릿으로 인프라 노출 항목 찾기

## 논문 정보

| 항목 | 내용 |
|---|---|
| 원제 | *Limiting Attack Surface for Infrastructure Applications using Custom YAML Templates in Nuclei Automation* |
| 저자 | Hardik Solanki |
| 소속·문헌 | National College of Ireland, School of Computing, MSc Cyber Security 연구 프로젝트 |
| 지도교수·제출일 | Prof. Vikas Sahni, 2023년 1월 6일 |
| 정리한 원문 | `YAML Templates in Nuclei Automation.pdf` |

## 핵심 요약

| 질문 | 논문의 내용 |
|---|---|
| 문제 | 일반적인 취약점 검사에서 놓칠 수 있는 인프라 애플리케이션의 파일·관리 화면 노출을 찾아 공격 표면을 줄이고자 한다. |
| 해결 방법 | 찾으려는 항목의 요청·응답 조건을 사용자 정의 Nuclei YAML 템플릿으로 작성해 여러 대상에 자동 적용한다. |
| 실제 수행 | Subversion 작업 파일, WS_FTP 로그 파일, 관리자 로그인 화면을 찾는 템플릿 3개를 만들고 인프라 대상 67개에 시험했다. |
| 결과 | 논문은 각각 4개, 2개, 2개의 일치 대상을 보고한다. 이는 세 가지 템플릿의 탐지 사례이며 전체 취약점 탐지율을 뜻하지 않는다. |

## 연구 흐름

1. 인프라 환경에서 공개되면 문제가 될 수 있는 파일이나 관리 화면을 고른다.
2. 각 항목을 식별할 HTTP 요청과 응답 조건을 Nuclei용 YAML 템플릿으로 적는다.
3. 템플릿을 시험·수정하고, 논문에서 설명한 대상 목록에 Nuclei를 실행한다.
4. 일치 결과를 검토해 파일의 공개 접근 가능 여부와 화면 노출 여부를 확인한다.
5. 템플릿을 공유하려는 경우 기존 템플릿과의 중복 여부도 확인한다. 논문은 중복을 이유로 제출이 거절될 수 있다고 설명한다.

## 세 가지 실험 결과

| 템플릿 | 찾는 항목 | 67개 대상 중 보고된 일치 수 | 읽을 때 주의할 점 |
|---|---|---:|---|
| `svn-wc-db.yaml` | 외부에서 접근 가능한 Subversion 작업 파일 `wc.db` | 4 | 파일 노출을 확인한 사례다. |
| `ws-ftp-log.yaml` | 공개된 `WS_FTP.LOG` | 2 | 로그에 민감한 내용이 포함될 가능성이 있다. |
| `superadmin-ui-panel.yaml` | 외부에 보이는 관리자 로그인 화면 | 2 | 논문의 심각도 표기도 `info`다. 화면 노출만으로 인증 우회나 악용 가능한 취약점이 입증되지는 않는다. |

## 결과의 범위와 한계

- 논문은 특정한 템플릿 세 개와 대상 67개에 대한 탐지 결과를 보여준다. 다른 환경과 취약점 종류에 결과가 그대로 적용된다고 볼 수 없다.
- 논문에는 오탐이 없다는 취지의 서술이 있으나, 전체 검사 결과에 대한 독립적인 정답 표지나 오탐률 계산은 제시되지 않는다.
- 논문이 제로데이 대응 가능성을 언급하지만, 제로데이를 실제로 발견하거나 차단했음을 보여주는 평가로 읽기는 어렵다.
- 템플릿이 어떤 항목에 일치했는지와 그 항목이 실제 공격 가능한 취약점인지는 별도로 검증해야 한다.

## 용어

| 용어 | 뜻 |
|---|---|
| Nuclei | 정해진 검사 규칙을 여러 대상에 적용해 일치 여부를 확인하는 보안 검사 도구 |
| YAML 템플릿 | 검사 요청, 응답에서 찾을 조건, 결과 정보 등을 적은 규칙 파일 |
| 공격 표면 | 외부인이 접근하거나 공격에 이용할 수 있는 시스템의 부분 |
| Subversion·`wc.db` | 버전 관리 도구와 그 작업 정보가 담긴 데이터베이스 파일 |
| WS_FTP 로그 | 파일 전송 프로그램이 남기는 기록 파일 |
| 오탐 | 실제 문제가 없는데 검사 결과가 문제라고 판단하는 경우 |
| 제로데이 | 공개되거나 패치되기 전의 취약점을 가리키는 말 |
