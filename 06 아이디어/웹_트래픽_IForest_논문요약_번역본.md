## 한국어 본문 번역·정리

### 초록

기업의 디지털 전환이 진행될수록 데이터 자산의 가치가 올라가고 해커에게도 더 매력적인 표적이 된다. 웹 로그가 방대하므로 사이버보안 전문가가 웹 트래픽의 이상을 찾아내려면 발전된 분류 방법이 필요하다. 본 연구는 비지도 머신러닝 방법인 Isolation Forest를 사용하여 정상·이상 웹 트래픽을 식별하는 것을 목표로 한다. 공개된 전자상거래 웹사이트 로그 데이터셋을 가져와 데이터 적재, 자료형 변환, 정리, 정규화로 이루어진 체계적인 과정으로 준비했다. 이 과정에서 학습 데이터에 파생 열을 추가하고, 시험 데이터에는 수작업 레이블을 부여했다. 이후 Isolation Forest의 탐지 성능을 보안 전문가의 판단과 비교했다. Python의 scikit-learn으로 구현한 모형은 정확도 93%, 정밀도 95%, 재현율 90%, F1 점수 92%를 보였다. 적절한 데이터 준비, 모형 개발·구현·평가를 거치면 Isolation Forest가 웹 트래픽 이상을 상당히 정확하게 찾아내는 유용한 방법이 될 수 있음을 보여준다.

**주요어:** 이상 탐지, 웹 트래픽, 머신러닝, Isolation Forest.

## 1. 서론

개인정보 보호법이 엄격해지면서 웹사이트 소유자에게 보안 침해는 벌금, 평판 손상, 서비스 중단에 따른 매출 손실을 일으킬 수 있다. 따라서 보안 담당자가 침해로 이어질 수 있는 이상 웹 트래픽을 조기에 식별해야 한다[1–5]. 정상과 악성 활동은 모두 웹 로그에 흔적을 남긴다[2,3]. 그러나 공격자가 웹 기반 공격을 늘리고 탐지를 회피하도록 방법을 숨기기 때문에, 기존 네트워크·웹 서버 방화벽만으로는 충분하지 않다[1,3,6,7]. 로그의 양도 방대해 수동 분석이 현실적으로 어렵다[3,5].

머신러닝은 이상 트래픽의 식별을 빠르게 해 준다. 하지만 이상은 전체 트래픽 중 극히 일부인 경우가 많아 클래스가 불균형하다. 정상 패턴과 다른 트래픽에는 계절적 활동 증가와 같은 무해한 이상도 있고, 취약점 악용·사기·서비스 방해를 나타내는 악성 이상도 있다[2,8]. 악성 행위자는 정상 트래픽 속에 행동을 숨기므로 로그의 복잡한 패턴을 살피는 일이 웹 성능 최적화와 보안 양쪽에 중요하다.

이전 연구는 분류기 앙상블의 스택 구조, 통계·머신러닝·혼합 방법, 네트워크 트래픽의 Extended Isolation Forest 등을 다루었다[1–8]. 규칙 기반 방법은 이미 알려진 위협을 찾는 데 유용하지만 공격 방식의 변화에 적응하기 어렵다. 머신러닝은 방대한 로그의 패턴을 학습하여 새로운 방식의 악성 활동도 발견할 수 있다. 다만 데이터 불균형은 여전히 큰 과제다.

IForest는 학습에 레이블을 요구하지 않으며 빠르고 부분 표본을 사용하므로 대용량 데이터에 적합하다[7,9–14]. 네트워크 이상 탐지에는 쓰였지만 웹 트래픽 이상 탐지에서는 널리 구현되지 않았다. 이 연구는 웹 로그에 IForest를 구현하여 정확한 탐지에 필요한 데이터와 매개변수, 구현 방법, 성능을 조사한다. 이상 발견 결과는 네트워크·웹사이트 관리자가 숨은 취약점을 찾고 대응책을 마련하는 데 도움이 될 수 있다. 연구 질문은 (1) 어떤 데이터와 매개변수를 어떻게 준비하는가, (2) IForest를 어떻게 구현하는가, (3) 웹 트래픽 이상 탐지 성능은 어떠한가이다.

## 2. 방법론

공개 데이터셋의 정상·이상 트래픽에서 IForest를 구현하고 정확도·정밀도·재현율·F1 점수로 평가한다[15]. 그림 1의 연구 절차는 **데이터 준비 → 모델 생성 → 모델 평가**의 세 단계다.

**그림 1.** 연구 설계의 개요.

### 2.1. 웹 트래픽 데이터 준비

사용한 자료는 Harvard Dataverse의 Farzin Zaker가 공개한 “2019 Online Shopping Store—Web Server Logs”로, Kaggle에서 취득했다[9,16]. 약 3.3GB, 천만 건 정도의 이란 전자상거래 사이트 `zanbil.ir`의 Nginx 접근 로그다. 표 1에는 방문자 IP, 요청 시각, HTTP 방식, URI, 프로토콜, 상태 코드, 전송 바이트, 참조 페이지, 사용자 에이전트가 포함된 로그 예가 있다. 정상 트래픽은 사용자와 웹 서버가 상호작용할 때의 일반적 행동 패턴이다. 일반적 패턴에서 벗어난 항목을 자동으로 공격으로 단정해서는 안 되지만, 이후의 실제 공격을 예고한 사례도 있어 조사할 가치가 있다[1,4,5,17].

**표 1. 웹 트래픽 원시 로그의 예**

```text
40.77.167.129 — [22/Jan/2019:03:56:18 +0330]
"GET /image/57710/productModel/100x100 HTTP/1.1" 200 1695
"-" "Mozilla/5.0 (compatible; bingbot/2.0; +http://www.bing.com/bingbot.htm)"
```

**표 2. 원시 데이터의 열과 자료형**

| 열 | 자료형 | 열 | 자료형 | 열 | 자료형 |
|---|---|---|---|---|---|
| Srcip | object | URIs | category | Bytes | int32 |
| Timestamp | object | Protocol | category | Referrer | category |
| Method | category | Status | category | User-Agent | category |

연구진은 적재, 자료형 변환, 정리를 연결한 파이프라인을 설계했다. 전체 로그의 25%를 학습용, 10%를 시험용으로 추출하고 결측 행을 제거했다[18]. 작은 표본은 정상점이 잘못 이상으로 분류되는 **스왐핑**과 이상점이 정상처럼 보이는 **마스킹** 효과를 줄일 수 있다[12,13,19–22]. 원래 Apache 로그 형식의 데이터를 CSV 표로 변환한 뒤, Python으로 자료형 오류와 결측값을 정리했다.

**그림 2.** 데이터 준비 과정의 파이프라인.

### 2.2. IForest 구현

URI, User-Agent, Referrer에서 `URI_occurrences`, `IOC_occurrences`, `User-Agent_occurrences`, `URI_length`, `UserAgentLength` 등의 파생 특징을 만들었다. 원래 열인 Srcip, Timestamp, Method, URI, Protocol, Status, Bytes, Referrer, User-Agent도 입력에 포함했다. 사용자 에이전트와 URI 문자열에서 비정상 문자 집합과 침해 지표(IOC)의 출현을 분석했다. 정상적인 문자열에 없는 악성 지표가 포함되면 이상 징후일 수 있다. URI는 인터넷의 이름 또는 자원을 식별하는 문자열이며, URL은 그중 자원의 위치와 가져오는 방식까지 지정하는 하위 유형이다.

Python scikit-learn 파이프라인에서 숫자가 아닌 범주형 자료를 `OneHotEncoder()`로 바꾸었다. 원핫 인코딩은 단어마다 별도 차원을 두어 해당 단어가 나타나면 1, 아니면 0으로 표시한다. 공격에서 일반 사전에 없는 문자열이 자주 쓰인다는 한계도 있다. 숫자형 자료에는 `StandardScaler()`를 적용하여 큰 수치 자체가 결과에 편향을 만들지 않도록 했다. `ColumnTransformer`로 열별 변환을 묶고, 숫자 열은 평균 0, 표준편차 1로 맞췄다. 모델을 만든 뒤 시험 데이터에 같은 전처리 파이프라인을 적용했다. 시험 결과에는 예측 `Predict`(이상 −1, 정상 +1)와 `Anomaly_Score` 열을 추가했다.

격리 숲은 선택한 특징과 값으로 데이터를 재귀적으로 무작위 분할한다. 다른 점과 크게 다른 이상은 트리 뿌리에 가까운 짧은 경로에서 격리되는 경향이 있으므로 이상 점수가 커진다. 이 연구에서는 이상 비율을 나타내는 `contamination = 0.03`, 재현 가능한 난수를 위한 `random_state = 42`, 병렬 처리 `n_jobs = 16`, 표본 비율 `max_samples = 0.25`를 사용했다. 데이터셋에서 추정한 실제 이상 비율이 1.6% 미만이라는 판단을 바탕으로 오염률을 3%로 정했다. 이 값은 실제 이상 비율에 얼마나 가까운지에 따라 결과가 달라지는 민감한 매개변수다[11,25–27].

**그림 3.** 데이터 준비 및 모델 생성 과정.

### 2.3. IForest 평가

시험 데이터에는 모델 결과 외에 사람이 점수를 매긴 `Human Rating`과 SQL 삽입, 크로스 사이트 스크립팅, 탐색·터널 연결 등 공격 종류를 적은 `Attack Type`을 추가해 총 17개 열을 만들었다. 사람의 정상·이상 판단과 모델 예측을 비교하여 성능을 측정했다. 산점도와 혼동 행렬로 결과를 시각화했고, 높은 이상 점수는 정상에 비해 드문 데이터일 가능성이 큰 것으로 보았다.

정확도만 보면 불균형 자료에서 다수를 정상으로 분류하는 모델이 실제 이상을 놓쳐도 높은 점수를 받을 수 있다. 그래서 정밀도, 재현율, F1 점수도 함께 평가했다. TP는 실제 이상을 이상으로, TN은 실제 정상을 정상으로 맞힌 수다. FP는 정상을 이상으로 잘못 본 수, FN은 이상을 놓친 수다.

```text
정확도 = (TP + TN) / (TP + TN + FP + FN)       (1)
정밀도 = TP / (TP + FP)                        (2)
재현율 = TP / (TP + FN)                        (3)
F1 점수 = 2 × 정밀도 × 재현율 / (정밀도 + 재현율)  (4)
```

**그림 4.** 데이터 준비, 모델 생성, 모델 평가의 연결 과정.

**그림 5.** (a) 바이트 수와 IOC 발생 횟수, (b) 요청 방식과 URI 발생 횟수, (c) User-Agent와 IOC 발생 횟수의 이상 시각화.

## 3. 결과와 논의

### 3.1. 웹 트래픽 데이터 준비 결과

IForest가 웹 로그에서 작동하도록 학습 데이터의 결측 행을 제거하고 숫자가 아닌 열을 변환했다. 원자료에서 Bytes 열만 일반적인 숫자형이었으므로 특징 공학으로 네 열(`URI_occurrences`, `IOC_occurrences`, `User-Agent_occurrences`, `URI_length`)을 추가했다. 숫자 열은 `StandardScaler`, 범주형 열은 `OneHotEncoder`에 넣었다.

**표 3. 준비된 학습 데이터의 스키마**

| 열 | 자료형 | 열 | 자료형 |
|---|---|---|---|
| Srcip | object | Timestamp | object |
| Method | category | URIs | category |
| Protocol | category | Status | category |
| Bytes | int32 | Referrer | category |
| User-Agent | category | URI_occurrences | int64 |
| IOC_occurrences | int64 | User-Agent_occurrences | int64 |
| URI_length | int64 | | |

시험 데이터에도 같은 정리와 특징 생성을 적용했다. 그 뒤 사람의 평가와 공격 유형, 모델의 예측 및 이상 점수 열을 추가하고 결과를 CSV로 저장했다.

**표 4. 준비된 시험 데이터에 추가된 열**

| 열 | 뜻 |
|---|---|
| Attack Type | 공격 종류 |
| Human Rating | 사람이 매긴 정상·이상 평가 |
| Predict | 모델의 분류 결과 |
| Anomaly_Score | 모델의 이상 점수 |

학습·시험에는 각각 전체의 25%, 10%를 사용했다. IForest 자체는 비지도 방법이므로 전통적인 정답 레이블 기반 분할을 하지 않고 무작위 표본을 사용했다[11,15,24]. 전처리 후 학습 레코드는 2,591,287개, 시험 레코드는 1,035,020개였다. 연구진은 시험 로그를 사람이 평가해 실제 보안 전문가의 판단과 머신러닝 분류를 비교했다. 정규화와 척도 조정도 모델 생성 전에 수행했다. 일반적인 원핫 인코딩·표준화 외에 사람이 붙인 시험 레이블과 파생 열을 함께 사용한 점이 이 연구의 데이터 준비 특징이다.

**표 5. 모델에 사용한 데이터셋**

| 구분 | 전체 대비 비율 | 레코드 수 |
|---|---:|---:|
| 학습 | 25% | 2,591,287 |
| 시험 | 10% | 1,035,020 |

### 3.2. IForest 구현 및 평가 결과

시험 데이터에서 계산한 분류 지표는 표 6과 같다. 정확도 93%와 정밀도 95%는 예측한 이상 가운데 실제 이상이 많은 편임을, 재현율 90%는 실제 이상의 약 10%를 놓쳤음을 보여준다. 정밀도와 재현율을 함께 반영한 F1 점수는 92%다.

**표 6. IForest 분류 성능**

| 정확도 | 정밀도 | 재현율 | F1 점수 |

| 0.93 | 0.95 | 0.90 | 0.92 |

다른 IForest 연구와 비교하면 이 연구의 성능은 비슷하거나 처리 속도가 더 빠른 수준이라고 논문은 평가한다[21,22]. 비교 연구 하나는 정확도 95.4%, 정밀도 94.81%, 재현율 97.25%, F1 96.01%를, 다른 연구는 IForest와 커널 주성분 분석을 결합해 각각 87.3%, 93.7%, 92.5%, 93.1%를 보였다. 후자의 IForest 단독 결과는 정확도 80.9%, 정밀도 86.0%, 재현율 85.5%, F1 85.2%였다. 본 연구에서 모델 적용에 걸린 시간은 23.620082초였다. 속도는 빠른 대응에 중요하지만 결과의 질을 희생해서는 안 되므로 정확도와 함께 균형을 보아야 한다.

이 연구는 전체의 약 25%를 학습, 10%를 시험에 쓰고 숫자·범주형 자료를 변환했다. 시험 약 100만 건은 모델 검증을 위해 수동으로 레이블을 붙였다고 기술한다. 모델은 PCA, 오토인코더, 앙상블 같은 다른 이상 탐지 방법을 결합하지 않고 IForest만 구현했다. HTTP 기반 웹 트래픽만 다루며 전송 계층 세그먼트나 네트워크 계층 패킷은 포함하지 않는다.

## 4. 결론 및 권고

공개 웹 로그를 적재, 자료형 변환, 정리하고 파생 특징을 만든 뒤 IForest를 개발·구현·평가했다. 학습 2,591,287건과 시험 1,035,020건에서 정확도 93%, 정밀도 95%, 재현율 90%, F1 92%를 얻었다. 이는 네트워크 관리자와 보안 연구자가 웹 트래픽에서 이상을 신속히 찾고 웹사이트 대상 공격의 실마리를 파악하는 데 IForest가 도움이 될 수 있음을 보여준다. 모델 실행 시간은 약 23.62초로, 조기에 공격 벡터를 파악해 대응할 시간을 제공할 수 있다.

향후에는 웹 로그를 최근 공개된 공통 취약점 및 노출(CVE)의 특성과 연결해 특징을 만들고, 알려지지 않은 제로데이 공격에 대한 효율도 탐구할 수 있다. 다만 이 논문은 웹 로그의 응용 계층 자료에 초점을 맞췄으며 더 낮은 네트워크 계층은 분석하지 않았다.
