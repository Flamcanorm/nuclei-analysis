# RuleForge: 대규모 웹 취약점 탐지 규칙의 자동 생성과 검증

## 핵심 요약

| 질문 | 논문의 내용 |
|---|---|
| 문제 | 새로 공개되는 CVE 수에 비해 사람이 HTTP 공격 탐지 규칙을 만드는 속도가 느리다. 자동 생성 규칙은 오탐·미탐을 줄이도록 검증해야 한다. |
| 입력과 출력 | **입력:** CVE 설명과 공격 예시를 담은 Nuclei YAML 템플릿. **출력:** 보안 이벤트에서 특정 CVE 악용 요청을 찾는 JSON 기반 탐지 규칙. 즉 Nuclei 템플릿 자체를 생성하는 연구가 아니다. |
| 방법 | CVE 우선순위 선정 → LLM으로 규칙 후보 5개 생성 → 후보별 최대 5회 수정 → 합성 요청·LLM 평가·실제 트래픽·IP 평판·전문가 검토로 검증한다. 실패 사유를 다시 생성 단계에 전달한다. |
| 결과 | LLM 평가 점수는 100개 시험 예에서 AUROC 0.75, 보정 오류(ECE) 0.17이었다. 50개 CVE 비교에서 합성 시험만 쓰는 경우보다 거짓양성 규칙을 67%, 일치 IP가 없는 규칙을 71% 줄였다고 보고한다. |

## 시스템 처리 순서

1. Nuclei 템플릿에서 CVE 관련 설명·요청 예시를 수집하고 우선순위를 정한다.
2. Amazon Bedrock의 LLM을 이용해 CVE 하나당 서로 다른 탐지 규칙 후보 5개를 만든다.
3. 각 후보를 7개 악성·3개 정상의 합성 HTTP 요청으로 시험하고, 10개 중 적어도 8개를 맞히도록 한다.
4. 다른 정상 요청을 공격으로 잘못 잡을 위험과 공격을 놓칠 위험을 LLM이 각각 평가한다.
5. 일부 규칙은 대규모 실제 웹 트래픽에서 일치 건수와 관련 IP 평판을 검사한다.
6. 마지막 승인 여부는 보안 엔지니어가 검토한다. 실패 이유는 다음 생성 시도에 반영한다.

## 평가 결과와 범위

- 논문은 2025년 마지막 4개월의 운영에서 AI 규칙 생성의 생산성이 사람의 생성보다 336% 높았다고 보고한다. 절대 규칙 수는 공개하지 않았다.
- 실제 트래픽 검사는 최대 월 50억 건에서 임의 추출한 기록을 사용하며, 주로 요청 본문을 검사하지 않는 규칙에 적용된다.
- Nuclei 템플릿이 없는 CVE에는 기존 운영 방식만으로 규칙을 만들기 어렵다. 별도로 비정형 문서 10건을 시험해 전체 10건 중 4건의 규칙을 사용 가능한 수준으로 평가했으나, 이는 생산 환경 기능이 아닌 개념 검증이다.
- 생성과 평가에 같은 Claude 모델 계열을 사용해 자기 선호 편향이 생길 수 있고, 사람이 검토한 추론 설명 사례는 9건에 불과하다. 저자도 이를 통계적으로 결론 내리기 어려운 예비 결과로 다룬다.

## Nuclei와의 관계

이 연구에서 Nuclei YAML은 **취약점 지식을 공급하는 구조화된 입력**이다. 생성되는 JSON 규칙은 실제 이벤트 로그의 HTTP 악용 요청을 분류하기 위한 것이므로, “Nuclei 템플릿 자동 생성”과 구분해야 한다.

## 용어

| 용어 | 뜻 |
|---|---|
| CVE | 공개된 취약점에 붙이는 공통 식별 번호 |
| LLM-as-a-judge | LLM이 다른 생성 결과의 품질을 평가하는 방식 |
| 민감도·특이도 | 악성 요청을 놓치지 않는 정도·정상 요청을 잘못 잡지 않는 정도 |
| AUROC | 좋은 규칙과 나쁜 규칙을 점수로 얼마나 잘 구별하는지 보는 지표 |
| ECE | 예측한 확신도와 실제 정확도가 얼마나 다른지 보는 지표. 낮을수록 보정이 좋다. |
