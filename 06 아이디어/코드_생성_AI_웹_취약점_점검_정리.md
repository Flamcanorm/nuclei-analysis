# 코드 생성 AI를 이용한 웹 취약점 점검 방법에 관한 연구

## 핵심 요약

| 질문 | 논문의 내용 |
|---|---|
| 문제 | 수동 웹 취약점 점검은 오래 걸리고 사람의 실수에 영향을 받는다. 웹 스캐너는 정해진 패턴에 강하지만 복잡한 로그인·업무 흐름을 다루기 어렵다. |
| 방법 | 보안 전문가가 점검 목표와 페이지·입력 필드를 자연어로 적으면 코드 생성 AI가 Selenium 기반 테스트 코드를 만들도록 한다. 생성 코드를 실행·수정하고 화면 캡처 등 증적을 관리한다. |
| 사례 | Cursor AI로 SQL 인젝션 점검 코드를 생성하고, VS Code의 Continue 확장으로 로그인 이후 명령어 삽입 점검 절차를 작성한다. |
| 보고된 결과 | 논문은 수동 방식보다 점검 시간이 약 40% 줄었다고 요약한다. 본문 사례에서는 코드 생성 AI로 약 20분 걸린 작업을 웹 스캐너·수동 점검으로는 약 1시간이 필요했다고 서술한다. |

## 연구 흐름

1. 웹 스캐너와 RPA 방식의 장단점을 비교한다.
2. 취약점 유형, 로그인 절차, 입력 필드, 기대 결과를 프롬프트에 구체적으로 적는다.
3. 코드 생성 AI가 브라우저 자동화용 테스트 코드를 만든다.
4. 전문가가 코드의 실행 안전성, 오류, 오탐·미탐을 확인하고 프롬프트와 코드를 고친다.
5. 취약점 시험 전후 화면과 실행 기록을 증적으로 남긴다.

## 결과 해석과 한계

- 논문의 약 40% 단축 수치는 제시된 점검 사례·조건에 대한 보고다. 모든 웹 취약점 종류와 사이트에서 동일한 개선을 뜻하지 않는다.
- 본문에서 처음 생성한 코드가 의도와 다르게 작동해 수정이 필요했던 사례를 제시한다.
- 복잡한 업무 로직, 권한 관리 문제, AI가 잘 모르는 새 취약점은 전문가 점검이 여전히 필요하다고 결론 내린다.
- 논문의 비교 표에는 오탐률 `0%` 같은 강한 표현이 있으나, 이 수치를 보편적 성능으로 일반화할 만큼의 광범위한 평가가 제시된 것은 아니다.

## 용어

| 용어 | 뜻 |
|---|---|
