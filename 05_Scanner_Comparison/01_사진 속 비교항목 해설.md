## 비교표가 답하려는 질문

사진은 각 도구를 다음 순서로 비교한다.

```text
무엇으로 검사를 정의하는가?
        ↓
무엇을 검사하는가?
        ↓
어떤 순서로 실행하는가?
        ↓
무엇을 근거로 결과를 판단하는가?
        ↓
새 검사를 어떻게 추가하는가?
        ↓
결과를 어떻게 제공하는가?
        ↓
Nuclei와 무엇이 비슷하고 다른가?
```

이 질문들은 보안 스캐너의 구조를 설명하기에 적절하다. 다만 마지막 두 행인 `가장 비슷한 점`과 `중요한 차이`는 원자료에 직접 들어 있는 기능이 아니라 작성자의 해석이다.

## 1. 검사 정의

[[05_비교 용어 사전#^term-scan-definition|검사 정의]]는 도구가 `어떤 요청을 보내고 어떤 응답이면 결과로 인정할지` 기록하는 방법이다.

| 도구         | 검사 정의          | 실제 의미                                                      |
| ---------- | -------------- | ---------------------------------------------------------- |
| Nuclei     | YAML Template  | 요청, Protocol, Matcher, Extractor, Metadata 등을 Template에 기록 |
| Jaeles     | YAML Signature | HTTP 요청과 응답 판정 조건을 Signature에 기록                           |
| Nikto      | 검사 DB와 Plugin  | 알려진 경로·제품·설정 검사와 실행 로직을 DB 및 Plugin으로 관리                   |
| WAVE       | 취약점 Rule DB    | 알려진 취약 Page의 특성과 실제 공격 Rule을 저장                            |
| Bitscanner | 공격 Pattern     | Parameter에 넣을 Payload와 응답에서 찾을 Pattern을 저장                 |

같은 `외부 검사 규칙`이라는 공통점은 있지만 표현 능력은 같지 않다. Nuclei Template은 여러 Protocol과 다단계 실행을 표현할 수 있고, Bitscanner의 공격 Pattern은 Crawler가 찾은 웹 입력 지점에 적용하는 공격 자료에 가깝다.

## 2. 주요 대상

[[05_비교 용어 사전#^term-target|주요 대상]]은 도구가 검사하도록 설계된 자산의 종류다.

```text
Nuclei
└─ URL, Host, IP, CIDR, API 정의, File 등 폭넓은 입력

Jaeles
└─ HTTP URL과 Web Application

Nikto
└─ Web Server와 그 Server가 제공하는 HTTP 자원

WAVE
└─ Web Application 안의 개별 Page

Bitscanner
└─ Crawler가 탐색하는 Web Application
```

`Web Server`, `Web Application`, `Web Page`는 같은 말이 아니다.

- Web Server: HTTP 요청을 받아 콘텐츠를 제공하는 서버 프로그램과 설정
- Web Application: 로그인, 게시판, 결제처럼 동작을 제공하는 웹 소프트웨어 전체
- Web Page: Web Application 안에서 접근하는 하나의 URL 또는 화면

## 3. 실행 흐름

[[05_비교 용어 사전#^term-execution-flow|실행 흐름]]은 입력이 결과가 되기까지의 단계다.

### Nuclei

```text
Target 입력
  ↓
Catalog·Loader가 Template 선택
  ↓
Parser가 Template 해석
  ↓
Engine이 Protocol Request 실행
  ↓
Matcher 판정 + Extractor 값 추출
  ↓
Output Writer가 결과 출력
```

사진의 `Target → Template → Request → Matcher → Output`은 핵심만 줄인 표현이다. 실제 코드 흐름에는 Template 선택·해석, 속도 제한, 입력 공급, 결과 작성 같은 구성요소가 더 있다.

### Jaeles

```text
Target 입력
  ↓
Selector로 Signature 선택
  ↓
HTTP Request 실행
  ↓
응답 조건 판정
  ↓
CLI·Report 출력
```

### Nikto

```text
Web Server 입력
  ↓
검사 DB·Plugin 선택
  ↓
HTTP Request 실행
  ↓
Body·Header·Cookie·Status Code 판정
  ↓
결과 출력
```

### WAVE

```text
Site 구조 수집
  ↓
Page 특성 유사도 비교
  ↓
적용 가능한 취약점 Rule 선택
  ↓
HTTP Request 실행
  ↓
응답 분석
```

### Bitscanner

```text
Crawler가 Page 탐색
  ↓
입력 Parameter 발견
  ↓
공격 Pattern 삽입
  ↓
공격 요청과 응답 비교
  ↓
보고서 생성
```

## 4. 판정 방법

[[05_비교 용어 사전#^term-detection-logic|판정 방법]]은 `탐지 결과를 성립시키는 증거`다.

- Nuclei: Matcher가 상태 코드, 단어, 정규식, DSL 등의 조건을 검사한다.
- Jaeles: Signature에 적힌 HTTP 상태 코드와 문자열 등의 조건을 검사한다.
- Nikto: Body, Header, Cookie, Status Code 조건을 조합한다.
- WAVE: Page 특성 유사도로 Rule 적용 대상을 먼저 좁힌 뒤, Rule 응답을 분석한다.
- Bitscanner: 공격 Payload를 보낸 응답에서 취약점별 Pattern을 비교한다.

> [!warning] 사진에서 수정할 부분
> Nuclei의 `Matcher와 Extractor`를 모두 판정 방법으로 적으면 역할이 섞인다. Matcher는 결과가 성립하는지 판정하고, Extractor는 응답에서 값만 꺼낸다. 따라서 `Matcher로 판정하고 Extractor로 필요한 값을 추출`이라고 써야 정확하다.

## 5. 확장 방법

[[05_비교 용어 사전#^term-extensibility|확장 방법]]은 프로그램 핵심 코드를 전부 수정하지 않고 새 검사를 추가하는 방식이다.

| 도구 | 새 검사 추가 방법 | 의미 |
|---|---|---|
| Nuclei | Template 추가 | 새로운 취약점·설정·정보 탐지 정의 추가 |
| Jaeles | Signature 추가 | 새로운 HTTP 검사 정의 추가 |
| Nikto | 검사 DB·Plugin 추가 | 새 검사 데이터 또는 실행 로직 추가 |
| WAVE | Page 특성·Rule 추가 | 대상 Page 식별 정보와 공격 Rule 추가 |
| Bitscanner | 공격 Pattern 추가 | 새 Payload와 응답 Pattern 추가 |

Nuclei와 Jaeles가 특히 비슷한 이유가 이 부분이다. 실행 Engine을 바꾸지 않고 외부 규칙 파일을 추가할 수 있다.

## 6. 결과 출력

[[05_비교 용어 사전#^term-output|결과 출력]]은 사람이 읽거나 다른 시스템이 처리할 수 있도록 탐지 결과를 표현하는 방법이다.

- Nuclei: 일반 CLI 출력, JSONL, JSON Export, SARIF, Markdown 등
- Jaeles: CLI, 파일 출력, HTML Report
- Nikto: CSV, JSON, HTML, SQL, TXT, XML 등
- WAVE: 논문에서 구현한 연구 시스템의 취약점 결과
- Bitscanner: Crawler·Scanner 결과를 정리한 보고서

Nuclei·Jaeles·Nikto는 구체적인 파일 형식을 비교할 수 있다. WAVE·Bitscanner는 논문 속 시스템이므로 현재 배포판의 출력 옵션처럼 비교해서는 안 된다.

## 7. 가장 비슷한 점

이 행은 기능 목록이 아니라 `Nuclei와 연결되는 핵심 개념`을 한 문장으로 요약한 것이다.

- Jaeles: 실행 Engine과 외부 Signature 분리
- Nikto: 외부 검사 DB로 HTTP 응답 판정
- WAVE: 외부 Rule을 선택하여 요청·응답 판정
- Bitscanner: 자동 요청, 응답 비교, 보고서 생성

## 8. 중요한 차이

이 행은 각 도구가 Nuclei와 다른 설계 중심을 요약한다.

- Nuclei: 여러 Protocol과 대량 Target 실행
- Jaeles: HTTP Signature와 사용자 정의 Web Scanner 중심
- Nikto: Web Server의 파일·설정·구성요소 검사 중심
- WAVE: Page 유사도를 이용한 Rule 실행 전 사전 검증
- Bitscanner: Crawler가 입력 Parameter를 찾는 과정 중심

## 비교항목 자체에 대한 평가

사진의 8개 행은 `구조와 기능을 설명`하는 데는 좋지만 `어느 도구가 더 우수한지` 증명하지는 못한다.

성능 우위를 말하려면 다음 항목이 추가로 필요하다.

- 같은 Target과 같은 취약점 Test Case
- 탐지 성공 수, 오탐 수, 미탐 수
- 요청 수와 실행 시간
- CPU·Memory 사용량
- Rule·Template 수와 품질
- 최근 유지보수 여부
- 동일한 조건에서 반복한 실험
