# 표의 정확성 검토와 수정안

#전지성 #도구비교/검토 #표수정

## 전체 평가

사진의 표는 처음 보는 사람이 다섯 대상을 빠르게 구분하는 용도로는 유용하다. 다만 다음 세 문제가 있다.

1. 실제 오픈소스와 논문 연구 시스템을 같은 종류처럼 배치했다.
2. Nuclei의 Matcher와 Extractor 역할을 모두 `판정 방법`으로 묶었다.
3. 현재 유지보수 여부와 동일 조건의 성능 자료가 없어 우열을 판단할 수 없다.

## 그대로 사용해도 되는 내용

- Nuclei가 Template 기반이며 여러 Protocol을 지원한다.
- Jaeles가 Signature와 Engine을 분리한 Web 중심 프레임워크다.
- Nikto가 Web Server 중심이며 검사 DB와 Plugin을 사용한다.
- WAVE가 Page 유사도를 확인한 뒤 관련 Rule을 적용한다.
- Bitscanner가 Crawler로 Parameter를 찾고 공격 Pattern을 적용한다.

## 수정해야 하는 내용

### 1. Nuclei 판정 방법

기존:

```text
Matcher와 Extractor
```

수정:

```text
Matcher로 탐지 여부 판정
Extractor로 응답값 추출
```

Extractor가 값을 추출했다는 사실만으로 취약점이 성립하는 것은 아니다.

### 2. Nuclei 실행 흐름

기존:

```text
Target → Template → Request → Matcher → Output
```

수정:

```text
Target
→ Template 선택·해석
→ Protocol Request
→ Matcher 판정·Extractor 추출
→ Output
```

사진은 개념도이므로 기존 표현도 틀리지는 않지만, 코드 구조를 설명할 때는 Catalog, Parser, Engine, Output Writer가 중간에 있다는 사실을 보충해야 한다.

### 3. Jaeles 상태

표의 `오픈소스` 표시는 맞지만 다음 문장을 추가해야 한다.

```text
공식 저장소가 보관 처리되어 더 이상 유지보수되지 않음
```

오픈소스라는 사실과 현재 개발이 계속된다는 사실은 서로 다르다.

### 4. Nikto 출력 형식

사진의 `TXT·JSON·HTML·XML 등`은 일부 형식만 보여 준 요약이다. 현재 공식 도움말에는 CSV와 SQL 계열 출력도 포함된다.

### 5. WAVE와 Bitscanner 구분

두 대상은 다음과 같이 표시하는 편이 정확하다.

```text
국내 논문에서 제안·구현한 연구 시스템
현재 유지되는 공개 오픈소스 제품과 동일하게 비교할 수 없음
```

### 6. 가장 비슷한 점과 중요한 차이

두 행은 측정값이 아니라 작성자의 해석이다. 표 아래에 다음 문장을 붙이는 것이 좋다.

> `가장 비슷한 점`과 `중요한 차이`는 기능 문서의 원문이 아니라 Nuclei를 기준으로 재구성한 분석 결과다.

## 추가하면 좋은 비교 항목

| 추가 항목 | 필요한 이유 |
|---|---|
| 자료 종류 | 오픈소스 제품인지 논문 연구 시스템인지 구분 |
| 유지보수 상태 | 현재 실제 도입 가능성 판단 |
| 구현 언어 | 코드 확장과 의존 환경 비교 |
| Rule 표현력 | 단순 Pattern인지 다단계 Scenario인지 구분 |
| Target 발견 방식 | 사용자가 입력하는지 Crawler가 찾는지 구분 |
| 오탐 검증 방식 | 한 번의 Match인지 추가 검증이 있는지 확인 |
| 동시 실행·Rate Limit | 대량 검사 능력과 Target 부하 판단 |
| 재현 가능한 실험 | 성능과 정확도 주장의 신뢰성 판단 |

## 수정된 핵심 비교표

| 비교 항목 | Nuclei | Jaeles | Nikto | WAVE | Bitscanner |
|---|---|---|---|---|---|
| 자료 종류 | 현재 개발 중 오픈소스 | 보관 처리된 오픈소스 | 현재 사용 가능한 오픈소스 | 2008년 국내 논문 연구 시스템 | 2020년 국내 논문 연구 시스템 |
| 검사 정의 | YAML Template | YAML Signature | 검사 DB·Plugin | Page 특성·취약점 Rule DB | 공격 Pattern |
| 주요 대상 | 여러 Protocol의 자산 | HTTP·Web Application | Web Server | Web Application Page | Web Application |
| Target 발견 | 사용자가 입력·외부 입력 연동 | 사용자가 URL·목록 입력 | 사용자가 Host 입력 | Site 구조 분석 | Crawler가 Page·Parameter 탐색 |
| 판정 | Matcher 판정, Extractor 추출 | HTTP 응답 조건 | Body·Header·Cookie·Code | Page 유사도 후 Rule 응답 | 공격 응답 Pattern |
| 확장 | Template 추가 | Signature 추가 | DB·Plugin 추가 | 특성·Rule 추가 | Pattern 추가 |
| 핵심 차이 | 다중 Protocol·대량 실행 | Web Signature 중심 | Web Server 중심 | Page 적합성 사전 검증 | Crawler 중심 |

## 우열을 판단할 수 없는 이유

이 표만으로 `Nuclei가 모든 면에서 가장 좋다`고 결론 내릴 수는 없다.

- 같은 취약점을 같은 Target에서 검사한 실험이 아니다.
- Rule과 Template의 수·품질이 통제되지 않았다.
- WAVE는 2008년, Bitscanner는 2020년 연구로 시점이 다르다.
- Jaeles는 현재 보관 상태지만 Nuclei와 Nikto는 이후에도 변했다.
- 정확도, 오탐률, 미탐률, 실행 시간과 자원 사용량을 동일 조건에서 측정하지 않았다.

다만 공개된 기능 범위와 현재 유지보수 상태를 기준으로 하면, Nuclei가 가장 넓은 Protocol과 자동화 기능을 제공한다는 설명은 가능하다.
