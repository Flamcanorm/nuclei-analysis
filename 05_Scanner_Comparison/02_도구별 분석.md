| 대상 | 종류 | 현재 비교할 수 있는 것 |
|---|---|---|
| Nuclei | 현재 개발 중인 오픈소스 | 코드, CLI, Template, 최신 기능, 출력 |
| Jaeles | 보관 처리된 오픈소스 | 마지막 공개 코드, Signature 구조, 과거 기능 |

| Bitscanner | 2020년 국내 논문 연구 시스템 | 논문에 적힌 Crawler·Scanner 구조와 실험 |

## 1. Nuclei

Nuclei는 외부 Template이 검사 내용을 정의하고, Go로 작성된 Engine이 이를 읽어 여러 Target에 실행하는 범용 보안 스캐너다.

```text
Nuclei 실행 파일
├─ CLI 입력
├─ Template 선택·해석
├─ Target 공급
├─ Protocol 요청
├─ 동시 실행·Rate Limit
├─ Matcher·Extractor
└─ 결과 출력

Nuclei Template
├─ ID와 Info
├─ Protocol Request
├─ Matcher
├─ Extractor
└─ Flow·Variable 등 실행 제어
```

### 장점

- HTTP 외에도 DNS, SSL, TCP, WHOIS, File, Headless, WebSocket, JavaScript, Code 등 지원 범위가 넓다.
- Template과 Engine을 분리하여 새 검사를 추가하기 쉽다.
- Matcher, Extractor, DSL과 다중 요청을 이용해 검증 절차를 자세히 표현할 수 있다.
- 많은 Target과 Template을 병렬로 처리하고 요청을 Cluster할 수 있다.
- 사람이 읽는 출력과 자동화 시스템용 형식을 모두 지원한다.

### 주의점

- Template의 판정 조건이 부정확하면 오탐이나 미탐이 발생할 수 있다.
- 탐지 결과가 실제 취약점인지 다시 검증할 책임은 남아 있다.
- 많은 Template을 무조건 실행하면 Target과 검사 장비에 부하가 생길 수 있다.

## 2. Jaeles

Jaeles는 Go로 작성된 Web Application Scanner 제작 프레임워크다. Signature가 HTTP 요청과 판정 조건을 정의하고 Engine이 이를 실행한다.

```text
Target
  ↓
Signature Selector
  ↓
HTTP Request
  ↓
조건 판정
  ↓
CLI·HTML Report
```

### Nuclei와 가까운 이유

- Go로 작성되었다.
- 실행 Engine과 YAML 기반 외부 검사 규칙을 분리한다.
- 단일 URL, URL 목록과 표준 입력을 받을 수 있다.
- Signature 선택·제외와 동시 실행 수를 지정할 수 있다.
- 새 Signature를 추가하여 검사를 확장한다.

### 중요한 현재 상태

Jaeles 공식 저장소는 보관 처리되어 더 이상 유지보수되지 않는다고 명시한다. 따라서 구조 비교 자료로는 유용하지만, 현재 운영 도구를 선택하는 비교에서는 유지보수 상태를 반드시 함께 적어야 한다.

## 3. Nikto

Nikto는 Web Server에서 위험한 파일, 기본 파일, 오래된 구성요소와 잘못된 설정 등을 찾는 오픈소스 스캐너다.

```text
Web Server
  ↓
검사 DB·Plugin
  ↓
HTTP Request
  ↓
Body·Header·Cookie·Status Code Matcher
  ↓
결과 파일
```

### Nuclei와 가까운 이유

- 검사 Engine 외부의 DB와 Plugin에 검사 자료를 둔다.
- HTTP 요청을 보내고 응답의 여러 부분을 조건으로 판정한다.
- 여러 형식으로 결과를 저장할 수 있다.

### 중요한 차이

Nikto는 Web Server 검사에 집중한다. Nuclei처럼 DNS, WHOIS, File, Code 등 여러 Protocol을 하나의 Template 체계로 다루는 범용 구조는 아니다.

## 4. WAVE

WAVE는 2008년 `웹 애플리케이션 취약점 분석 시스템` 논문에서 제안된 Web Application Vulnerability Estimator다.

핵심은 Rule을 바로 실행하지 않고 먼저 Page 특성을 비교하는 것이다.

```text
대상 Page
  ↓
JavaScript 함수·입력 변수·링크·이미지 특성 추출
  ↓
알려진 취약 Page와 유사도 비교
  ↓
관련 Rule만 선택
  ↓
요청과 응답 분석
```

### Nuclei와 연결되는 부분

- Engine 밖에 검사 Rule을 저장한다.
- HTTP 요청과 응답 조건으로 취약점을 판단한다.
- 관련성이 낮은 Rule을 줄이려는 선택 단계가 있다.

### Nuclei와 다른 핵심

WAVE는 `이 Page가 그 Rule의 대상과 정말 비슷한가?`를 Page 내부 특성으로 먼저 확인한다. Nuclei의 Automatic Scan이 기술 식별 결과와 Template Tag를 연결하는 것과 목적은 비슷하지만, WAVE는 개별 Page 특성의 유사도를 사용한다는 차이가 있다.

## 5. Bitscanner

Bitscanner는 2020년 논문에서 제안된 Crawler 기반 Web Application 취약점 검사 시스템이다.

```text
Crawler
  ↓
Page·Form·Parameter 탐색
  ↓
취약점별 공격 Pattern 선택
  ↓
Payload를 Parameter에 삽입
  ↓
응답 Pattern 비교
  ↓
보고서 생성
```

### Nuclei와 연결되는 부분

- 공격 요청을 자동으로 전송한다.
- 응답 Pattern으로 취약 여부를 판단한다.
- 여러 취약점 검사를 반복하고 결과를 보고서로 만든다.

### Nuclei와 다른 핵심

Bitscanner는 Crawler가 먼저 입력 지점과 Parameter를 발견하는 과정이 중심이다. Nuclei는 기본적으로 선택된 Template이 요청 경로와 검사 조건을 알고 있다고 가정하는 Template 중심 실행에 가깝다.

## 역할별로 다시 분류

```text
외부 규칙 파일과 Engine 분리 비교
└─ Nuclei ↔ Jaeles

HTTP 검사 DB와 응답 판정 비교
└─ Nuclei ↔ Nikto

Rule 실행 전 대상 적합성 검증 아이디어
└─ Nuclei ↔ WAVE

Crawler 기반 자동 입력 발견 아이디어
└─ Nuclei ↔ Bitscanner
```
