# 논문 전용 용어 사전

#전지성 #논문용어 #용어사전

## 사용 방법

각 용어에는 두 가지 표식을 사용한다.

```text
#논문용어/SAST
└─ Obsidian에서 같은 태그가 붙은 내용을 검색할 때 사용

블록 ID: `term-sast`
└─ 다른 문서의 링크를 눌렀을 때 이 정의로 바로 이동할 때 사용
```

다른 문서에서는 다음처럼 연결한다.

```text
[[05_논문 전용 용어 사전#^term-sast|SAST]]
```

## 연구와 논문 구성

### 선행연구

#논문용어/선행연구

현재 연구보다 먼저 발표된 관련 연구다. 연구자는 선행연구를 조사하여 이미 해결된 문제, 아직 해결되지 않은 문제와 자신의 연구가 다른 점을 찾는다.

```text
선행연구 조사
    ↓
기존 방법의 장점·한계 확인
    ↓
새로운 연구 문제 결정
```

^term-related-work

### 연구 목적

#논문용어/연구목적

연구를 통해 해결하려는 문제와 달성하려는 목표다. “무엇을 만들었는가”보다 “왜 이 연구가 필요한가”를 설명한다.

^term-research-purpose

### 연구 방법

#논문용어/연구방법

연구 목적을 검증하기 위해 사용한 데이터, 도구, 실험 절차와 분석 방법을 뜻한다.

^term-research-method

### 연구 모델

#논문용어/연구모델

연구자가 문제를 설명하거나 해결하기 위해 구성한 개념적 구조다. 실제 프로그램일 수도 있고, 여러 요소의 관계를 나타내는 이론적 모형일 수도 있다.

^term-research-model

### 아키텍처

#논문용어/아키텍처

시스템을 구성하는 요소와 요소 사이의 연결 관계를 나타내는 전체 설계도다.

```text
입력 → 분석 구성요소 → 판정 → 출력
```

아키텍처를 제안했다는 말이 반드시 프로그램을 완성했다는 뜻은 아니다.

^term-architecture

### 프로토타입

#논문용어/프로토타입

아이디어가 실제로 작동하는지 확인하기 위해 만든 초기 시험 버전이다. 핵심 기능은 있지만 완성 제품 수준의 안정성·편의성·성능을 모두 갖추지 않을 수 있다.

^term-prototype

### 탐색적 연구

#논문용어/탐색적연구

아직 충분히 연구되지 않은 문제에서 가능한 구조나 연구 방향을 먼저 제시하는 연구다. 확정적인 성능 증명보다 새로운 가능성 탐색에 목적이 있다.

^term-exploratory-study

### 실증 연구

#논문용어/실증연구

제안한 주장이나 모델을 실제 데이터, 실험, 관찰 또는 설문조사로 확인하는 연구다.

^term-empirical-study

### 정량적 실험

#논문용어/정량적실험

결과를 정확도, 시간, 비율, 처리량처럼 숫자로 측정하는 실험이다.

```text
정성적 표현: 기존보다 빠르다.
정량적 표현: 평균 처리 시간이 10초에서 8초로 감소했다.
```

^term-quantitative-experiment

### 정성적 분석

#논문용어/정성적분석

수치만으로 표현하기 어려운 특징, 의미, 장단점과 사용자의 평가를 설명하는 분석이다.

^term-qualitative-analysis

### 실험군과 비교군

#논문용어/실험군 #논문용어/비교군

- 실험군: 새로 제안한 방법을 적용한 대상
- 비교군: 기존 방법이나 기준 방법을 적용한 대상

두 집단은 가능한 한 같은 데이터와 환경에서 비교해야 한다.

^term-experimental-control-group

### 베이스라인

#논문용어/베이스라인

새로운 방법의 성능을 비교하기 위한 기준 방법이다. AI 기반 탐지기를 평가한다면 기존 Nuclei 또는 OWASP ZAP 결과가 베이스라인이 될 수 있다.

^term-baseline

### 재현성

#논문용어/재현성

다른 연구자가 같은 데이터와 방법으로 실험했을 때 비슷한 결과를 얻을 수 있는 성질이다. 데이터, 설정, 도구 버전과 절차가 공개될수록 재현하기 쉽다.

^term-reproducibility

### 일반화

#논문용어/일반화

특정 학습 데이터나 시험 환경에서만 잘 작동하지 않고, 처음 보는 다른 웹사이트와 공격 데이터에서도 성능을 유지하는 능력이다.

^term-generalization

### 도메인 일반화

#논문용어/도메인일반화

학습한 환경과 특성이 다른 환경에서도 모델이 동작하는 능력이다.

```text
학습: PHP 기반 쇼핑몰
적용: Java 기반 공공기관 사이트
```

두 환경의 기술과 데이터 형태가 달라도 탐지 성능을 유지해야 도메인 일반화가 좋다고 말할 수 있다.

^term-domain-generalization

### 연구 한계

#논문용어/연구한계

데이터 범위, 실험 환경, 구현 수준과 평가 방법 때문에 연구 결과를 모든 상황에 그대로 적용하기 어려운 부분이다.

^term-research-limitations

### 향후 연구

#논문용어/향후연구

현재 연구에서 해결하지 못한 문제와 이후에 추가로 검증하거나 구현해야 할 내용을 뜻한다.

^term-future-work

## 애플리케이션 보안 분석

### 취약점

#논문용어/취약점

공격자가 시스템의 기밀성, 무결성 또는 가용성을 해칠 때 이용할 수 있는 약점이다.

^term-vulnerability

### SAST

#논문용어/SAST

`Static Application Security Testing`의 약자이며, 프로그램을 실행하지 않고 소스코드를 검사하는 정적 애플리케이션 보안 테스트다.

```text
소스코드 → 위험한 함수·데이터 흐름 분석 → 취약 가능성 출력
```

^term-sast

### DAST

#논문용어/DAST

`Dynamic Application Security Testing`의 약자이며, 실행 중인 애플리케이션에 실제 요청을 보내고 응답을 검사하는 동적 애플리케이션 보안 테스트다.

```text
실행 중인 웹사이트 → 공격 요청 → 응답 분석 → 취약점 판정
```

Nuclei의 일반적인 원격 HTTP 검사는 DAST와 가까운 성격을 가진다.

^term-dast

### HAST

#논문용어/HAST

`Hybrid Application Security Testing`의 약자다. SAST, DAST처럼 서로 다른 애플리케이션 보안 검사 방법을 결합한다.

^term-hast

### 블랙박스 테스트

#논문용어/블랙박스

대상의 소스코드와 내부 구조를 보지 않고 외부에서 입력을 보내 결과를 확인하는 방식이다.

^term-black-box

### 화이트박스 테스트

#논문용어/화이트박스

소스코드, 함수, 데이터 흐름과 내부 설계를 알고 검사하는 방식이다.

^term-white-box

### 그레이박스 테스트

#논문용어/그레이박스

테스트 계정, API 문서, CMS 매뉴얼 또는 일부 소스처럼 내부 정보를 일부 제공받아 검사하는 방식이다.

^term-grey-box

### 규칙 기반 탐지

#논문용어/규칙기반탐지

미리 정한 조건에 입력이나 응답이 맞는지 검사하는 방식이다.

```text
응답 상태 코드가 200인가?
응답 본문에 "SQL syntax error"가 있는가?
```

^term-rule-based-detection

### 시그니처 기반 탐지

#논문용어/시그니처기반탐지

이미 알려진 공격의 문자열, 바이트 패턴, 요청 형태 또는 응답 특징을 찾아 탐지하는 방식이다.

^term-signature-detection

### 스캐너

#논문용어/스캐너

대상에 존재할 수 있는 취약점, 설정 오류와 노출 정보를 자동으로 검사하는 프로그램이다.

^term-scanner

### Crawler

#논문용어/Crawler

웹페이지의 링크를 따라 이동하면서 페이지와 입력 지점을 자동으로 수집하는 구성요소다.

^term-crawler

### Endpoint

#논문용어/Endpoint

클라이언트가 요청을 보낼 수 있는 URL 또는 API 접근 지점이다.

```text
GET /users
POST /login
GET /api/orders/10
```

^term-endpoint

### 매개변수

#논문용어/매개변수

클라이언트가 서버에 전달하는 입력 항목이다.

```text
/user?id=10
       └─ id가 매개변수 이름
```

^term-parameter

### HTTP 요청과 응답

#논문용어/HTTP요청 #논문용어/HTTP응답

- 요청: 브라우저나 검사 도구가 서버에 보내는 메시지
- 응답: 서버가 요청을 처리한 뒤 돌려주는 메시지

상태 코드, Header와 Body 등이 탐지 자료로 사용된다.

^term-http-request-response

### Payload

#논문용어/Payload

요청에 넣어 보내는 실제 데이터 또는 취약점 시험용 입력값이다.

```text
정상 값: id=10
시험 값: id=1' OR '1'='1
```

^term-payload

### Exploit

#논문용어/Exploit

취약점을 실제로 이용하여 의도하지 않은 동작을 발생시키는 코드나 방법이다.

^term-exploit

### PoC

#논문용어/PoC

`Proof of Concept`의 약자다. 발견한 취약점이 실제로 성립한다는 것을 안전하고 제한된 범위에서 증명하는 절차 또는 코드다.

^term-poc

### CMS

#논문용어/CMS

`Content Management System`의 약자다. 웹사이트의 글, 페이지, 사용자와 디자인을 관리할 수 있게 해주는 시스템이다. WordPress, Drupal, Joomla 등이 예다.

^term-cms

### CI/CD

#논문용어/CI-CD

코드 변경 후 빌드, 테스트, 보안 검사와 배포를 자동으로 수행하는 개발 파이프라인이다.

^term-ci-cd

### 전 주기 보안

#논문용어/전주기보안

설계, 개발, 테스트, 배포, 운영과 업데이트까지 소프트웨어의 전체 생명주기에 보안 검사를 적용하는 개념이다.

^term-full-lifecycle-security

## 취약점 분류와 표준

### CVE

#논문용어/CVE

공개적으로 알려진 개별 보안 취약점에 부여하는 식별 번호 체계다.

```text
CVE-2025-12345
```

^term-cve

### CWE

#논문용어/CWE

취약점이 생기는 일반적인 소프트웨어 약점 유형을 분류한 목록이다. CVE가 개별 사건이라면 CWE는 약점의 종류에 가깝다.

^term-cwe

### OWASP Top 10

#논문용어/OWASP-Top-10

웹 애플리케이션에서 중요하게 다뤄야 할 대표적인 보안 위험 10가지를 정리한 목록이다.

^term-owasp-top-10

### SANS Top 25

#논문용어/SANS-Top-25

심각하고 자주 발생하는 소프트웨어 약점 유형을 우선순위로 정리한 목록이다. 논문에 따라 CWE Top 25 또는 CWE/SANS Top 25라고 표현하기도 한다.

^term-sans-top-25

### CWSS

#논문용어/CWSS

`Common Weakness Scoring System`의 약자다. 소프트웨어 약점의 중요도와 위험도를 수치화하기 위한 평가 체계다.

^term-cwss

## AI와 데이터 분석

### 인공지능과 머신러닝

#논문용어/AI #논문용어/Machine-Learning

- 인공지능: 사람이 수행하는 판단·분류·생성 작업을 컴퓨터가 수행하도록 만드는 넓은 분야
- 머신러닝: 규칙을 사람이 전부 작성하지 않고 데이터에서 패턴을 학습하는 AI 방법

^term-ai-ml

### 모델

#논문용어/AI모델

학습 데이터를 이용해 입력과 출력 사이의 패턴을 학습한 결과물이다. 새로운 HTTP 요청이 들어오면 정상 또는 공격으로 예측할 수 있다.

^term-ai-model

### 데이터셋

#논문용어/데이터셋

연구와 AI 학습·평가에 사용하는 데이터의 모음이다.

```text
정상 HTTP 요청
공격 HTTP 요청
각 요청의 정답 레이블
```

^term-dataset

### 레이블

#논문용어/레이블

데이터에 붙이는 정답 표시다.

```text
요청 A → 정상
요청 B → SQL Injection
```

^term-label

### 특징

#논문용어/특징 #논문용어/Feature

AI가 판단할 때 사용하는 데이터의 속성이다. URL 길이, 특수문자 수, 요청 방법, 상태 코드와 문자열 순서 등이 특징이 될 수 있다.

^term-feature

### 전처리

#논문용어/전처리

원본 데이터를 AI가 학습할 수 있는 형태로 정리하는 과정이다. 오류 제거, 중복 제거, 값 변환, 레이블 정리 등이 포함된다.

^term-preprocessing

### 학습 데이터와 테스트 데이터

#논문용어/학습데이터 #논문용어/테스트데이터

- 학습 데이터: 모델이 패턴을 배우는 데 사용하는 데이터
- 테스트 데이터: 학습이 끝난 모델의 성능을 확인하는 별도 데이터

테스트 데이터를 학습에 사용하면 실제 성능보다 결과가 좋게 보일 수 있다.

^term-train-test-data

### 데이터 불균형

#논문용어/데이터불균형

정상과 공격처럼 분류할 집단의 데이터 개수가 크게 다른 상태다.

```text
정상 99,000개
공격 1,000개
```

이 경우 모델이 모든 입력을 정상으로 판단해도 정확도가 높게 보일 수 있다.

^term-class-imbalance

### SMOTE

#논문용어/SMOTE

적은 집단의 기존 데이터 사이에서 인공 표본을 만들어 데이터 불균형을 완화하는 방법이다. 단순 복사와 달리 주변 표본의 특징을 조합한다.

^term-smote

### Random Forest

#논문용어/Random-Forest

여러 개의 의사결정나무가 각각 예측한 결과를 종합하여 최종 분류를 결정하는 머신러닝 알고리즘이다.

```text
여러 결정나무의 판단
    ↓
다수결 또는 평균
    ↓
최종 정상·공격 분류
```

^term-random-forest

### LSTM

#논문용어/LSTM

`Long Short-Term Memory`의 약자이며, 문자·단어·요청처럼 순서가 있는 데이터에서 앞뒤 관계를 학습하는 신경망 모델이다.

LSTM의 Memory는 파일을 장기간 저장한다는 뜻이 아니라, 앞에서 본 정보 중 필요한 특징을 뒤의 판단에 활용한다는 의미다.

^term-lstm

### Sequence

#논문용어/Sequence

순서가 있는 데이터의 나열이다. URL의 문자 순서, Payload 안의 토큰 순서 또는 여러 HTTP 요청의 시간 순서가 될 수 있다.

^term-sequence

### 재학습

#논문용어/재학습

새로운 정상·공격 데이터를 추가해 기존 AI 모델을 다시 학습하는 과정이다.

^term-retraining

### Kafka

#논문용어/Kafka

많은 이벤트나 메시지를 실시간에 가깝게 전달하고 처리하기 위한 분산 스트리밍 플랫폼이다. 논문에서는 보안 이벤트를 AI 처리 단계로 전달하는 데 사용한다.

^term-kafka

### Zero-day

#논문용어/Zero-day

제작자나 방어자가 충분한 패치와 탐지 규칙을 준비하기 전에 악용될 수 있는 새 취약점 또는 공격을 뜻한다.

^term-zero-day

## 성능 평가

### TP·TN·FP·FN

#논문용어/TP #논문용어/TN #논문용어/FP #논문용어/FN

| 구분 | 실제 상태 | 도구 판단 | 의미 |
|---|---|---|---|
| TP | 공격·취약 | 공격·취약 | 올바르게 탐지 |
| TN | 정상 | 정상 | 올바르게 정상 판단 |
| FP | 정상 | 공격·취약 | 오탐 |
| FN | 공격·취약 | 정상 | 미탐 |

^term-confusion-matrix

### 정확도

#논문용어/정확도

전체 데이터 중 올바르게 판단한 비율이다.

```text
(TP + TN) / 전체 데이터
```

정상 데이터가 지나치게 많으면 정확도만으로 모델을 평가하기 어렵다.

^term-accuracy

### 정밀도

#논문용어/정밀도

공격 또는 취약점이라고 탐지한 결과 중 실제로 맞은 비율이다.

```text
TP / (TP + FP)
```

^term-precision

### 재현율

#논문용어/재현율

실제로 존재하는 공격 또는 취약점 중 도구가 찾아낸 비율이다.

```text
TP / (TP + FN)
```

^term-recall

### F1-score

#논문용어/F1-score

정밀도와 재현율을 하나의 값으로 종합한 평가 지표다. 두 지표 중 하나만 지나치게 높은 모델보다 균형 잡힌 모델을 평가할 때 사용한다.

^term-f1-score

### 오탐률

#논문용어/오탐률

실제로 정상인 데이터 중 공격 또는 취약점으로 잘못 판단한 비율이다.

^term-false-positive-rate

### 미탐률

#논문용어/미탐률

실제로 공격 또는 취약점인 데이터 중 정상으로 잘못 판단하여 놓친 비율이다.

^term-false-negative-rate

### 지연 시간

#논문용어/지연시간

입력을 받은 순간부터 분석 결과를 반환할 때까지 걸리는 시간이다.

^term-latency

### 처리량

#논문용어/처리량

일정 시간 동안 처리할 수 있는 요청이나 데이터의 개수다.

```text
초당 1,000개 요청 처리
```

^term-throughput

### 연산 비용

#논문용어/연산비용

분석에 필요한 CPU, GPU, 메모리, 처리 시간과 전력 등의 컴퓨터 자원이다.

^term-computational-cost

## 추가 오픈소스·API·AI 연구 용어

### Plugin

#논문용어/Plugin

기존 프로그램의 핵심 코드를 모두 수정하지 않고 새로운 기능을 끼워 넣는 확장 단위다.

```text
Tsunami Engine
├─ 서비스 탐색 Plugin
└─ 취약점 탐지 Plugin
```

Nuclei에서는 YAML Template이 많은 검사를 표현하지만, Tsunami에서는 Java 코드로 작성한 Plugin이 검사를 구현한다.

^term-plugin

### Module

#논문용어/Module

하나의 책임을 맡도록 나눈 프로그램 구성 부분이다. 함수 하나보다 큰 단위이며 파일, Package 또는 여러 Class의 묶음일 수 있다.

예를 들어 PentestGPT는 추론, 명령 생성, 결과 해석을 서로 다른 Module로 나눈다.

^term-module

### OpenAPI

#논문용어/OpenAPI

REST API의 주소, HTTP Method, Parameter, 요청 본문과 응답 구조를 기계가 읽을 수 있게 적은 명세 형식이다. 예전에는 Swagger Specification이라는 이름으로 알려졌다.

```text
OpenAPI 문서
└─ POST /users
   ├─ 필요한 Parameter
   ├─ Request Body
   └─ 예상 Response
```

RESTler와 Schemathesis는 OpenAPI 문서를 읽어 자동으로 API 요청을 만든다.

^term-openapi

### GraphQL

#논문용어/GraphQL

Client가 필요한 Field를 질의문으로 지정하는 API 방식이다. REST처럼 기능마다 URL을 나누기보다 하나의 Endpoint에서 Query와 Mutation을 처리하는 경우가 많다.

^term-graphql

### Schema

#논문용어/Schema

데이터가 어떤 Field와 자료형을 가져야 하는지 정의한 구조 규칙이다.

```text
User Schema
├─ id: integer
├─ name: string
└─ email: string
```

API Scanner는 Schema를 이용해 정상값, 경계값과 잘못된 값을 생성할 수 있다.

^term-schema

### Fuzzing

#논문용어/Fuzzing

프로그램에 정상값뿐 아니라 경계값, 잘못된 값과 변형된 Payload를 반복해서 넣어 예상하지 못한 오류를 찾는 시험 방법이다.

무작위 값만 보내는 것을 뜻하지 않는다. Schema, 실행 결과, 코드 Coverage 또는 학습 모델을 이용해 다음 입력을 선택할 수도 있다.

^term-fuzzing

### Stateful Testing

#논문용어/Stateful-Testing

각 요청을 독립적으로 시험하지 않고 이전 요청이 만든 상태와 응답값을 다음 요청에 사용하면서 검사하는 방식이다.

```text
로그인
  ↓ Token 획득
사용자 생성
  ↓ userId 획득
사용자 조회·수정·삭제
```

^term-stateful-testing

### Request Sequence

#논문용어/Request-Sequence

목적을 달성하기 위해 정해진 순서로 실행하는 여러 요청의 연속이다. RESTler는 API 의존성을 분석하여 실행 가능한 Request Sequence를 만든다.

^term-request-sequence

### 생산자·소비자 의존성

#논문용어/Producer-Consumer

앞 요청이 값을 만들고 뒤 요청이 그 값을 필요로 하는 관계다.

```text
POST /users → id=17 생산
GET /users/17 → id 소비
```

^term-producer-consumer

### Property-based Testing

#논문용어/Property-based-Testing

사람이 시험값을 하나씩 모두 적는 대신 “항상 지켜야 하는 성질”을 정의하고 도구가 다양한 입력값을 생성해 그 성질이 깨지는지 확인하는 방법이다.

예:

```text
잘못된 자료형을 보내도 서버가 죽지 않아야 한다.
응답은 OpenAPI Schema를 따라야 한다.
```

Schemathesis가 이 방식과 밀접하게 연결된다.

^term-property-based-testing

### State Machine

#논문용어/State-Machine

프로그램이 가질 수 있는 상태와 상태 사이의 이동 조건을 표현한 모델이다.

```text
로그아웃
  ↓ 로그인 성공
로그인
  ↓ 로그아웃
로그아웃
```

웹 Crawler와 API Scanner는 State Machine을 이용해 가능한 작업 순서를 탐색할 수 있다.

^term-state-machine

### Navigation Model

#논문용어/Navigation-Model

웹사이트에서 어떤 클릭·입력·폼 제출을 거쳐 다른 화면 상태로 이동했는지 기록한 모델이다. URL 목록보다 넓은 개념이며 JavaScript로 바뀐 화면과 로그인 상태도 표현할 수 있다.

^term-navigation-model

### State Transition

#논문용어/State-Transition

사용자의 행동이나 요청으로 현재 상태에서 다른 상태로 이동하는 것이다.

```text
상품 화면
  ↓ 장바구니 담기
장바구니에 상품이 있는 상태
```

^term-state-transition

### Code Coverage

#논문용어/Code-Coverage

시험하는 동안 전체 프로그램 코드 중 실제로 실행된 부분의 비율이나 범위다. Coverage가 높다고 취약점을 모두 찾은 것은 아니지만, 실행되지 않은 코드가 많으면 그 안의 취약점도 검사하지 못했을 가능성이 있다.

^term-code-coverage

### Scan Coverage

#논문용어/Scan-Coverage

보안 검사에서 계획한 Target, URL, Endpoint, Parameter, Template 또는 기능 중 실제로 검사한 범위다.

`0 matches`는 Scan Coverage가 100%라는 뜻이 아니다.

^term-scan-coverage

### Dynamic Taint Tracking

#논문용어/Dynamic-Taint-Tracking

시험용 표시값을 실제 프로그램에 입력한 뒤 그 값이 실행 중 어디로 이동하고 어느 응답이나 화면에 나타나는지 추적하는 방법이다.

Black Widow는 입력한 표시값이 이후 웹 상태에 나타나는지를 관찰하여 상태 사이 데이터 의존성을 찾는다.

^term-dynamic-taint-tracking

### Constraint Solving

#논문용어/Constraint-Solving

입력이 만족해야 하는 조건을 수식이나 논리식으로 만들고 그 조건을 통과하는 값을 계산하는 방법이다.

```text
나이 >= 18
문자열 길이 = 8
첫 글자 = A
```

NAVEX는 폼과 실행 경로의 조건을 통과하는 입력을 만드는 데 이 개념을 사용한다.

^term-constraint-solving

### Reinforcement Learning

#논문용어/Reinforcement-Learning

Agent가 행동을 선택하고 환경에서 받은 보상을 이용해 더 나은 행동 선택 방법을 학습하는 머신러닝 방식이다.

SQIRL에서는 Payload 변형이 행동이고 SQL Injection 탐지에 도움이 되는 피드백이 보상 역할을 한다.

^term-reinforcement-learning

### Agent

#논문용어/Agent

주어진 목표를 위해 현재 상황을 관찰하고 다음 행동을 선택하며 Tool을 실행하는 소프트웨어 구성요소다. LLM을 사용한다고 모두 Agent인 것은 아니며, 일반적으로 관찰·판단·행동의 반복 구조가 있어야 한다.

^term-agent

### Tool

#논문용어/AI-Tool

AI Agent가 실제 행동을 수행하기 위해 호출하는 기능이다. 예를 들어 명령 실행, Nuclei Scan, 파일 읽기와 웹 요청 등이 Tool이 될 수 있다.

^term-ai-tool

### Guardrail

#논문용어/Guardrail

AI가 위험하거나 허용되지 않은 행동을 하지 않도록 입력, 출력과 실행 직전 행동을 검사하고 제한하는 안전장치다.

```text
AI가 명령 생성
    ↓
허용된 Target인가?
위험한 Option인가?
비밀값을 외부로 보내는가?
    ↓
허용 또는 차단
```

^term-guardrail

### Prompt Injection

#논문용어/Prompt-Injection

AI가 읽는 웹페이지, 문서 또는 사용자 입력에 숨겨진 지시를 넣어 원래 규칙을 무시하게 만드는 공격이다. 보안 Agent가 외부 웹페이지를 읽고 명령을 실행할 수 있을 때 특히 위험하다.

^term-prompt-injection

### Confidence Score

#논문용어/Confidence-Score

모델이나 분석기가 자신의 판단을 얼마나 확실하다고 보는지 나타내는 참고 점수다. 점수가 높아도 실제 취약점이라는 보장은 없으므로 정답 레이블과 실제 검증을 이용해 점수가 믿을 만한지 평가해야 한다.

^term-confidence-score

### Callback Server

#논문용어/Callback-Server

검사 대상이 외부로 보낸 HTTP·DNS 등의 요청을 받아 기록하는 서버다. 응답에 취약점 흔적이 직접 나타나지 않는 Blind SSRF나 Blind RCE를 확인하는 데 사용한다.

^term-callback-server

### OAST

#논문용어/OAST

Out-of-Band Application Security Testing의 약자다. Scanner가 직접 받은 응답 밖에서 발생한 DNS·HTTP Callback을 관찰하여 취약점을 확인한다. Nuclei의 Interactsh와 Tsunami Callback Server가 이 목적에 사용될 수 있다.

^term-oast

### Fixture

#논문용어/Fixture

Test를 같은 조건에서 반복할 수 있도록 미리 준비한 입력 데이터와 실행 환경이다. Template 오탐 내성 시험에서는 저장된 정상·취약·404·WAF 응답이 Fixture가 된다.

^term-fixture

### Test Oracle

#논문용어/Test-Oracle

Test 결과가 맞는지 틀린지 판단하는 기준이다. 취약 응답은 반드시 탐지하고 정상 응답은 탐지하지 않아야 한다는 정답표가 Test Oracle 역할을 할 수 있다.

^term-test-oracle

### Redaction

#논문용어/Redaction

보고서나 AI 입력에서 비밀번호, Token, Cookie, API Key와 개인정보를 제거하거나 알아볼 수 없게 바꾸는 처리다.

^term-redaction

### Manifest

#논문용어/Manifest

실행 결과를 재현하는 데 필요한 Version, 설정, 파일 Hash와 실행 환경 정보를 구조적으로 기록한 문서다.

^term-manifest

### Hash

#논문용어/Hash

파일이나 데이터에서 일정한 길이의 식별값을 계산하는 함수 또는 결과다. 파일 내용이 조금만 달라져도 보통 다른 값이 나오므로 같은 Template Version과 내용을 사용했는지 확인할 수 있다.

^term-hash

### Code Generation AI

#논문용어/Code-Generation-AI

사람이 자연어로 원하는 동작을 설명하면 프로그래밍 코드를 생성하거나 수정하는 AI다. 생성된 코드가 정확하거나 안전하다는 보장은 없으므로 실행 전에 사람이 검토하고 Test해야 한다.

^term-code-generation-ai

### RPA

#논문용어/RPA

Robotic Process Automation의 약자다. 사람이 화면에서 반복하는 입력, 클릭, 파일 저장과 업무 절차를 Software Robot이 대신 수행하도록 자동화하는 기술이다.

웹 보안에서는 로그인, Menu 이동, Form 입력과 Capture 같은 사용자 행동을 재현하는 데 사용할 수 있다.

^term-rpa

### Selenium WebDriver

#논문용어/Selenium

Chrome이나 Firefox 같은 실제 Browser를 Code로 조종하는 자동화 도구다. URL 접속, Element 찾기, 값 입력, Button 클릭과 화면 Capture를 수행할 수 있다.

Selenium 자체가 취약점을 판정하는 Scanner는 아니다. 어떤 Payload를 넣고 무엇을 취약한 결과로 볼지는 작성된 Test Code가 결정한다.

^term-selenium

### Cursor AI

#논문용어/Cursor-AI

^term-cursor-ai

Visual Studio Code에 설치하는 Open Source AI Coding Extension이다. 여러 AI Model을 연결해 Code 생성, 수정과 설명을 요청할 수 있다.

^term-continue

### Prompt Engineering

#논문용어/Prompt-Engineering

AI가 원하는 결과를 만들도록 목표, 입력, 제약조건, 예시와 출력 형식을 Prompt에 구체적으로 설계하고 반복해서 개선하는 작업이다.

보안 Test에서는 Target, Scope, 로그인 절차, Field, Payload, 성공 조건과 금지할 행동을 명확하게 작성해야 한다.

^term-prompt-engineering

### Headless Browser

#논문용어/Headless-Browser

사람에게 Browser 창을 보여주지 않고 내부적으로 Page를 불러오고 JavaScript를 실행하는 Browser 실행 방식이다. 자동 Test와 대량 수집에 유용하지만 실제 Browser Process를 사용하므로 단순 HTTP 요청보다 자원 비용이 클 수 있다.

^term-headless-browser

### 증적

#논문용어/증적

보안 점검을 실제로 수행했고 어떤 결과가 나왔는지 보여주는 자료다. Request·Response, Log, 화면 Capture, 실행 시각, 사용한 Payload와 재현 절차 등이 증적이 될 수 있다.

^term-evidence

### Edge Case

#논문용어/Edge-Case

일반적인 입력과 달리 값의 경계나 드문 조건에서 발생하는 사례다. 빈 문자열, 최대 길이, 매우 큰 숫자, 특수문자와 동시에 발생하는 요청 등이 예다.

^term-edge-case

### Negative Control

#논문용어/Negative-Control

취약점을 유발하지 않아야 하는 정상 입력이나 정상 응답을 함께 시험하는 비교 기준이다.

```text
공격 Payload로 Login 성공
        +
정상적으로 실패해야 할 Control 입력
        ↓
두 결과를 비교해 공격 때문에 성공했는지 확인
```

Negative Control 없이 공격 요청만 확인하면 정상 기능이나 공통 오류 Page를 취약점으로 잘못 판단할 수 있다.

^term-negative-control

### WAVE

#논문용어/WAVE

`Web Application Vulnerability Estimator`의 약자다. 2008년 `웹 애플리케이션 취약점 분석 시스템` 논문에서 제안한 블랙박스 웹 취약점 분석 도구다.

취약점 룰을 바로 실행하지 않고, 먼저 대상 페이지의 JavaScript 함수·입력 변수·링크·이미지 경로를 취약점이 알려진 페이지와 비교한다. 같은 프로그램의 페이지라고 판단되면 관련 룰을 실행한다.

^term-wave

### 콘텐츠 유사도

#논문용어/콘텐츠유사도

두 웹 페이지가 가진 내부 요소와 구조가 얼마나 비슷한지를 비교한 정도다. WAVE 논문에서는 JavaScript 함수 이름, GET·POST 변수, 링크와 이미지 경로를 비교해 이름만 같은 다른 프로그램의 페이지를 구분하려 했다.

콘텐츠가 비슷하다는 사실만으로 취약점이 확정되는 것은 아니다. WAVE에서는 적용할 취약점 룰을 고르는 사전 확인에 사용한다.

^term-content-similarity

### 특성 정보

#논문용어/특성정보

대상을 서로 구분하거나 같은 종류인지 판단할 때 사용하는 관찰값이다.

WAVE에서는 다음 네 종류를 웹 페이지의 특성 정보로 사용한다.

- JavaScript 함수 이름
- GET·POST 변수의 타입과 이름
- 링크의 `href` 값
- 이미지 파일의 경로와 이름

^term-feature-information

### Nikto

#논문용어/Nikto

웹 서버의 알려진 위험 파일, 설정과 오래된 구성요소 등을 검사하는 오픈소스 웹 서버 스캐너다. WAVE 논문에서는 약 3,300개의 룰을 가진 기존 룰 기반 도구의 대표 사례로 비교한다.

논문의 3,300개는 2008년 당시 비교 조건이므로 현재 Nikto의 검사 수로 해석하면 안 된다.

^term-nikto
